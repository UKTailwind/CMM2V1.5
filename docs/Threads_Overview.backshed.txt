[CENTER][SIZE=5][COLOR=BLUE][B]Colour Maximite 2: threads for MMBasic, an overview[/B][/COLOR][/SIZE][/CENTER]
[I]25 November 2026. Work in progress: threads are not in any release yet, and the details may still change. Comments and ideas are welcome.[/I]

MMBasic has long had interrupts: something happens, a short routine runs, and the program carries on. Threads are a different tool. A thread is an ordinary SUB that runs [B]alongside[/B] the main program for as long as it likes, with its own loops, its own LOCAL variables and its own PAUSEs. The firmware shares the processor between the threads, a millisecond at a time.

[CODE]Option Explicit
Dim Integer beats

Sub Heart
  Do
    Inc beats
    Pause 500                 ' the rest of the program runs meanwhile
  Loop
End Sub

Thread Start 1, Heart
Do
  Text 0, 0, "Beats: " + Str$(beats) + "  "
  Pause 100
Loop Until Inkey$ <> ""
End                           ' the threads stop with the program[/CODE]


[SIZE=4][COLOR=BLUE][B]What works today[/B][/COLOR][/SIZE]
These run on a test board now:

• [B]THREAD START n, sub [, argument ...][/B] starts thread n (1 to 16) running a SUB. The main program is thread 0. The arguments are worked out when THREAD START runs and handed to the SUB by value. A global array is handed over as itself, so the thread can fill it.
• [B]THREAD EXIT[/B] ends the thread that runs it. A thread also ends when its SUB ends.
• [B]THREAD YIELD[/B] gives up the rest of the thread's time slice.
• [B]THREAD STOP n[/B] ends thread n where it stands. Its local variables and memory are freed.
• [B]THREAD PAUSE n[/B] and [B]THREAD RESUME n[/B] hold thread n and let it go on.
• [B]THREAD SLICE ms[/B] sets the time slice, 1 to 100 ms. It is 1 ms unless you say otherwise.
• [B]THREAD START n SIZE kb LOCALS m NEST d, sub[/B] gives one thread its own stack size, number of local variables and depth of loops and calls, so a small thread takes less memory. [B]THREAD SIZE kb [, locals [, nest]][/B] sets them for threads started without.
• [B]THREAD LOCK k[/B] and [B]THREAD UNLOCK k[/B]: sixteen locks. Only one thread at a time gets past THREAD LOCK k; the others wait there, without using any processor time, until it unlocks. THREAD LOCK k, ms gives up after that many milliseconds with an error.
• [B]THREAD HOLD[/B] and [B]THREAD RELEASE[/B]: no other thread runs between them. For a few statements that must not be split.
• [B]THREAD WAIT n[/B] waits until thread n has ended. [B]THREAD WAIT FLAG f[/B] waits until FLAG(f) is 1, which any thread or an interrupt routine can set. Either can have a time limit: THREAD WAIT n, ms.
• [B]THREAD LIST[/B] shows each thread, the line it is at, what it is doing or waiting for, and the most stack it has used. TRACE ON shows a thread's lines as [#n:line], MEMORY has a line for the threads, and OPTION PROFILING charges each line only the time its own thread spent on it.
• [B]MM.INFO(THREAD)[/B] is the number of the thread that runs it. [B]MM.INFO(THREAD n)[/B] is 0 if thread n is not running, 1 if it is running, 2 if it is in a PAUSE, 3 if it has been paused and 4 if it is waiting. [B]MM.INFO(THREAD LOCK k)[/B] is the thread that has lock k, or -1.

[SIZE=4][COLOR=BLUE][B]How they work[/B][/COLOR][/SIZE]
• [B]One thread runs at a time, and the switch comes only between statements,[/B] never in the middle of one. A statement is always whole: Inc count in two threads never loses a count.
• [B]The threads take turns,[/B] 1 ms each, in number order. A thread whose PAUSE has just ended goes next, so things that are timed stay on time among busy threads.
• [B]Each thread has its own[/B] LOCAL variables, FOR and DO loops, SUB and FUNCTION calls, GOSUBs, ON ERROR setting with MM.ERRNO and MM.ERRMSG$, and place in the DATA for READ. Two threads can run the same SUB at the same time, each with its own locals, recursion included.
• [B]Each thread has its own print position, colours, font and write page,[/B] starting with those of the thread that started it. A thread's COLOUR, FONT, TEXT, PRINT @ or PAGE WRITE does not disturb another thread's printing or drawing, or the line someone is typing at an INPUT. MODE gives every thread the new mode's.
• [B]Everything else is shared:[/B] global variables and arrays, STATIC variables, the screen itself, open files, sound, sprites, the turtle, the pins and the options.
• [B]A thread that waits costs nothing.[/B] PAUSE, INPUT and LINE INPUT, the waits for the next frame (PAGE COPY ...,B and FRAMEBUFFER WAIT), the network's and Bluetooth's commands, TEMPR(), THREAD LOCK and THREAD WAIT all let the other threads run meanwhile. A program can sit in INPUT for its user while its threads keep the screen moving, or wait on a web request while the game goes on.
• [B]An interrupt belongs to the thread that set it up.[/B] SETTICK, SETPIN, ON KEY and the rest work as before, and the routine runs in the thread that set it up, with its colours and print position, and to its end before any other thread runs. So a thread can set up a SETTICK and sit in THREAD WAIT FLAG until its routine sets the flag, while the main program sits in INPUT. Interrupts set up by the main program run in the main program, as they always did.
• [B]END in any thread, an error in any thread, or Ctrl-C stops the whole program.[/B] An error says where it was: "Error in thread 3, line 5". After an error or Ctrl-C the firmware also lists the threads, each with its line and what it was waiting for, which is how you find two threads that are each waiting for the other's lock.
• [B]OPTION COMPILE ON works with threads.[/B]
• [B]The cost:[/B] a program that starts no thread runs as fast as before. A switch takes about 5 microseconds, so 1 ms slices cost about half a percent. A thread takes about 26 KB of memory while it runs (as little as 14 KB if you make it small), given back when it ends.


[SIZE=4][COLOR=BLUE][B]What they cannot do[/B][/COLOR][/SIZE]
• [B]They do not make a program faster.[/B] There is one processor: four busy threads get a quarter of it each. Threads are for doing several things at once, not for doing one thing sooner.
• [B]They cannot cut into a statement.[/B] A statement that takes a long time (a SORT of a large array, a file copy, loading a picture) holds every thread until it is done.
• [B]No priorities.[/B] Every thread that is ready gets its turn.
• [B]Limits:[/B] with the usual sizes a thread can go about nine FUNCTIONs deep (SUB calls take nothing) and have 48 local variables, its FOR loops, DO loops and calls can each be 20 deep, and about ten threads can run at once; each takes about 26 KB. SIZE, LOCALS and NEST on THREAD START, or THREAD SIZE for all, change that: more stack for deep recursion, or a small stack, few locals and shallow nesting for a simple thread (about 14 KB with SIZE 12 LOCALS 8 NEST 4). Each thread has its own lists of loops and calls, as long as it asks for, so it pays only for what it uses.
• [B]Not allowed in a thread:[/B] RUN, CHAIN, FLASH RUN, LIBRARY LOAD, MsgBox() and GUI CLICK. Not allowed while any thread is running: ERASE, REDIM, CLEAR, SAVE CONTEXT and LOAD CONTEXT. THREAD START is for programs, not the command prompt, and CONTINUE does not work after Ctrl-C in a program with threads.


[SIZE=4][COLOR=BLUE][B]The one thing to watch: what the threads share[/B][/COLOR][/SIZE]
A switch can come between any two statements. Suppose two threads both do this to a global:

[CODE]v = total
total = v + 1[/CODE]

If the switch comes between the two statements, both threads read the same total, both add one, and one count is lost. The ways round it:

• [B]One statement.[/B] Inc total is a single statement, and nothing can come between.
• [B]One writer.[/B] A variable that one thread sets and the others only read is always safe.
• [B]One owner.[/B] One thread does all the writing to a file, and the others only set variables for it.
• [B]A lock.[/B] Every thread does it between THREAD LOCK 1 and THREAD UNLOCK 1, and they go one at a time:

[CODE]Thread Lock 1
v = total
total = v + 1
Thread Unlock 1[/CODE]

• [B]A hold.[/B] For two or three quick statements, THREAD HOLD before and THREAD RELEASE after: no other thread runs between them.

A test and the action after it are two statements too, so If free > 0 Then free = free - 1 can be cut in the middle when two threads run it.

[B]Some things belong to the whole program,[/B] and are best given to one thread, or used with a lock:

• [B]The screen itself.[/B] Each thread has its own print position, but two threads that simply PRINT without saying where write over each other, and CLS or a scroll moves everything under all of them. Give each thread its own part of the screen with PRINT @ or TEXT.
• [B]The keyboard.[/B] INKEY$, INPUT and KEYDOWN in two threads at once race for the keys: one thread should read the keyboard at a time.
• [B]The current drive and directory[/B] (DRIVE, CHDIR), and DIR$() going on from its last search.
• [B]The network and Bluetooth belong to one thread.[/B] The main program may use them to set up (WEB CONNECT, WEB NTP); the first other thread to use one then has it until it ends, and a WEB or BLUETOOTH command in any other thread is an error that names the owner. Its interrupt routines (WEB TCP INTERRUPT and the rest) run in it.
• [B]A bus.[/B] An I2C, SPI or 1-Wire conversation over several statements, and MM.I2C and MM.ONEWIRE after it, need one thread or a lock.
• [B]The OPTIONs[/B] (BASE, DEFAULT, EXPLICIT, ANGLE and the rest): set them before the threads start.
• [B]TIMER, RANDOMIZE, SYNC[/B], sound, sprites, the turtle and the GUI's controls.


[SIZE=4][COLOR=BLUE][B]Ideas for using them[/B][/COLOR][/SIZE]
• [B]Something with a rhythm of its own:[/B] a clock in the corner, a heartbeat LED, a status line, a tune played note by note with a PAUSE between the notes while the game goes on.
• [B]Straight-line code in place of a state machine:[/B] traffic lights, a sequence of valves and timers, an alien that moves, waits and fires. Each is written as steps with PAUSEs between them, not as a SETTICK routine and a variable that remembers where it had got to.
• [B]Many of the same thing:[/B] every ball, alien or robot is the same SUB in a thread of its own, with its own variables (the second example).
• [B]A long job with a live screen:[/B] a Mandelbrot or a big calculation runs in a thread while the main program shows progress and reads the keys, and can pause it, let it go on or stop it (the third example).
• [B]Logging:[/B] one thread samples a sensor every 100 ms into an array, another writes the array to the SD card every ten seconds, and the main program draws the graph.
• [B]Communications:[/B] a thread owns the network or a COM port: it makes the requests, or sets up the interrupt and puts the lines together, leaves each one in a global and sets a flag. The main program, or another thread, sits in THREAD WAIT FLAG until there is one.
• [B]A timeout:[/B] a thread that waits five seconds and then sets a flag, or stops another thread.
• [B]A program that listens while it works:[/B] the main program sits in INPUT for the next command while threads run the machine, the display or the game.

[B]Thread or interrupt?[/B] An interrupt is for something that happens and wants a quick, short answer. A thread is for something that goes on: it waits, loops and has a flow of its own. They work well together: a thread sets up its interrupt, the routine sets a flag, and the thread, waiting in THREAD WAIT FLAG, acts on it.


[SIZE=4][COLOR=BLUE][B]Two more examples[/B][/COLOR][/SIZE]
[B]Four balls, one SUB.[/B] Each thread runs Ball with its own position, speed and colour, given to it as arguments. Each CIRCLE carries its own colour, so the threads cannot mix them up.

[CODE]Option Explicit
Dim Integer i
Dim Integer col(4) = (0, RGB(red), RGB(green), RGB(yellow), RGB(cyan))

Sub Ball(x As Float, y As Float, dx As Float, dy As Float, c As Integer)
  Do
    Circle x, y, 5, 1, 1, 0, 0                    ' rub the old one out
    x = x + dx : y = y + dy
    If x < 10 Or x > MM.HRes - 10 Then dx = -dx
    If y < 10 Or y > MM.VRes - 10 Then dy = -dy
    Circle x, y, 5, 1, 1, c, c
    Pause 20
  Loop
End Sub

CLS
For i = 1 To 4
  Thread Start i, Ball, 100 * i, 60 * i, 2 + i, 1 + i, col(i)
Next
Do : Pause 50 : Loop Until Inkey$ <> ""
End[/CODE]

[B]A long job that listens.[/B] The picture is drawn by a thread. The main program reads the keys: P pauses the drawing, R lets it go on, Q stops it.

[CODE]Option Explicit
Dim Integer done, row
Dim k$

Sub Picture
  Local Integer x, y
  For y = 0 To MM.VRes - 1
    For x = 0 To MM.HRes - 1
      Pixel x, y, RGB(x And 255, y And 255, (x Xor y) And 255)
    Next
    row = y
  Next
  done = 1
End Sub

CLS
Thread Start 1, Picture
Do While done = 0
  k$ = UCase$(Inkey$)
  If k$ = "P" Then Thread Pause 1
  If k$ = "R" Then Thread Resume 1
  If k$ = "Q" Then Exit Do
  Pause 50
Loop
Thread Stop 1                 ' (does nothing if the thread has ended)
Print @(0, 0) "Ended at row"; row[/CODE]
