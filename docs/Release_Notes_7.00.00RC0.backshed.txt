[CENTER][SIZE=5][COLOR=BLUE][B]Colour Maximite 2: MMBasic 7.00.00RC0 (release candidate) release notes[/B][/COLOR][/SIZE][/CENTER]
[I]3 November 2026. Compared with 7.00.00b5, the previous beta. The full notes, compared with MMBasic 5.07.02, are posted with these.[/I]

This is the first release candidate of MMBasic 7.00 for the Colour Maximite 2. Unless problems are found in it, it will become 7.00.00. Please report problems on the Back Shed forum.

It adds two things. The Colour Maximite 2 can now run programs written in C and C++, compiled for its processor: MicroPython, Doom and ScummVM come with it, and a new manual explains how to write more. And it has an FM synthesiser, an emulated OPL3, which plays MIDI files, the PicoMite's PLAY MIDI and PLAY NOTE commands without a VS1053 module, and the music of DOS games.

The same firmware file runs on both the Generation 1 and the Generation 2.


[SIZE=4][COLOR=BLUE][B]Before you update[/B][/COLOR][/SIZE]
• [B]Options kept:[/B] all of them. A setting of OPTION FLASH 1 becomes OPTION FLASH 2 (see below).
• [B]Kept:[/B] the library, the variables saved with VAR SAVE, the flash slots (which are on the SD card), and the programs and files on the SD card.
• [B]Not kept:[/B] the program held in flash, as the firmware now uses that part of the flash. RUN loads it again from its file as usual. A program run at power up by OPTION AUTORUN has to be run once with RUN after the update.


[SIZE=4][COLOR=BLUE][B]What is new[/B][/COLOR][/SIZE]
• [B]Loadable programs.[/B] A file ending .APP is a program written in C or C++ and compiled for the Colour Maximite 2's processor. RUN runs it:

[CODE]RUN "A:/micropython.app"
CHDIR "A:/Doom" : RUN "doom.app"[/CODE]

    ◦ It runs at the full speed of the processor and takes over the computer while it runs, through services the firmware gives it: the console, files, the screen, the keyboard and mouse, sound, the FM synthesiser and the I/O pins.
    ◦ The words after RUN's comma are its arguments. When it ends, MMBasic carries on: at the command prompt it returns to the prompt, and in a BASIC program it goes on with the next statement, the program's variables as they were.
    ◦ MMBasic tidies up after it: its files are closed, its sound stopped, its I/O pins released, and the video mode, font, colours and palette put back.
    ◦ Ctrl-C asks it to end, and then stops the BASIC program that ran it too.
    ◦ A Generation 2 keeps 8MB of its memory for loadable programs. A Generation 1 lends a program the largest free part of MMBasic's heap (about 4MB at the command prompt) while it runs.
    ◦ Errors: "Not a loadable program", "Needs a newer firmware", "Needs a G2", "Needs n KB, n KB free", "The program file is damaged".
• [B]Three programs come with the firmware,[/B] in CMM2_Programs_7.00.00RC0.zip, to copy to the SD card:
    ◦ [B]MicroPython,[/B] as on the Pico Computer 3: its display, keyboard, mouse, audio and image modules, SQLite, ulab and the machine module on the rear I/O pins. It runs Python about twice as fast as the RP2350 does.
    ◦ [B]Doom,[/B] with Freedoom, a free replacement for its game data: about 50 frames a second on a Generation 2 with its sound effects and its music on the FM synthesiser.
    ◦ [B]ScummVM,[/B] for classic adventure games (AGI, SCI, SCUMM, Gobliiins and Kyrandia), with two free games: the Freddy Pharkas demo and DG: The Adventure Game. It needs a Generation 2.
• [B]A new manual, Colour Maximite 2 Loadable Programs,[/B] is for programmers: the tools that build a program (in the repository's tools/sdk, with the free Arm GNU toolchain), how the firmware runs one, every service with examples, and how MicroPython, Doom and ScummVM were ported.
• [B]An FM synthesiser:[/B] an emulation of the Yamaha YMF262 (the OPL3 of the Sound Blaster cards), by ymfm.
    ◦ [B]PLAY MIDIFILE file$ [, interrupt][/B] plays a Standard MIDI File.
    ◦ [B]PLAY MIDI[/B] turns it into a General MIDI instrument for [B]PLAY NOTE ON[/B] and [B]PLAY NOTE OFF[/B] and [B]PLAY MIDI CMD[/B], the PicoMite's commands for its VS1053 module. [B]PLAY MIDI TEST[/B] plays a tune kept in the firmware.
    ◦ Each of the 128 General MIDI instruments and each drum is an FM instrument of the GENMIDI bank in the firmware (Freedoom's, the bank Doom's music was written for), so MIDI music sounds as it did on a DOS game's Sound Blaster.
    ◦ [B]PLAY OPL file$ [, interrupt][/B] plays music recorded from an OPL chip: IMF (Wolfenstein 3D, Commander Keen), DOSBox's DRO and VGM files.
    ◦ [B]PLAY OPL[/B] on its own, [B]PLAY OPL WRITE[/B] and [B]PLAY OPL RESET[/B] let a program write the chip's registers itself, and [B]PLAY OPL TEST[/B] measures its share of the processor.
    ◦ It plays in the background as the other sounds do, and PLAY PAUSE, RESUME, STOP and VOLUME work on it. MM.INFO$(SOUND) gives "OPL" or "MIDI", and MM.INFO$(TRACK) the file's name.
    ◦ It takes a share of the processor while it plays: about 20% with no notes sounding and 30% to 55% for typical music on a Generation 2. A BASIC program keeps about three quarters of its speed.


[SIZE=4][COLOR=BLUE][B]What behaves differently[/B][/COLOR][/SIZE]
• [B]OPTION FLASH[/B] takes 2 to 6, and 2 is the default. The firmware has grown into the first part of the flash that programs used.
• [B]MM.INFO(HEAP)[/B] on a Generation 2 is 8MB less (about 15.9MB), as that memory is kept for loadable programs.


[SIZE=4][COLOR=BLUE][B]Fixed since 7.00.00b5[/B][/COLOR][/SIZE]
• [B]With a USB touch screen and OPTION MAXCTRLS above 0, programs ran slower,[/B] as every statement checked for the GUI's touch input. The GUI is now seen to once a millisecond: the solar eclipse benchmark takes 1.70 s compiled with the GUI running, as it does without it.
• [B]After PLAY WAV (or FLAC, MP3) and PLAY STOP,[/B] the sound output kept the number of the file it had closed. A file the program opened next could be given that number, and the next sound command closed it.


[SIZE=4][COLOR=BLUE][B]The programs tested[/B][/COLOR][/SIZE]
• The regression tests: tests/cmm2 (113 programs), the PicoMite's tests, the goldens (202 programs) and the Testfiles (66), each with OPTION COMPILE OFF, ON and SHADOW; SP Tools; the editor's and the file manager's tests. All give the results they gave with 7.00.00b5, except the free memory that three of the Testfiles print, now 8MB less on a Generation 2.
• On a Generation 1, tests/cmm2 runs as on a Generation 2, apart from what the Generation 1's hardware does not have (32-bit colour, the mouse in use) and rgb121 (see Known problems).
• MicroPython, Doom and ScummVM on both generations (ScummVM on the Generation 2), including the full Day of the Tentacle.


[SIZE=4][COLOR=BLUE][B]Known problems[/B][/COLOR][/SIZE]
• [B]RUN's arguments are changed when RUN does not start the line.[/B] In [FONT=Courier]CHDIR "A:/Doom" : RUN "doom.app", -timedemo demo1[/FONT] the program is given the arguments as MMBasic stores them, in capitals and with the minus sign changed. MM.CMDLINE$ after a RUN inside a program is affected the same way. Typed as a line of its own, RUN passes them as they are written.
• [B]On a Generation 1, the test program rgb121 stops responding in MODE 8,4[/B] when it shows three layers (FRAMEBUFFER LAYER TOP) and waits for a frame. It is in 7.00.00b5 too. A reset is needed.
• [B]With a USB touch screen connected, a mouse click can be taken as a swipe[/B] by the GUI controls' gestures, as the click's end is taken from the touch screen.
• An armed interrupt pin slows the program down, because the pin is polled after every statement.


[SIZE=4][COLOR=BLUE][B]The manual[/B][/COLOR][/SIZE]
The User Manual describes all of the above:

• RUN of a .APP file, in the commands, and the chapter Using MMBasic's new section Loadable Programs;
• the FM synthesiser, in the chapter Sound Output's new section FM Synthesis and MIDI, and PLAY MIDI, PLAY NOTE, PLAY MIDI CMD, PLAY MIDI TEST, PLAY MIDIFILE and PLAY OPL in the commands;
• MM.INFO$(SOUND) and MM.INFO$(TRACK), in the read-only variables;
• the memory kept for loadable programs, in the chapter MMBasic Characteristics.

Appendix O lists the new companion manual, Colour_Maximite_2_Loadable_Programs.pdf, posted with this release.
