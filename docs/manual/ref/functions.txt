# Functions: the reference entries (tools/manual/reftext.py)

=== ABS( number )
---
Returns the absolute value of the argument 'number' (i.e. any negative sign is removed and a positive number is returned).

=== ACOS( number )
---
Returns the inverse cosine of the argument 'number' in radians (or in degrees after OPTION ANGLE DEGREES).  'number' must be -1 to 1.

=== ASC( string$ )
---
Returns the ASCII code (i.e. byte value) for the first letter in ‘string$’.

=== ASIN( number )
---
Returns the inverse sine value of the argument 'number' in radians (or in degrees after OPTION ANGLE DEGREES).  'number' must be -1 to 1.

=== ATN( number )
---
Returns the arctangent of the argument 'number' in radians (or in degrees after OPTION ANGLE DEGREES).

=== ATAN2( y, x )
---
Returns the arc tangent of the two numbers x and y as an angle expressed in radians (or in degrees after OPTION ANGLE DEGREES).
It is similar to calculating the arc tangent of y / x, except that the signs of both arguments are used to determine the quadrant of the result.

=== BASE$( base, number [, chars])
---
Returns a string giving the value of 'number' in the number base 'base'.  'base' can be from 2 to 36 with the digits above nine represented by the letters A to Z.
'chars' is optional and specifies the number of characters in the string with zero as the leading padding character(s).
BIN$(), OCT$() and HEX$() are shortcuts for BASE$() with a base of 2, 8 and 16 respectively.  Use BASE$() for any other base, for example BASE$(12, 100) will return 84.

=== BAUDRATE( comm [, timeout] )
--- keep
Returns the baud rate of any data received on the serial communications port ‘comm’, which is 1 for COM1: or 2 for COM2: (the ports on the rear I/O connector).  The port must not be open.
This will sample the port over the period of ‘timeout’ seconds (1 to 10).  ‘timeout’ will default to one second if not specified.  The result is the nearest standard baud rate, from 110 to 460800.
Returns zero if no activity on the port within the timeout period.

=== BIN$( number [, chars])
---
Returns a string giving the binary (base 2) value for the 'number'.
'chars' is optional and specifies the number of characters in the string with zero as the leading padding character(s).

=== BIN2STR$(type, value [,BIG])
---
Returns a string containing the binary representation of 'value'. 
'type' can be:
{l=1404 h=1275}  INT64	signed 64-bit integer converted to an 8 byte string 
{l=1404 h=1275}  UINT64	unsigned 64-bit integer converted to an 8 byte string
{l=1404 h=1275}  INT32  	signed 32-bit integer converted to a 4 byte string
{l=1404 h=1275}  UINT32  	unsigned 32-bit integer converted to a 4 byte string 
{l=1404 h=1275}  INT16  	signed 16-bit integer converted to a 2 byte string
{l=1404 h=1275}  UINT16  	unsigned 16-bit integer converted to a 2 byte string 
{l=1404 h=1275}  INT8  	signed 8-bit integer converted to a 1 byte string
{l=1404 h=1275}  UINT8  	unsigned 8-bit integer converted to a 1 byte string 
{l=1404 h=1275}  SINGLE  	single precision floating point number converted to a 4 byte string
{l=1404 h=1275}  DOUBLE	double precision floating point number converted to a 8 byte string
By default the string contains the number in little-endian format (i.e. the least significant byte is the first one in the string).  Setting the third parameter to ‘BIG’ will return the string in big-endian format (i.e. the most significant byte is the first one in the string).  In the case of the integer conversions, an error will be generated if the  ‘value’ cannot fit into the ‘type’ (eg, an attempt to store the value 400 in a INT8).
This function makes it easy to prepare data for efficient binary file I/O or for preparing numbers for output to sensors and saving to flash memory. 
See also the function STR2BIN

=== BIT(var%, bitno)
---
Returns the value of a specific bit (0-63) in an integer variable (0 or 1).
See also the BIT command

=== BOUND(array() [,dimension])
---
This returns the upper limit of the array for the dimension requested. 
The dimension defaults to one if not specified. Specifying a dimension value of 0 will return the current value of OPTION BASE. 
Requesting a dimension that the array does not have will generate an error, as will using BOUND() on a variable that is not an array.  Note that zero is a valid upper limit: an array declared with a single element under OPTION BASE 0 (for example DIM a(0)) has an upper limit of zero.
For example:
DIM myarray(44,45) 
BOUND(myarray(),2) will return 45

=== BYTE(var$, byteno)
---
Returns the integer value of a specific byte in a string (0-255). This is the equivalent of ASC(MID$(var$,byteno,1)) but operates much faster.
See also the BYTE command

=== CALL(userfunname$ [,userfunparameters,..])
---
This is an efficient way of programmatically calling user defined functions. (See also the CALL command).  In many cases it can be used to eliminate complex SELECT and IF THEN ELSEIF ENDIF clauses and is processed in a much more efficient manner.  
‘userfunname$’ can be any string or variable or function that resolves to the name of a normal user function (not an in-built command).  ‘userfunparameters’ are the same parameters that would be used to call the function directly.  
A typical use for this command could be writing any sort of emulator where one of a large number of functions should be called depending on a some variable. It also provides a method of passing a function name to another subroutine or function as a variable.

=== CHOICE(condition, ExpressionIfTrue, ExpressionIfFalse)
---
This function allows you to do simple either/or selections more efficiently and faster than using IF THEN ELSE ENDIF clauses.
The condition is anything that will resolve to nonzero (true) or zero (false).
The expressions are anything that you could normally assign to a variable or use in a command and can be integers, floats or strings.
Examples: \n	PRINT CHOICE(1, "hello","bye") will print "hello"\n	PRINT CHOICE (0, "hello","bye") will print "bye"\n	a=1 : b=1 : PRINT CHOICE (a=b, 4, 5) will print 4

=== CHR$( number )
---
Returns a one-character string consisting of the character corresponding to the ASCII code (i.e. byte value) indicated by argument 'number'.

=== CINT( number )
---
Round numbers with fractional portions up or down to the next whole number or integer.
For example, 	45.47 will round to 45\n		45.57 will round to 46\n		-34.45 will round to -34\n		-34.55 will round to -35
See also INT() and FIX().

‘channel’ is optional and is the I^^2^^C channel for the controller (1 to 3, defaults to 3, the front panel Wii connector).
‘funct’ is a 1 or 2 letter code indicating the information to return as follows:

{b=20 a=20 l=941 h=567}T	the ID code of the controller, &HA4200101
The positions are from 0 to 255: the left joystick has 64 steps and the right joystick and the L and R buttons 32.

=== CLICK(DOWN)
or
CLICK(UP)
or
CLICK(X)
or
CLICK(Y)
or
CLICK(REF)
or
CLICK(LASTREF)
or
CLICK(LASTX)
or
CLICK(LASTY)
---
Reports the clicks for the GUI controls (see the chapter GUI Controls), as the PicoMite's CLICK() does: the left button of the mouse (a USB mouse as soon as it is plugged in, or a mouse set with OPTION MOUSE), a click made with GUI CLICK, or a button set with GUI CLICK PIN.  A USB touch screen is read with TOUCH(), which takes these keywords too; the touch screen's own keywords and the gestures (CLICK(SWIPE) and the others) are a syntax error here.
CLICK(DOWN) returns 1 (true) if the button is currently down.  CLICK(UP) returns 1 (true) if it is not.
CLICK(X) and CLICK(Y) return the cursor's active point while the button is down (see GUI CURSOR): where the mouse is when the cursor is linked to it, which the GUI's own pointer is, and where GUI CLICK presses.  They return -1 when the button is not down.
CLICK(LASTX) and CLICK(LASTY) return the coordinates of the last location that was clicked on.
CLICK(REF) returns the reference number of the GUI control that is currently being clicked on, or zero if none.  CLICK(LASTREF) returns the reference number of the last control that was clicked on.
LASTX, LASTY, REF and LASTREF are kept by the GUI controls: they change only when OPTION MAXCTRLS is set and the program has used the GUI commands (for example, created a control or set GUI INTERRUPT).  The controls are described in the document GUI Controls and Programming.pdf (see Appendix O).

=== COS( number )
---
Returns the cosine of the argument 'number' in radians (or in degrees after OPTION ANGLE DEGREES).

=== CTRLVAL( [#]ref )
---
Returns the value of the GUI control number ‘ref’: a number for most controls (for a list box the index of the item selected, for a slider its value), and a string for a text box, a format box, a display box or a caption.
The GUI controls need OPTION MAXCTRLS, and are clicked with a mouse or with GUI CLICK.  They are described in the chapter GUI Controls and in the document GUI Controls and Programming.pdf (see Appendix O).

=== CWD$
---
Returns the current working directory, with its drive, as a string.  A: is the SD card and C: the USB flash drive.
The format is:     `A:/dir1/dir2`.  See also MM.INFO(DIRECTORY), which always ends with a ‘/’.

=== DATE$
--- keep
Returns the current date based on MMBasic’s internal clock as a string in the form "DD-MM-YYYY".   For example, "28-07-2012".
The internal clock/calendar will keep track of the time and date including leap years.  To set the date use the command DATE$ =.

=== DATETIME$(n)
---
Returns the date and time corresponding to the epoch number ‘n’ (number of seconds that have elapsed since midnight GMT on January 1, 1970), from -2147483648 to 2147483647 (13 December 1901 to 19 January 2038). 
The format of the returned string is “dd-mm-yyyy hh:mm:ss”. Use the text NOW to get the current datetime string, ie,  DATETIME$(NOW)

=== DAY$(date$)
---
Returns the day of the week for a given date as a string. \nFor example,  “Monday”, “Tuesday” etc. 
‘date$’ is a string and its format can be DD-MM-YY or DD-MM-YYYY or YYYY-MM-DD.  You can also use NOW to get the day for the current date, eg, PRINT DAY$(NOW)

=== DEG( radians )
---
Converts 'radians' to degrees.

Returns data from the mouse in use: a USB mouse, or else the PS2 mouse set with OPTION MOUSE 0 or a mouse opened with CONTROLLER MOUSE OPEN (a PS2 mouse or a Hobbytronic interface).  This is the PicoMite's function; the MOUSE() function reads the same mice.

=== DIR$( fspec, type )\nor\nDIR$( fspec )\nor\nDIR$(  )
---
Will search the current drive (the SD card or the USB flash drive) for files and return the names of entries found.
'fspec' is a file specification using wildcards the same as used by the FILES command.  Eg, "\*" will return all entries, "\*.TXT" will return text files.  Note that the wildcard \*.\* does not find files or folders without an extension.  'fspec' can include a path (eg, "C:/data/\*.TXT") and then that directory is searched instead of the current one.
'type' is the type of entry to return and can be one of:
{t=l1396 l=432}ALL	Search for all files and directories\nDIR	Search for directories only\nFILE	Search for files only (the default if 'type' is not specified)
The function will return the first entry found.  To retrieve subsequent entries use the function with no arguments.  i.e.  DIR$( ).  The return of an empty string indicates that there are no more entries to retrieve.
{l=496 h=496}This example will print all the files in a directory:\n`f$ = DIR$("\*", FILE)\nDO WHILE f$ <> ""\n  PRINT f$\n  f$ = DIR$()\nLOOP`

=== DISTANCE( trigger, echo )
or
DISTANCE( trig-echo )
---
Measure the distance to a target using the HC-SR04 ultrasonic distance sensor.
Four pin sensors have separate trigger and echo connections.  'trigger' is the I/O pin connected to the "trig" input of the sensor and 'echo' is the pin connected to the "echo" output of the sensor. 
Three pin sensors have a combined trigger and echo connection and in that case you only need to specify one I/O pin to interface to the sensor.
Note that the HC-SR04 is a 5V device so the I/O pins used with it should be 5V tolerant (the pins marked 5V under I/O Pin Capabilities in the chapter Hardware Features).
The I/O pins are automatically configured by this function and multiple sensors can be used on different I/O pins.
The value returned is the distance in centimetres to the target or -1 if no target was detected or -2 if there was an error (i.e. sensor not connected).

=== EOF( [#]fnbr )
---
Will return true if the file previously opened on the SD card or USB flash drive for INPUT with the file number ‘#fnbr’ is positioned at the end of the file.
For a serial communications port opened as 'fnbr' this function will return true if there are no characters waiting in the receive buffer.  #0 can be used which refers to the console's input buffer.
The # is optional.  Also see the OPEN, INPUT and LINE INPUT commands and the INPUT$ function.

=== EPOCH(DATETIME$)
---
Returns the epoch number (number of seconds that have elapsed since midnight GMT on January 1, 1970) for the supplied DATETIME$ string. 
The format for DATETIME$ is “dd-mm-yyyy hh:mm:ss”, “dd-mm-yy hh:mm:ss”,  or “yyyy-mm-dd hh:mm:ss”,. Use NOW to get the epoch number for the current date and time, i.e. PRINT EPOCH(NOW)

=== EVAL( string$ )
---
Will evaluate 'string$' as if it is a BASIC expression and return the result. 
'string$' can be a constant, a variable or a string expression. The expression can use any operators, functions, variables, subroutines, etc that are known at the time of execution.  The returned value will be an integer, float or string depending on the result of the evaluation.
For example:  S$ = "COS(RAD(30)) \* 100" : PRINT EVAL(S$) 
Will display:  86.6025

=== EXP( number )
---
Returns the exponential value of 'number', i.e. e^x where x is 'number'.

=== FIELD$( string1, nbr [, string2 [, string3]] )
---
Returns a particular field in a string with the fields separated by delimiters. Note that a space character cannot be used as a delimiter.
'nbr' is the field to return (the first is nbr 1).  'string1' is the string to search and 'string2' is a string holding the delimiters (more than one can be used); if it is omitted the delimiter is a comma. The space character may not be used as a delimiter.
'string3' is optional and if specified will include characters that are used to quote text in 'string1' (ie, quoted text will not be searched for a delimiter).  The quote characters are returned as part of the field.  Spaces at the start and end of the field are removed.
For example:
S$ = "foo, boo, zoo, doo"
r$ = FIELD$(s$, 2, ",")
will result in r$ = "boo".  While:
s$ = "foo, 'boo, zoo', doo"
r$ = FIELD$(s$, 2, ",", "'")
will result in r$ = "'boo, zoo'".

=== FIX( number )
---
Truncate a number to a whole number by eliminating the decimal point and all characters to the right of the decimal point. 
For example 9.89 will return 9 and -2.11 will return -2. 
The major difference between FIX() and INT() is that FIX() provides a true integer function (i.e. does not return the next lower number for negative numbers as INT() does).  This behaviour is for Microsoft compatibility. 
See also CINT() .

=== FORMAT$( nbr [, fmt$] )
---
{kn=1}Will return a string representing ‘nbr’ formatted according to the specifications in the string ‘fmt$’.
{kn=1}The format specification starts with a % character and ends with a letter.  Anything outside of this construct is copied to the output as is.
{kn=1}The structure of a format specification is:\n                    % [flags] [width] [.precision] type
{kn=1}Where ‘flags’ can be:
{kn=1 t=l432,l1152 l=1152 h=1152}	-	Left justify the value within a given field width
{kn=1 t=l432,l1152 l=1152 h=1152}	0	Use 0 for the pad character instead of space
{kn=1 t=l432,l1152 l=1152 h=1152}	+	Forces the + sign to be shown for positive numbers
{kn=1 t=l432,l1152 l=1152 h=1152}	space	Causes a positive value to display a space for the sign. Negative values still show the – sign
‘width’ is the minimum number of characters to output, less than this the number will be padded, more than this the width will be expanded.
‘precision’ specifies the number of fraction digits to generate with an e, or f type or the maximum number of significant digits to generate with a g type and defaults to 6.  If specified, the precision must be preceded by a dot (.).
\n‘type’ can be one of:
{t=l432,l1152 l=1152 h=1152}	g	Automatically format the number for the best presentation.
{t=l432,l1152 l=1152 h=1152}	f	Format the number with the decimal point and following digits
{t=l432,l1152 l=1152 h=1152}	e	Format the number in exponential format
If uppercase G or E is used the exponential output will use an uppercase E.  If the format specification is not specified “%g” is assumed.  Only one format specification is allowed, and the result can be at most 255 characters long ("String too long").
Examples:	format$(45) will return 45\nformat$(45, “%g”) will return 45\nformat$(24.1, “%g”) will return 24.1\nformat$(24.1, “%f”) will return 24.100000\nformat$(24.1, “%e”) will return 2.410000e+01\nformat$(24.1, “%09.3f”) will return 00024.100\nformat$(24.1, “%+.3f”) will return +24.100

=== GETSCANLINE
---
Reports the line that is currently being drawn on the VGA monitor.  Using this to time updates to the screen can avoid timing effects caused by updates while the screen is being updated.
The first visible line returns 0 and the last MM.VRES - 1; a larger value is in the frame blanking period.  In the modes whose lines are drawn twice (3, 5, 6, 7, 12, 13 and 17) the count is in the mode's own lines.

=== GPS()
--- keep
The GPS functions return data from a GPS receiver on a serial port opened with OPEN comspec$ AS GPS (an error is given if there is none).  The values are updated in the background as the receiver sends them.
The function GPS(VALID) should be checked before any of these functions are used to ensure that the returned value is valid.

=+= GPS(ALTITUDE)
--- keep
Returns the current altitude in metres (if the receiver sends the GGA sentence).

=+= GPS(DATE)
--- keep
Returns the normal date string corrected for local time, e.g. "12-01-2020".

=+= GPS(DOP)
--- keep
Returns the DOP (horizontal dilution of precision) value (if the receiver sends the GGA sentence).

=+= GPS(FIX)
--- keep

=== KEYDOWN(n)
---
Return the decimal ASCII value of the USB keyboard key that is currently held down or zero if no key is down.
The decimal values for the function and arrow keys are listed in Appendix I.
This function will report multiple simultaneous key presses and the parameter 'n' is the number of the keypress to report.  KEYDOWN(0) will return the number of keys being pressed 
For example, if "c", "g" and "p" are pressed simultaneously KEYDOWN(0) will return 3, KEYDOWN(1) will return 99, KEYDOWN(2) will return 103, etc.  The keys do not need to be pressed simultaneously and will report in the order pressed. Taking a finger off a key will promote the next key pressed to #1.
The first key ('n' = 1) is entered in the keyboard buffer (accessible using INKEY$) while keys 2 to 6 can only be accessed via this function.  Using this function will clear the console input buffer.
KEYDOWN(7) will give any modifier keys that are pressed. These keys do not add to the count in keydown(0)
The return value is a bitmask as follows:
lalt = 1, lctrl = 2, lgui = 4, lshift = 8, ralt = 16, rctrl = 32, rgui = 64, rshift = 128
KEYDOWN(8) will give the current status of the lock keys. These keys do not add to the count in keydown(0)
The return value is a bitmask as follows:
caps_lock = 1, num_lock = 2, scroll_lock = 4
Note that some keyboards will limit the number of active keys that they can report on.

=== LGETBYTE(array%(), n)
---
Returns the numerical value of the 'n'th byte in the LONGSTRING held in 'array%()'. This function respects the setting of OPTION BASE in determining which byte to return.
LGETBYTE treats the LONGSTRING as a plain array of bytes and therefore honours OPTION BASE when interpreting 'n': with OPTION BASE 0 the first byte is number 0, while with OPTION BASE 1 the first byte is number 1.
Note that LINSTR and LGETSTR$ always work with 1-based positions (the first character is position 1) irrespective of OPTION BASE. Consequently, when OPTION BASE 0 is in effect, a position returned by LINSTR (or passed to LGETSTR$) refers to the byte that LGETBYTE would read at that position minus one. Subtract 1 from a LINSTR result before passing it to LGETBYTE under OPTION BASE 0 (under OPTION BASE 1 the values line up directly).

=== PIXEL( x, y [,page])
--- keep
Returns the colour of a pixel on the screen.  ‘x’ is the horizontal coordinate and ‘y’ is the vertical coordinate of the pixel.  The optional ‘page’ specifies which page is to be read; the default is the current write page.  Set ‘page’ to FRAMEBUFFER to read from the framebuffer (see the FRAMEBUFFER command).
The colour is returned as a 24-bit RGB number: in the 12-bit colour depth with its transparency as well, in the 4-bit colour depth as one of the PicoMite's 16 colours (which MAP does not change), and in the 1-bit colour depth as the colour the pixel shows, its tile's foreground colour if it is set and its background colour if not (see TILE).
The colour is the one the colour depth holds, which is not the value RGB() gave when the pixel was drawn.  RGB() includes the transparency (15, opaque) in every colour depth but the 32-bit one, and each depth keeps only part of the 24 bits.  For example RGB(200, 100, 50) reads back as &HCD6531 in the 16-bit colour depth, &HFCC6633 in the 12-bit one and &HFF4000 in the 4-bit one.  In the 8-bit colour depth the colour comes back through the palette (see MAP and OPTION VGA OUTPUT), so with the default palette RGB(red) reads back as &HE00000.  Only the 32-bit colour depth returns the colour exactly.
So, to test what is on the screen, do not compare PIXEL( with RGB().  Compare it with a colour read by PIXEL( from a pixel drawn in that colour: drawing the value PIXEL( returned and reading it again gives the same value in every colour depth.  Black reads as 0 in every colour depth but the 12-bit one, where opaque black is &HF000000.
See the chapter *Graphics Functions* for a definition of the colours and graphics coordinates.

I/O pins used must be numbered consecutively and any I/O pin that is invalid or not configured as a digital input or output (DIN, INTH, INTL, INTB or DOUT) will cause the error "Invalid input pin".  An output pin returns its state.  The start/nbr pair can be repeated if additional groups of input pins need to be added: the first pair gives the lowest bits.
{t=l2592}This can be used to conveniently communicate with parallel devices like memory chips.
{kl=1}See the PORT command to simultaneously output to a number of pins.

=== PULSIN( pin, polarity )
or

or

---
Measures the width of an input pulse from 1µs to 10 seconds with 1µs resolution.
'pin' is the I/O pin to use for the measurement, it must be previously configured as a digital input.  'polarity' is the type of pulse to measure, if zero the function will return the width of the next negative pulse, if non zero it will measure the next positive pulse.

=== SPRITE()
--- keep
The SPRITE functions return information regarding sprites, which are small graphic images on the screen.  These are useful when writing games.  See also the SPRITE commands and Appendix F.  In each of them the # before a sprite number is optional.

=+= SPRITE(A, [#]n)
---
Returns the address in memory of the image of sprite ‘n’, or 0 if the sprite is not loaded.  The pixels are held row after row, four bytes each whatever the colour depth: the red, green and blue in bits 0-23 and the transparency (0 to 15, 15 solid) in bits 24-27.

=+= SPRITE(B, [#]n)
---
Returns how the background under displayed sprite ‘n’ meets the sprite, pixel by pixel, as on the PicoMite: what is drawn on the screen, scenery for example, against the sprite's shape.  The background is the one stored when the sprite was last drawn (any sprites under it included).  The shape is each row's and each column's span of solid pixels, from the first to the last, so a gap inside a span counts as the sprite.
It returns:
{l=720}0 - nothing is there: every background pixel is the transparent colour (in the 12-bit colour depth, or transparent)
{l=720}1 - something is within the sprite's rectangle but outside its shape
{l=720}2 - something is within its shape
It returns 0 if the sprite is not displayed.

=+= SPRITE(B, [#]n, side)
---
Returns more about the background found by the last SPRITE(B, n), for ‘side’:
{l=720}0 - how far in from the sprite's left edge the background reaches (the offset of the furthest pixel + 1)
{l=720}1 - how far in from its right edge
{l=720}2 - how far in from its top edge
{l=720}3 - how far in from its bottom edge
{l=720}4 - how deep the background within the shape is, from the left ends of the row spans
{l=720}5 - from their right ends
{l=720}6 - from the top ends of the column spans
{l=720}7 - from their bottom ends
Sides 0 to 3 are 0 if no background is there, or if it reaches all the way across.  Of 4 and 5 only the smaller, the depth from the nearer end, is given (the other is 0), and so of 6 and 7; both are 0 if they are equal.  So, after a step to the right, SPRITE(B, n, 5) > 0 says that the sprite has run into something on its right.

=+= SPRITE(C, [#]n)
--- keep
Returns the number of new collisions (contacts that began) of sprite ‘n’ found when it was last moved, or -1 if there were none.  Up to seven are recorded.  If n = 0 it returns the number of sprites that had a new collision following the last SPRITE SCROLL, SCROLLR, MOVE or RESTORE command.
A sprite that stays in contact with another is not counted again: SPRITE(T, n) returns all the sprites it is touching.

=+= SPRITE(C, [#]n, m)
---
Returns the number of the sprite which caused the ‘m’th collision of sprite ‘n’ (‘m’ from 1 to SPRITE(C, n)).  If n = 0 then returns the sprite number of the ‘m’th sprite that had a new collision following a SPRITE SCROLL, SCROLLR, MOVE or RESTORE command.
If the collision was with a static object (see SPRITE STATIC) the return value is &H80 + its number, and if it was with the edge of the screen it is:
{l=720}&HF1	collision with left of screen
{l=720}&HF2	collision with top of screen
{l=720}&HF4	collision with right of screen
{l=720}&HF8	collision with bottom of screen

=+= SPRITE(D, [#]s1, [#]s2)
--- keep
Returns the distance between the centres of sprites ‘s1’ and ‘s2’ (returns -1 if either sprite is not displayed).

=+= SPRITE(E, [#]n)
--- keep
Returns a bitmap indicating any edges of the screen the sprite is in contact with: 1 = left of screen, 2 = top of screen, 4 = right of screen, 8 = bottom of screen.  Returns 0 if the sprite is not displayed.

=+= SPRITE(H, [#]n)
--- keep
Returns the height of sprite ‘n’.  This function is active whether or not the sprite is currently displayed (active).  Returns -1 if the sprite is not loaded.

=+= SPRITE(L, [#]n)
--- keep
Returns the layer number of sprite ‘n’ if it is displayed, -1 if it is not.

=+= SPRITE(N)
--- keep
Returns the number of displayed (active) sprites.

=+= SPRITE(N, n)
--- keep
Returns the number of displayed (active) sprites on layer ‘n’ (0 to 10).

=+= SPRITE(S)
--- keep
Returns the number of the sprite which last caused a collision.  NB if the number returned is zero then the collision is the result of a SPRITE SCROLL, SCROLLR, MOVE or RESTORE command and the SPRITE(C…) function should be used to find how many and which sprites collided.  Returns -1 if the last command that checks for collisions found none.

=+= SPRITE(ST, [#]n, X|Y|W|H|A)
---
Returns the left (X), top (Y), width (W) or height (H) of static object ‘n’ (1 to 64), or -1 if it is not declared, or (A) 1 if it is declared and 0 if not.  See SPRITE STATIC.

=+= SPRITE(ST, COLLISION)
---
Returns the number of the sprite in the last collision with a static object, or -1 if there has been none.

=+= SPRITE(ST, OBJECT)
---
Returns the number of the static object in the last collision with one, or -1 if there has been none.

=+= SPRITE(T, [#]n)
--- keep
Returns a bitmap showing all the sprites currently touching the requested sprite.  Bits 0-63 in the returned integer represent a current collision with sprites 1 to 64 respectively.  Returns 0 if the sprite is not displayed.

=+= SPRITE(V, [#]s1, [#]s2)
--- keep
Returns the vector from sprite ‘s1’ to ‘s2’ in radians.
The angle is based on the clock so if ‘s2’ is above ‘s1’ on the screen then the answer will be zero (and it increases clockwise).  This can be used on any pair of sprites that are visible.  If either sprite is not visible the function will return -1.
This is particularly useful after a collision if the programmer wants to make some differential decision based on where the collision occurred.  The angle is calculated between the centre of each of the sprites which may of course be different sizes.

=+= SPRITE(W, [#]n)
--- keep
Returns the width of sprite ‘n’.  This function is active whether or not the sprite is currently displayed (active).  Returns -1 if the sprite is not loaded.

=+= SPRITE(X, [#]n)
--- keep
Returns the X-coordinate of sprite ‘n’.  This function is only active when the sprite is currently displayed (active).  Returns 10000 otherwise.

=+= SPRITE(Y, [#]n)
--- keep

=== TOUCH(X)
or

Reports a USB touch screen (see the chapter Keyboard, Mouse and Gamepad), as the PicoMite's TOUCH() does, and the mouse and GUI CLICK as CLICK() does.  A press belongs to what made it, a finger or the mouse's button (or GUI CLICK), until that is released.

{t=l1300 b=20 a=20 l=1440 h=1066}DTAP	1 on a double tap: two taps within 500 mS and 30 pixels of each other
{t=l1300 b=20 a=20 l=1440 h=1066}HOLD	1 on a long press: a finger held still for 500 mS (it is reported while the finger is still down)
{t=l1300 b=20 a=20 l=1440 h=1066}PINCH	0 for none, 1 expand, 2 contract
{t=l1300 b=20 a=20 l=1440 h=1066}EXPAND	1 when two fingers move apart by 30% or more (CONTRACT: together)
{t=l1300 b=20 a=20 l=1440 h=1066}ROTATE	0 for none, 1 clockwise, 2 anticlockwise
{t=l1300 b=20 a=20 l=1440 h=1066}CW	1 when two fingers turn clockwise by about 15 degrees (CCW: anticlockwise)
{t=l1300 b=20 a=20 l=1440 h=1066}TTAP	1 on a two-finger tap: both fingers down for less than 300 mS, moving no more than 15 pixels
