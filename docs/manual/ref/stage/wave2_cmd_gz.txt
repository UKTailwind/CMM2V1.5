The GUI commands create the GUI controls and manage them: GUI BUTTON, SWITCH, CHECKBOX, RADIO, LED, FRAME, NUMBERBOX, TEXTBOX, FORMATBOX, SPINBOX, DISPLAYBOX, CAPTION, GAUGE, BARGAUGE and AREA create a control and GUI PAGE, SETUP, DELETE, DISABLE, ENABLE, HIDE, SHOW, RESTORE, REDRAW, FCOLOUR, BCOLOUR and INTERRUPT manage them. # ACTION REPLACE commands.txt 856 "=== GUI BITMAP  x,  y,  bits  [, width]  [, height]  [, scale]  [, c]  [, bc]"
=== GUI BITMAP  x,  y,  bits  [, width]  [, height]  [, scale]  [, c]  [, bc]
---
Displays the bits in a bitmap on the screen starting at 'x' and 'y'.
'height' and 'width' are the dimensions of the bitmap as displayed on the screen and default to 8x8.  
{t=l2592}'scale' is optional and can be 1 to 15 (the default is 1).  
{t=l2592}'c' is the drawing colour and 'bc' is the background colour.  They are optional and default to the current foreground and background colours.  'bc' can be -1 and then the background is not drawn (the pixels of the zero bits are left as they are).
The bitmap can be an integer or a string variable or constant and is drawn using the first byte as the first bits of the top line (bit 7 first, then bit 6, etc) followed by the next byte, etc.  When the top line has been filled the next line of the displayed bitmap will start with the next bit in the integer or string.  An integer holds 64 bits (its least significant byte is the first) and a string up to 255 bytes: 'width' x 'height' must not be more bits than it holds ("Not enough data").
See the chapter *Graphics Functions* for a definition of the colours and graphics coordinates.

=== GUI CURSOR ON [n [,x, y [,colour]]]
--- keep tight
Displays and manipulates a cursor (eg, a mouse pointer) on the screen.  The cursor sits above all other graphics and nothing can overwrite it.  It is drawn on page 0 (page 1 in the 12-bit colour depth) and it is not available in the 4-bit colour depth ("Invalid for this screen mode").
GUI CURSOR ON enables and displays the cursor.  ‘n’ is the cursor number: 0 is a mouse type pointer (the default), 1 is a cross hair and 2 is a user defined cursor previously loaded with GUI CURSOR LOAD.  ‘x’ and ‘y’ specify the initial position of the cursor's active point (the top left corner of the screen if omitted) and ‘colour’ can be used to override the default white colour of cursors 0 and 1.  If the cursor is already on the command does nothing.

=+= GUI CURSOR LOAD fname$
--- keep tight
GUI CURSOR LOAD loads cursor number 2 from the file ‘fname$’, which must be given with its extension, and GUI CURSOR ON 2 then displays it.  The cursor must be off when it is loaded ("Cursor On").  The file uses the same layout and colour coding as a sprite file (see SPRITE LOAD) except that the header line is: width, height, xoffset, yoffset.  The two offsets define the position of the cursor’s active point within the image - the mouse pointer (cursor 0) has offsets 0,0 (the tip of the arrow) and the cross hair (cursor 1) has 7,7 (its centre).  The cursor is held in the pixel format of the colour depth in use when it is loaded, so it should be loaded after the MODE command.

The cursor cannot be linked while the GUI controls are using the mouse ("Mouse in use for GUI").

Shows the syntax of a command or function.  It can only be used at the command prompt (in the editor F11 shows the help for the keyword at the cursor).  ‘searchtext’ need not be quoted.
If the SD card has the file help.txt in its root directory (A:/help.txt) HELP looks up ‘searchtext’ in that file.  This can be a user written or community developed file and must be in a particular format.
For each help entry the first line must be a search string prefixed with a ~ character. This is used for the help functionality to find an entry and is not displayed. The ‘searchtext’ can contain ? for single character substitution or \* for multiple character (or none) substitution.
Following, the search string the next line would typically give the syntax of a particular command of function. Any subsequent lines would be further explanation.
{kn=1}e.g.

Without A:/help.txt the help built into MMBasic is used.  HELP then shows up to three lines of it that start with the text typed so far (‘searchtext’ and any characters typed after it, which can be deleted with backspace), and the up and down arrow keys move through the matches.  Esc or F12 ends the command.

This controls the action taken if an error occurs while running a program and applies to all errors discovered by MMBasic including syntax errors, wrong data, missing hardware, etc.

The first version of the command sets an interrupt which will call 'target' user defined subroutine whenever there is one or more characters waiting in the console input buffer (typed on the USB keyboard or received from the serial console). 
Note that all characters waiting in the input buffer should be read in the interrupt subroutine otherwise another interrupt will be automatically generated as soon as the program returns from the interrupt.

# cmd_sync (External.c:1524): a time of 0 clears it ("SYNC not initialised" after).  The example's GP0 is a PicoMite

# ACTION REPLACE commands.txt 2579 "=== SYNC time% [,period]"
=== SYNC time% [,period]
or
SYNC
---
The SYNC command allows the user to implement very precisely timed repeated actions (1-2 microseconds accuracy). 
To enable this the command is first called with the parameter time%. This sets up a repeating clock for time% microseconds. The optional parameter ‘period’ modifies the time and can be  “U” for microseconds, “M” for milliseconds or “S” for seconds. 
Once the clock is set up the program is synchronised to it using the SYNC command without parameters. This waits for the clock period to expire. For periods below 2 ms this is non-interruptible. Above 2 ms the program will respond to Ctrl-C but not any MMBasic interrupts. 
SYNC 0 stops the clock.
Typical use is to set the clock outside of a loop and then at the top of the loop call the SYNC command without parameters. This means the contents of the loop will be executed exactly once for each clock period set.  For example, the following would drive a servo with the required precise 50Hz timing:

{kn=1 b=0 a=0 l=720}`SYNC 20, M`
{kn=1 b=0 a=0 l=720}`DO`
{kn=1 b=0 a=0 l=720}`  SYNC`
{kn=1 b=0 a=0 l=720}`  PULSE 7, n`
{kn=1 b=0 a=0 l=720}`LOOP`
