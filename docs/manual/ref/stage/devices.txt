=== ADC OPEN freq, pin1 [, pin2] [, pin3] [, interrupt]
---
The ADC commands capture up to three channels of analog data in the background into arrays, at up to 500KHz per channel (480KHz on a 400MHz processor), with an optional trigger.  See also the chapter *Using the I/O Pins*.
{}
ADC OPEN opens the channels.  ‘freq’ is the sampling frequency in Hz.  The number of bits in each conversion follows from it and is applied automatically:
{n=39 v=0}Above 160KHz the conversion is 8 bits per channel
{n=39 v=0}From 40KHz to 160KHz it is 10 bits
{n=39 v=0}From 20KHz to 40KHz it is 12 bits
{n=39 v=0}From 10KHz to 20KHz it is 14 bits
{n=39 v=0}Below 10KHz it is 16 bits
Each channel has its own converter.  ‘pin1’, the first channel, can be one of the pins 7, 10, 16, 22, 24 or 37, ‘pin2’ (the second) one of 8, 12, 26 or 29 and ‘pin3’ (the third) 13 or 15.  The pins are reserved for the ADC until ADC CLOSE.
‘interrupt’ is a normal MMBasic subroutine that will be called when the conversion completes.  It is always the fifth argument, so the arguments of unused channels are left empty, for example:  `ADC OPEN 100000, 7, , , Done`

=+= ADC FREQUENCY freq
--- keep
Changes the sampling frequency without closing and opening the ADC.  The new frequency is used by the next ADC START (it does not change a capture already running).
This command is only valid if the number of bits given by the table above does not change; otherwise use ADC CLOSE and ADC OPEN.

=+= ADC TRIGGER channel, level [, timeout]
---
Sets up triggering of the ADC.  This is given after ADC OPEN and before the ADC START command.
The ‘channel’ can be a number between one and three depending on the number of pins specified in the ADC OPEN command.
The ‘level’ can be between -VCC and VCC (VCC is OPTION VCC, normally 3.3).  A positive number indicates that the trigger will be on a positive going transition through the specified voltage.  A negative number indicates a negative going transition through the specified voltage (without its sign).
‘timeout’ is the number of ADC samples to take before abandoning the wait for the trigger condition and starting the capture anyway.  Setting a value equal to the frequency of the sampling would give a timeout of 1 second.  If it is 0 or omitted the ADC waits for ever.
The trigger applies to every ADC START until the ADC is closed.

=+= ADC START array1!() [, array2!()] [, array3!()] [, C1min, C1max] [, C2min, C2max] [, C3min, C3max]
---
This starts conversion into the specified arrays, one for each channel opened (in the order of their pins in ADC OPEN).  The arrays must be floating point and the same size.  The size of the arrays defines the number of conversions.  Start can be called repeatedly once the ADC is OPEN.
‘C`x`min’ and ‘C`x`max’ will scale the readings of channel `x`.  For example, C1min=200 and C1max=100 will create values ranging from 200 to 100 for equivalent voltages of 0 - 3.3.  If the scaling is not used the results are returned as a voltage between 0 and OPTION VCC (defaults to 3.3V).  The scaling values are always the fourth to the ninth arguments, so the arguments of the arrays not used are left empty, for example:  `ADC START a!(), , , 0, 100`
If ADC OPEN did not specify an interrupt the command waits until the arrays are filled.  If it did, the command returns at once and the interrupt is called when they are full: the arrays must then be global (or STATIC), not LOCAL, as they are filled after the command has returned.

=+= ADC CLOSE
--- keep
Closes the ADC and returns the pins to normal use.

# Src/External.c:1466 Bitstream: exactly three arguments (pin, count 1-250000, array); the pin must be DOUT or OC (:1479); the array integer or float, of at least 'n' elements, each value 0-65535 (FloatToUint16, :1502-1505); TIM17 counts microseconds; the pin is toggled before each wait; interrupts are off throughout (:1509)
=== BITSTREAM pin, n, array()
---
This command is used to generate an extremely accurate bit sequence on the pin specified.  The pin must have previously been set up as an output (SETPIN pin, DOUT, with or without OC) and set to the required starting level.
‘n’ is the number of transitions (1 to 250000) and ‘array()’ is a numeric array (integer or floating point) with at least ‘n’ elements.
Notes:
{n=39 v=0}The array contains the length of each level in the bitstream in microseconds (0 to 65535, so the maximum period is 65.5 ms).
{n=39 v=0}The first transition will occur immediately on executing the command.
{n=39 v=0}The last period in the array is ignored other than defining the time before control returns to the program or command line.
{n=39 v=0}The pin is left in the starting state if the number of transitions is even and the opposite state if the number of transitions is odd.
{n=39 v=0}Interrupts are disabled while the sequence is generated, so everything else (sound, the USB devices, the timers) waits until it is finished.
The PicoMite's second pin, output modes and logic functions are not available.  BITBANG BITSTREAM, the older name, is still accepted.

=== CAN OPEN index, speed, mode
or
CAN OPEN index, 0, mode, prescaler, seg1, seg2, sjw
or
CAN OPEN index, 0, mode, prescaler, seg1, seg2, sjw, brs, dsize, dprescaler, dseg1, dseg2, dsjw
---
More detail is in Appendix J (CAN Support).  A CAN transceiver is needed between the pins and the CAN bus (see the chapter *Special Device Support*).
{}
Opens the CAN interface ‘index’ and allocates its pins: interface 1 uses pin 5 (CAN Rx) and pin 3 (CAN Tx), shared with the first I^^2^^C channel, and interface 2 uses pin 19 (CAN Rx) and pin 40 (CAN Tx), shared with SPI MOSI and SPI2 CLOCK.  Only one interface can be open at a time.
‘speed’ is the bit rate: 125000, 250000, 500000 or 1000000 bits per second, with the sample point at 80% and the Classical CAN frame type.
With a ‘speed’ of 0 the bit timing is given instead, from the 40MHz clock of the CAN controller: ‘prescaler’, ‘seg1’, ‘seg2’ and ‘sjw’ (the synchronisation jump width) alone for the Classical CAN frame type, or with the further six values for the CAN FD frame type: ‘brs’ is 1 for bit rate switching or 0 for none, ‘dsize’ the size of the data field (8, 12, 16, 20, 24, 32, 48 or 64 bytes) and ‘dprescaler’, ‘dseg1’, ‘dseg2’ and ‘dsjw’ the timing of the data phase.  Appendix J gives the values for the common speeds.
‘mode’ is 0 for normal operation, 1 for the internal loop back (nothing is sent to or received from the bus and the transceiver is not needed), 2 for the external loop back (as 1, but the messages are also sent to the bus) or 3 for monitoring the bus (messages are received but nothing is sent).
CAN OPEN sets the global filter to accept every message into FIFO 1 (as CAN FILTER GLOBAL 1, 1, 1, 1).  Other filters are set after CAN OPEN, then CAN START starts the interface.

=+= CAN FILTER index, eid, type, config, id1, id2
---
Sets the filter ‘index’ (0 to 20) for 11-bit identifiers (‘eid’ 0) or for 29-bit identifiers (‘eid’ 1).  The filters are tested in order of ‘index’; a message that matches none is dealt with by the global filter (below).
‘type’ is 0 for a range (the identifiers from ‘id1’ to ‘id2’), 1 for two identifiers (‘id1’ or ‘id2’), 2 for a classic filter (‘id1’ is the identifier and ‘id2’ the mask) or 3 for a range without the extended ID mask.
‘config’ is 0 to disable the filter, 1 to put a matching message in FIFO 0, 2 to put it in FIFO 1 or 3 to reject it.
‘id1’ and ‘id2’ are 0 to &H7FF for 11-bit identifiers and 0 to &H1FFFFFFF for 29-bit identifiers.
A filter can be set or changed while the interface is running.

=+= CAN FILTER GLOBAL id, eid, idr, eidr
---
Sets what happens to the messages that match no filter.  ‘id’ is for those with 11-bit identifiers and ‘eid’ for those with 29-bit identifiers: 0 accepts them into FIFO 0, 1 into FIFO 1 and 2 rejects them.  ‘idr’ and ‘eidr’ are the same for remote frames: 0 passes them to the filters, 1 rejects them.
The global filter can only be set while the interface is stopped: after CAN OPEN and before CAN START, or after CAN STOP.  CAN OPEN sets it to 1, 1, 1, 1.

=+= CAN START
or
CAN STOP
--- keep
CAN START starts the interface receiving messages and sending the messages queued by CAN SEND.  It must be given after CAN OPEN (and any filters).
CAN STOP stops it, for example to pause the reception of messages or to change the global filter.  CAN START starts it again.

=+= CAN SEND id, eid, rtr, dlc, msg, ret
or
CAN SEND id, eid, rtr, dlc, msg(), ret
---
Places a message in the next free transmit buffer and it is sent in order (there are 32 buffers).
‘id’ is the message’s identifier: 0 to &H7FF when ‘eid’ is 0 or 0 to &H1FFFFFFF (a 29-bit identifier) when ‘eid’ is 1.  ‘rtr’ is 1 for a remote frame (no data), otherwise 0.  ‘dlc’ is the number of data bytes: 0 to 8, or with CAN FD also 12, 16, 20, 24, 32, 48 or 64, and no more than the ‘dsize’ of CAN OPEN.
‘msg’ holds the data.  For Classical CAN it is an integer variable, sent from its most significant byte (with ‘dlc’ 2, &HAABB000000000000 sends &HAA then &HBB).  For CAN FD it is an integer array large enough for ‘dlc’ bytes (eg, `INTEGER msg(7)` for 64 bytes).
‘ret’ is an integer variable which is set to 0 if the message was queued or 1 if no transmit buffer was free.

=+= CAN READ fifo, id, eid, rtr, dlc, msg, fmi, ret
or
CAN READ fifo, id, eid, rtr, dlc, msg(), fmi, ret
---
Reads the next message from FIFO 0 or FIFO 1 (‘fifo’ is 0 or 1; each holds up to 32 messages).
The other arguments are integer variables (‘msg()’ an integer array with CAN FD) which are set from the message: ‘id’ its identifier, ‘eid’ 1 for a 29-bit identifier (otherwise 0), ‘rtr’ 1 for a remote frame, ‘dlc’ the number of data bytes, ‘msg’ the data (in the same order as CAN SEND, with the bytes beyond ‘dlc’ set to zero) and ‘fmi’ the number of the filter that accepted it, or 99 if it matched no filter and was accepted by the global filter.
‘ret’ is set to 0 if there was no message (the other variables are then not changed), otherwise to the number of messages that were waiting, including the one read.
Only one message is read each time and nothing interrupts the program when one arrives: the program reads them by calling CAN READ regularly (eg, in its main loop).

=+= CAN CLOSE
--- keep
Closes the CAN interface and releases the pins used for CAN Rx and CAN Tx.

=== CONTROLLER CLASSIC OPEN [channel] [, interrupt [, bitmask]]
or
CONTROLLER CLASSIC CLOSE [channel]
---
Opens a Wii Classic controller for communications.  These commands can also be written with WII in place of CONTROLLER (eg, `WII CLASSIC OPEN`).
‘channel’ is the I^^2^^C channel that the Classic is connected to: 1 or 2 on the rear I/O connector, or 3 (the default if it is not specified) for the Wii connector on the front panel.
‘interrupt’ is an optional MMBasic interrupt routine that will be triggered when a button is pressed.  ‘bitmask’ specifies which of the 15 buttons on the Wii Classic will trigger an interrupt.  The default is that they all will.  See the CLASSIC() function for which bits in the bitmask control which buttons.
The firmware checks for the existence of a controller on open and will throw an error if not found.  Once open the Classic is polled continuously in the background every 20 ms.  The I^^2^^C transfers are under interrupt control and non-blocking for the rest of the firmware.  The I^^2^^C channel is opened at 100KHz: other I^^2^^C devices can share the channel with the Classic, in which case I2C OPEN should not be used (I2C WRITE, READ and CHECK work on the channel without it).  A Nunchuk and a Classic cannot be open on the same channel.
CONTROLLER CLASSIC CLOSE will close the Classic on ‘channel’ (3 if it is omitted).
Also see the CLASSIC() function for accessing the state of the device.

=+= CONTROLLER MOUSE OPEN [channel] [, LBinterrupt] [, RBinterrupt] [, sensitivity] [, LBUpinterrupt]
or
CONTROLLER MOUSE CLOSE [channel]
---
Opens a mouse connected through the Hobbytronic USB mouse interface (see the chapter *Special Device Support*) for communications.
‘channel’ is the I^^2^^C channel that the interface is connected to: 1, 2 (the default: pins 27 and 28 on the rear I/O connector) or 3.
‘LBinterrupt’ and ‘RBinterrupt’ are optional MMBasic interrupt routines that will be triggered when the left or the right mouse button is pressed.  The interrupts trigger once on the button press and will not re-interrupt until it is released.  ‘LBUpinterrupt’ is an optional interrupt routine which is called when the left button is released.
The sensitivity of the Hobbytronic interface can be set by specifying a number between 0 and 10 for ‘sensitivity’.  0 (the default) sets it from the width of the screen; other values explicitly set the sensitivity as per the Hobbytronic documentation.
The interface is told the size of the screen (the current write page) when it is opened, so the mouse should be opened after the MODE command.  The firmware checks for the existence of the interface on open and will throw an error if not found.  This error can be trapped with the ON ERROR command.
Once open the interface is polled continuously in the background every 20 ms.  The I^^2^^C transfers are under interrupt control and non-blocking for the rest of the firmware.  The I^^2^^C channel is opened at 100KHz: other I^^2^^C devices (such as a Wii controller) can share it with the mouse, in which case I2C OPEN should not be used.
Only one mouse can be open at a time.  While a USB mouse is plugged in it is the mouse, on channel 2: CONTROLLER MOUSE OPEN 2 then only sets the interrupts, which work for the USB mouse too, and the other channels give an error.
CONTROLLER MOUSE CLOSE will close the mouse on ‘channel’ (2 if it is omitted).  Also see the MOUSE() function for accessing the state of the device.

=+= CONTROLLER MOUSE OPEN 0 [, LBinterrupt] [, RBinterrupt] [, sensitivity] [, LBUpinterrupt]
or
CONTROLLER MOUSE CLOSE 0
---
Opens a PS2 mouse for communications.
On the Generation 1 Colour Maximite 2 the mouse clock line is connected to pin 33 and the mouse data to pin 32 of the rear I/O connector.  Both lines MUST be pulled up to 5V with 4.7K resistors.  On the Generation 2 additional pins are allocated to the PS2 mouse and it is connected to the lower USB port: the pullup resistors are already fitted.
‘LBinterrupt’, ‘RBinterrupt’ and ‘LBUpinterrupt’ are optional interrupt routines as for the mouse above.
The PS2 mouse sensitivity can be set between 0 and 8.  Values of 1-4 set the resolution of the mouse to 1, 2, 4 or 8 counts/mm.  Values 5-8 do the same but in addition enable mouse scaling which gives a non-linear relationship between speed and count.  See <<https://isdaman.com/alsos/hardware/mouse/ps2interface.htm>> for more details.  NB: not all PS2 mice seem to implement these commands.
The firmware checks for the existence of a mouse on open and will throw an error if not found.  This error can be trapped with the ON ERROR command.  Once open the mouse operates under interrupt control so it has no performance impact unless the mouse is moving.
The PS2 mouse shares a hardware interrupt with pin 15, so it cannot be opened while pin 15 is a frequency, period or counting input, and pin 15 cannot be made one while the mouse is open.
CONTROLLER MOUSE CLOSE 0 will close the PS2 mouse.  Also see the MOUSE() function for accessing the state of the device.

=+= CONTROLLER NUNCHUK OPEN [channel] [, Zinterrupt [, Cinterrupt]]
or
CONTROLLER NUNCHUK CLOSE [channel]
---
Opens a Wii Nunchuk for communications.
‘channel’ is the I^^2^^C channel that the Nunchuk is connected to: 1 or 2 on the rear I/O connector, or 3 (the default if it is not specified) for the Wii connector on the front panel.
‘Zinterrupt’ and ‘Cinterrupt’ are optional MMBasic interrupt routines that will be triggered when the Z or the C button is pressed.  The interrupts trigger once on the button press and will not re-interrupt until it is released.
The firmware checks for the existence of a controller on open and will throw an error if not found.  This error can be trapped with the ON ERROR command.  If a Classic controller is plugged in instead, an error will not be thrown: you can check the ID code with NUNCHUK(T, channel).

Generate a pulse width modulated (PWM) output for driving analog circuits, sound output, etc.
There are a total of five outputs designated as PWM in the table of the external I/O connector in the chapter *Hardware Features* (they are also used for the SERVO command).  Controller 1 can have one, two or three outputs (1A on pin 12, 1B on pin 22 and 1C on pin 29) while controller 2 can have one or two outputs (2A on pin 36 and 2B on pin 31). The output will run continuously in the background while the program is running and can be stopped using the STOP command.  The frequency and duty cycle can be changed at any time (without stopping the output) by issuing a new PWM command.
The PWM function will take control of any specified outputs and when stopped the pins will be returned to a high impedance "not configured" state.

=== GPS()
--- keep
The GPS functions return data from a GPS receiver on a serial port opened with OPEN comspec$ AS GPS (an error is given if there is none).  The values are updated in the background as the receiver sends them.
The function GPS(VALID) should be checked before any of these functions are used to ensure that the returned value is valid.

=+= GPS(ALTITUDE)
--- keep
Returns the current altitude in metres (if the receiver sends the GGA sentence).

=+= GPS(DATE)
--- keep
Returns the normal date string corrected for local time, e.g. "12-01-2020".

=+= GPS(DOP)
--- keep
Returns the DOP (horizontal dilution of precision) value (if the receiver sends the GGA sentence).

=+= GPS(FIX)
--- keep
Returns the quality of the fix (if the receiver sends the GGA sentence): 0 for no fix, 1 for a GPS fix, 2 for a differential GPS fix, or another value as the receiver gives it.

=+= GPS(GEOID)
--- keep
Returns the geoid-ellipsoid separation in metres (if the receiver sends the GGA sentence).

=+= GPS(LATITUDE)
--- keep
Returns the latitude in degrees as a floating point number, values are negative for South of the equator.

=+= GPS(LONGITUDE)
--- keep
Returns the longitude in degrees as a floating point number, values are negative for West of the meridian.

=+= GPS(SATELLITES)
--- keep
Returns the number of satellites in use (if the receiver sends the GGA sentence).

=+= GPS(SPEED)
--- keep
Returns the ground speed in knots as a floating point number.

=+= GPS(TIME)
--- keep
Returns the normal time string corrected for local time, e.g. "12:09:33".

=+= GPS(TRACK)
--- keep
Returns the track over the ground (degrees true) as a floating point number.

=+= GPS(VALID)
--- keep
Returns 0 for invalid data and 1 for valid data.  It returns 0 when nothing has been received from the receiver for two seconds.
