# Commands: the reference entries (tools/manual/reftext.py)

===  ‘ (single quotation mark)
--- keep
Starts a comment and any text following it will be ignored.  Comments can be placed anywhere on a line.

=== \*[file] [cmdline]
--- keep
{t=l2005}The star/asterisk command is a shortcut for RUN that may only be used at the MMBasic prompt. eg,
{t=l1863} \*	RUN 
{t=l1863} \* -f	RUN -f
{t=l1863} \*foo	RUN "foo" 
{t=l1863} \*foo --wombat	RUN "foo", --wombat
{t=l1863} \*foo "wom"	RUN "foo", "wom"
{t=l1863} \*"foo bar" -x	RUN "foo bar", -x
The file name ends at the first space, or it is given in quotes, which allows a name with spaces.  Anything after the name is passed to the program as its command line (MM.CMDLINE$) exactly as it was typed: it is not evaluated.  See the RUN command.

===  ? (question mark)
--- keep
Shortcut for the PRINT command.

=== /\*
{b=0 a=0}\*/
--- keep
{b=0 a=0}Start and end of multi-line comments.  /\* and \*/ must be the first non-space characters on a line.  When the program is loaded (by RUN, or by F1 or F2 in the editor or AUTOSAVE) the lines from the one starting with /\* to the one starting with \*/ are dropped, so they take no memory and can be used anywhere in a program or an #INCLUDE file, inside subroutines and functions too (but not at the command prompt).  Any characters after /\* or \*/ on these lines are also treated as a comment, and a line that starts with /\* and also contains \*/ is a comment on its own.  A /\* without a matching \*/ gives the error "No matching \*/".  See also #COMMENT.

=== \#COMMENT START
or
\#COMMENT END
--- keep
Directives for multi-line comments.  When the program is loaded (by RUN, or by F1 or F2 in the editor or AUTOSAVE) the lines between #COMMENT START and #COMMENT END are dropped: they are not loaded into program memory, and a directive among them (an #INCLUDE or a #DEFINE) has no effect.  The directives must be the first non-space characters on their lines.  They can also be used in an #INCLUDE file.  See also /\* and \*/.

=== \#DEFINE "before", "after"
--- keep
This directive causes the text "before" to be replaced by the text "after" in the lines of the program that follow it, when the program is loaded (by RUN, or by F1 or F2 in the editor or AUTOSAVE).  Both parameters must be quoted strings.  Only whole words are replaced (#DEFINE "N", "M" does not change the N in PRINT), case is ignored, and quoted strings and comments in the program are not changed.  The replacements are also made in the #INCLUDE files that follow.
The #DEFINEs are applied in the reverse order of their creation, so a symbol can be redefined and from that point on in the program the new definition will be active.
The program can have up to 256 #DEFINE directives ("Too many #DEFINE statements").  A line that the replacements make longer than 255 characters gives the error "Line n is too long".

=== \#INCLUDE file$
--- keep
This directive inserts the file ‘file$’ into the program at that point when the program is loaded (by RUN, or by F1 or F2 in the editor or AUTOSAVE).  ‘file$’ is a quoted string; ".INC" is added if it has no extension, and the file must have the extension .INC.  Unless ‘file$’ starts with a drive or a / it is looked for relative to the directory holding the program, not the current directory, so CHDIR in the program does not affect it.  It can be on the SD card or the USB flash drive.
This acts exactly as if the included file was inserted into the code with an editor, but it is more convenient for libraries and other code that several programs share (see also LIBRARY).  An included file cannot have an #INCLUDE of its own ("Can't import from an import"); #DEFINE, #COMMENT, #MMDEBUG and /\* \*/ work in it.
The program is loaded from its file each time it is run, so a change to an included file takes effect at the next RUN.  Errors in an included file are reported with the file's name and the line number in it.

=== \#MMDEBUG ON
or
\#MMDEBUG OFF
--- keep
Directives for the program loader, which can appear anywhere in the program.  While #MMDEBUG is OFF (the default at the start of the program) the lines that start with the command MMDEBUG are dropped when the program is loaded, as comments are, so they cost nothing in the program's size or speed.  After #MMDEBUG ON they are kept.  An #INCLUDE file starts with the setting in force at its #INCLUDE.  See the MMDEBUG command.

=== A: , B: or C:
--- keep
Shortcut for DRIVE “A:” ,DRIVE “B:” or DRIVE “C:” at the command prompt

=== ADC OPEN freq, pin1 [, pin2] [, pin3] [, interrupt]
---
The ADC commands capture up to three channels of analog data in the background into arrays, at up to 500KHz per channel (480KHz on a 400MHz processor), with an optional trigger.  See also the chapter *Using the I/O Pins*.
{}
ADC OPEN opens the channels.  ‘freq’ is the sampling frequency in Hz.  The number of bits in each conversion follows from it and is applied automatically:
{n=39 v=0}Above 160KHz the conversion is 8 bits per channel
{n=39 v=0}From 40KHz to 160KHz it is 10 bits
{n=39 v=0}From 20KHz to 40KHz it is 12 bits
{n=39 v=0}From 10KHz to 20KHz it is 14 bits
{n=39 v=0}Below 10KHz it is 16 bits
Each channel has its own converter.  ‘pin1’, the first channel, can be one of the pins 7, 10, 16, 22, 24 or 37, ‘pin2’ (the second) one of 8, 12, 26 or 29 and ‘pin3’ (the third) 13 or 15.  The pins are reserved for the ADC until ADC CLOSE.
‘interrupt’ is a normal MMBasic subroutine that will be called when the conversion completes.  It is always the fifth argument, so the arguments of unused channels are left empty, for example:  `ADC OPEN 100000, 7, , , Done`

=+= ADC FREQUENCY freq
--- keep
Changes the sampling frequency without closing and opening the ADC.  The new frequency is used by the next ADC START (it does not change a capture already running).
This command is only valid if the number of bits given by the table above does not change; otherwise use ADC CLOSE and ADC OPEN.

=+= ADC TRIGGER channel, level [, timeout]
---
Sets up triggering of the ADC.  This is given after ADC OPEN and before the ADC START command.
The ‘channel’ can be a number between one and three depending on the number of pins specified in the ADC OPEN command.
The ‘level’ can be between -VCC and VCC (VCC is OPTION VCC, normally 3.3).  A positive number indicates that the trigger will be on a positive going transition through the specified voltage.  A negative number indicates a negative going transition through the specified voltage (without its sign).
‘timeout’ is the number of ADC samples to take before abandoning the wait for the trigger condition and starting the capture anyway.  Setting a value equal to the frequency of the sampling would give a timeout of 1 second.  If it is 0 or omitted the ADC waits for ever.
The trigger applies to every ADC START until the ADC is closed.

=+= ADC START array1!() [, array2!()] [, array3!()] [, C1min, C1max] [, C2min, C2max] [, C3min, C3max]
---
This starts conversion into the specified arrays, one for each channel opened (in the order of their pins in ADC OPEN).  The arrays must be floating point and the same size.  The size of the arrays defines the number of conversions.  Start can be called repeatedly once the ADC is OPEN.
‘C`x`min’ and ‘C`x`max’ will scale the readings of channel `x`.  For example, C1min=200 and C1max=100 will create values ranging from 200 to 100 for equivalent voltages of 0 - 3.3.  If the scaling is not used the results are returned as a voltage between 0 and OPTION VCC (defaults to 3.3V).  The scaling values are always the fourth to the ninth arguments, so the arguments of the arrays not used are left empty, for example:  `ADC START a!(), , , 0, 100`
If ADC OPEN did not specify an interrupt the command waits until the arrays are filled.  If it did, the command returns at once and the interrupt is called when they are full: the arrays must then be global (or STATIC), not LOCAL, as they are filled after the command has returned.

=+= ADC CLOSE
--- keep
Closes the ADC and returns the pins to normal use.

=== {b=0 a=0}ARRAY ADD in(), value ,out()
{}
--- keep
{a=0}This adds (or appends for strings) the value 'value' to every element of the matrix in() and puts the answer in out(). Works for arrays of any dimensionality of strings and both integer and float (can convert between integer and float). Setting ‘value’ to 0 or “” is optimised and is a fast way of copying an entire array. in() and out() can be the same array.
{b=0}

=== {b=0 a=0}ARRAY INSERT targetarray(), [d1] [,d2] [,d3] [,d4] [,d5] , sourcearray()
{b=0 a=0}
{}
--- keep
{b=0 a=0}This is the opposite of ARRAY SLICE, has a very similar syntax, and allows you, for example,  to substitute a single vector into an array of vectors with a single instruction or a one dimensional array of strings into a two dimensional array of strings.  The arrays can be numerical or strings and ‘sourcearray’ and ‘targetarray’ must be the same (NB: can convert between integers and floats for numerical arrays).  String arrays must have the same LENGTH.
{b=0 a=0}
{b=0 a=0}eg,
{b=0 a=0}`  OPTION BASE 1\n  DIM targetarray(3,4,5)\n  DIM sourcearray(4)=(1,2,3,4)\n  ARRAY INSERT targetarray(), 2, , 3, sourcearray()`
{b=0 a=0}Will set elements 2,1,3 = 1 and 2,2,3 = 2 and 2,3,3 = 3 and 2,4,3 = 4

=== {b=0 a=0}ARRAY SET value, array()
{}
--- keep
{b=0 a=0}Sets all elements in array() to the value ‘value’. Value can be a number or a string and ‘array’ must be the same (NB: can convert between integers and floats). Note this is the fastest way of clearing an array by setting it to zero or an empty string.

=== {b=0 a=0}ARRAY SLICE sourcearray(), [d1] [,d2] [,d3] [,d4] [,d5] , destinationarray()
{}
--- keep
{b=0 a=0}This command copies a specified set of values from a multi-dimensional array into a single dimensional array. It is much faster than using a FOR loop. The slice is specified by giving a value for all but one of the source array indices and there should be as many indices in the command, including the blank one, as there are dimensions in the source array. The arrays can be numerical or strings and ‘sourcearray’ and ‘destinationarray’ must be the same (NB: can convert between integers and floats for numerical arrays).  String arrays must have the same LENGTH.
{b=0 a=0}eg,
{b=0 a=0}`  OPTION BASE 1`
{b=0 a=0}`  DIM a(3,4,5)\n  DIM b(4)\n  ARRAY SLICE a(), 2, , 3, b()`
{b=0}Will copy the elements 2,1,3 and 2,2,3 and 2,3,3 and 2,4,3 into array b()

=== ARC x, y, r1, [r2], a1, a2 [, c]
--- keep
{b=0}Draws an arc of a circle with a given colour and width between two radials (defined in degrees). Parameters for the ARC command are:
{b=0 a=0}x:	X coordinate of centre of arc
{b=0 a=0}y: 	Y coordinate of centre of arc
{b=0 a=0}r1: 	inner radius of arc
{b=0 a=0}r2: 	outer radius of arc - can be omitted if 1 pixel wide
{b=0 a=0}a1: 	start angle of arc in degrees
{b=0 a=0}a2: 	end angle of arc in degrees
{b=0 a=0}c: 	Colour of arc (if omitted it will default to the foreground colour)
{b=0}Zero degrees is at the 12 o'clock position.

=== ASTRO body alt, az [, ra, dec]
or
ASTRO alt, az, ra2000, dec2000 [, pm_ra, pm_dec] [, ra, dec]
--- keep
Gives the position of the Sun, the Moon, a planet, a star or galaxy of the catalogue, or any object from its J2000 coordinates, at the time and place set by LOCATION: its altitude and azimuth, and its right ascension and declination if 'ra' and 'dec' are given.  See Appendix Q.

=== AUTOSAVE file$
or
AUTOSAVE N file$
or
AUTOSAVE APPEND [N] file$
--- keep
Enters automatic program entry mode: the lines of text sent to the console are saved to the file ‘file$’ on the SD card or USB flash drive (".BAS" is added if it has no extension).  This is one way of transferring a BASIC program from a computer: the program is pasted into a terminal emulator and this command captures the text.  It can also be used for typing a small program at the console.  The text is echoed back as it arrives, and a tab becomes a space.
The mode is ended with a function key:
{l=720}F1 saves the file and, if it is a .BAS file, loads it into program memory, where it becomes the current program (used by RUN, LIST and EDIT without a file name)
{l=720}F2 does the same and then runs the program
{l=720}F6 saves the file without loading it
At any time Control-C abandons the command and nothing is saved.  The text is held in memory until it is saved, up to 512KB: a longer text stops the command with the error "Not enough memory".
AUTOSAVE N does not echo the text.  After the first character, when there is a pause of more than 100 milliseconds between characters it shows the message "Enter F1 ,F2 or F6 to exit" and echoes what follows.
AUTOSAVE APPEND adds the text to the end of the file instead of replacing it, so that a program can be sent in parts; a file whose last line has no line ending is given one first, and the file is made if there is none.  N may follow APPEND.
The command can only be used at the command prompt.

=== BEZIER x%(), y%() [,n] [,colour]
--- keep
Draws a Bezier curve with up to 16 control points.  ‘x%()’ and ‘y%()’ are single dimension integer arrays holding the coordinates of the control points; they must have the same number of elements.  The curve starts at the first control point and ends at the last one used.
The optional parameter ‘n’ defines how many control points to use for the plot (the first ‘n’ elements of the arrays).  If omitted the size of the arrays determines the number.  ‘n’ must be from 2 to the array size, and no more than 16.
The optional parameter ‘colour’ defines the colour to plot the curve (defaults to the current foreground colour).

=== BITSTREAM pin, n, array() [, mode]
or
BITSTREAM pin1, n1, array1(), mode1, pin2, n2, array2() [, mode2 [, logic]]
---
This command is used to generate an extremely accurate bit sequence on the pin specified.  A pin that has been set up must be an output (SETPIN pin, DOUT, with or without OC), set to the required starting level; one that has not is made an output.
‘n’ is the number of transitions (1 to 250000) and ‘array()’ is a numeric array (integer or floating point) with at least ‘n’ elements.
‘mode’ is 0 (the default) for a normal output or 1 for an open collector one: the pin is made an open drain output with its pullup, released (high) at the start and then driven low or let go at each transition.  In mode 1 ‘n’ must be even, so that the pin ends released.
Notes:
{n=39 v=0}The array contains the length of each level in the bitstream in microseconds (0 to 65535, so the maximum period is 65.5 ms).
{n=39 v=0}In mode 0 the first transition will occur immediately on executing the command, and the last period in the array is ignored other than defining the time before control returns to the program or command line.  In mode 1 each period comes before its transition: the first transition comes after the first period and the command returns at the last.
{n=39 v=0}The pin is left in the starting state if the number of transitions is even and the opposite state if the number of transitions is odd.
{n=39 v=0}Interrupts are disabled while the sequence is generated, so everything else (sound, the USB devices, the timers) waits until it is finished.
The second form, the PicoMite's, generates two sequences at once, each pin changing at its own times, with each period coming before its transition as in mode 1.  ‘mode1’ can be left empty (0).  When ‘pin1’ and ‘pin2’ are the same pin, ‘logic’ sets how the levels of the two sequences, each starting low (high in mode 1), give its level: 0 (the default) exclusive OR, so that a transition in either changes it, 1 AND and 2 OR.  ‘logic’ cannot be used with two different pins.
BITBANG BITSTREAM, the older name, and DEVICE BITSTREAM, the PicoMite's, are still accepted.

=== BLIT READ [#]b, x, y, w, h [,page]
or
BLIT WRITE [#]b, x, y [,orientation]
or
BLIT LOAD[BMP] [#]b, fname$ [,x] [,y] [,w] [,h]
or
BLIT CLOSE [#]b
---
Copy one section of the display screen to or from a memory buffer.
BLIT READ will copy a portion of the display to the memory buffer ‘#b’.  The source coordinate is ‘x’ and ‘y’ and the width of the display area to copy is ‘w’ and the height is ‘h’.  When this command is used the memory buffer is automatically created and sufficient memory allocated.  If the buffer is already in use and the new area has the same width and height the new area overwrites the stored one (a different size is an error).  The optional ‘page’ specifies which page is to be read; the default is the current write page.  Set ‘page’ to FRAMEBUFFER to read from the framebuffer (see the FRAMEBUFFER command).
BLIT WRITE will copy the memory buffer ‘#b’ to the current write page.  The destination coordinate is ‘x’ and ‘y’ using the width and height of the buffer.  The optional ‘orientation’ parameter (0 to 7) defaults to 0, every pixel copied, and specifies how the stored image data is changed as it is written out.  It is the sum of the following values:
{l=720}&B001 = mirrored left to right
{l=720}&B010 = mirrored top to bottom
{l=720}&B100 = don't copy transparent pixels
BLIT LOAD, or BLIT LOADBMP, loads the BMP file ‘fname$’ into the buffer ‘#b’, as SPRITE LOADBMP does (see there for ‘x’, ‘y’, ‘w’ and ‘h’).
BLIT CLOSE will close the memory buffer ‘#b’ to allow it to be used for another BLIT READ operation and recover the memory used.
Notes:
{n=39 v=0}Sixty four buffers are available ranging from #1 to #64.  They are the sprites: BLIT and SPRITE are the same command, so a buffer read with BLIT READ can be shown with SPRITE SHOW and every SPRITE command can also be written as BLIT (see SPRITE).
{n=39 v=0}Two commands differ with the name used, as the PicoMite's separate BLIT and SPRITE commands do: BLIT WRITE copies every pixel unless its ‘orientation’ says otherwise, where SPRITE WRITE leaves out the transparent ones, and BLIT LOAD loads a BMP file, where SPRITE LOAD loads a sprite file.
{n=39 v=0}When specifying the buffer number the # symbol is optional.
{n=39 v=0}All other arguments are in pixels.
{n=39 v=0}A buffer's transparent pixels are those that the colour depth shows as the transparent colour: black, unless SPRITE SET TRANSPARENT has chosen another (see SPRITE).

=+= BLIT x1, y1, x2, y2, w, h [,page] [,orientation]
---
Copy one section of the display screen to another part of the display.
The source coordinate is ‘x1’ and ‘y1’.  The destination coordinate is ‘x2’ and ‘y2’.  The width of the screen area to copy is ‘w’ and the height is ‘h’.
‘page’ is the page number that the image data is read from; it is then written to the current write page as specified by the PAGE WRITE command.  If ‘page’ is omitted the data is read from the write page.  Set ‘page’ to FRAMEBUFFER to read from the framebuffer (see the FRAMEBUFFER command).
All arguments are in pixels and the source and destination can overlap.  The area is clipped to the source and destination pages.
The optional ‘orientation’ parameter (0 to 7, default 0) specifies how the section of the screen is changed as it is copied.  It is the sum of the following values:
{l=720}&B001 = mirrored left to right
{l=720}&B010 = mirrored top to bottom
{l=720}&B100 = don't copy transparent pixels: here those whose stored value is zero, black in the 4, 8 and 16-bit colour depths, and the colour 0 (black with a transparency of 0, which RGB(0,0,0) is not) in the 12 and 32-bit colour depths

=+= BLIT FRAMEBUFFER from, to, xin, yin, xout, yout, width, height [,colour]
---
__IN THE 4-BIT COLOUR DEPTH ONLY__ Copies an area of the framebuffer ‘from’ to the framebuffer ‘to’, as on the PicoMite.  ‘from’ and ‘to’ are each N, L, F, 2 or T (a framebuffer that has not been created is N, the display: see the FRAMEBUFFER command) and must be different.
‘xin’ and ‘yin’ define the top left of the area of ‘width’ and ‘height’ on the source framebuffer to be copied, which must be within it.  ‘xout’ and ‘yout’ define the top left of the area on the target framebuffer to receive the copy; the copy is clipped to the target.
The optional parameter ‘colour’ defines a pixel colour on the source which will not be copied.  If omitted (or -1) all pixels are copied.  The colour is specified as a number between 0 and 15 representing:\nBlack, Blue, Myrtle, Cobalt, Midgreen, Cerulean, Green, Cyan, Red, Magenta, Rust, Fuchsia, Brown, Lilac, Yellow and White

=+= BLIT FLASH n, to, xin, yin, xout, yout, width, height [,colour]
---
Copies an area of the image held in image slot ‘n’ to a framebuffer or a page, as the PicoMite's BLIT FLASH does.  ‘n’ is 1 to 8: the image slots are loaded with FLASH LOAD IMAGE (see Image Slots in the chapter Video Modes and Pages).
‘to’ is a framebuffer N, L, F, 2 or T, or a page number.  In a 4 or 1-bit mode a framebuffer that has not been created is N (but 2 is then an error); in the other colour depths N, L, F, 2 and T are the pages 0, 1, 2, 3 and 4.  In the 1-bit colour depth a pixel of the image that is not black is set.
‘xin’ and ‘yin’ define the top left of the area of ‘width’ and ‘height’ on the image to be copied, which must be within the image.  ‘xout’ and ‘yout’ define the top left of the area on the target to receive the copy; the copy is clipped to the target.
The image's pixels are the PicoMite's 16 colours, drawn in the colour depth of the target.  The optional parameter ‘colour’ defines a pixel colour in the image which will not be copied.  If omitted (or -1) all pixels are copied.  The colour is specified as a number between 0 and 15 representing:\nBlack, Blue, Myrtle, Cobalt, Midgreen, Cerulean, Green, Cyan, Red, Magenta, Rust, Fuchsia, Brown, Lilac, Yellow and White

=+= BLIT MEMORY address, x, y [,colour]
---
Draws an image held in memory as a packed array of colour nibbles on the current write page, with its top left at ‘x’, ‘y’; the image is clipped to the screen.  Each nibble is one of the PicoMite's 16 colours, a number between 0 and 15 representing:\nBlack, Blue, Myrtle, Cobalt, Midgreen, Cerulean, Green, Cyan, Red, Magenta, Rust, Fuchsia, Brown, Lilac, Yellow and White
The first word of the area of memory starting at ‘address’ must contain the width and height of the image as 16-bit integers with the width as the bottom 16 bits.  The pixels follow, two to a byte with the left pixel in the low nibble, each row following on from the one before.
If the optional parameter ‘colour’ is specified then pixels of that colour are not drawn (-1 draws them all).
If the top bit of either the width or height is set to 1 then the colour data is treated as compressed (the remaining 15 bits are used as the width and/or height).  The compression algorithm is simple: each byte contains a count in the bottom nibble (1-15) and a colour in the top nibble (0-15).  In the event that more than 15 pixels are the same colour additional bytes are used for that colour.

=+= BLIT COMPRESSED address, x, y [,colour]
---
As BLIT MEMORY, but the colour data is always treated as compressed, whatever the top bits of the width and height.  This is the PicoMite's form for compressed data whose width and height have no flag.

=== BOX x, y, w, h [,lw] [,c] [,fill]
--- keep
Draws a box on the screen with the top left hand corner at ‘x’ and ‘y’ with a width of ‘w’ pixels and a height of ‘h’ pixels.
‘lw’ is the width of the sides of the box and can be zero (0 to 100).  It defaults to 1.
‘c’ is the colour and defaults to the default foreground colour if not specified.  ‘fill’ is the fill colour.  It can be omitted or set to -1 in which case the box will not be filled.
All parameters can be expressed as arrays and the software will plot the number of boxes as determined by the dimensions of the smallest array.  ‘x’ and ‘y’ must both be arrays or both be single variables/constants otherwise an error will be generated.  ‘w’, ‘h’, ‘lw’, ‘c’ and ‘fill’ can be either arrays or single variables/constants (a single value is used for every box).
See the chapter *Graphics Functions* for a definition of the colours and graphics coordinates.

=+= BOX AND_PIXELS x, y, w, h, colour [,page]
or
BOX OR_PIXELS x, y, w, h, colour [,page]
or
BOX XOR_PIXELS x, y, w, h, colour [,page]
--- keep
Executes the requested logical operation (AND, OR or exclusive OR) between each pixel in the area with its top left at ‘x’, ‘y’, ‘w’ pixels wide and ‘h’ pixels high, and the colour ‘colour’ (in the pixel format of the colour depth), and writes the result to the same area of the current write page.  The pixels are read from page ‘page’ (the write page if it is omitted; FRAMEBUFFER for the framebuffer).  The area is clipped to the page.  They are not available in the 4 and 1-bit colour depths ("Invalid for this screen mode").
In the 12-bit colour depth the operation includes the pixels' transparency, which RGB() sets to 15 (solid): eg, XOR_PIXELS with RGB(255,255,255) also makes the solid pixels transparent, and with &HFFFFFF changes only their colour.

=== BYTE(var$, byteno)=value
--- keep
Sets a specific byte in a string to an integer value. ‘value’ can be in the range 0-255. The byteno can be between 1 and the current length of the string variable. This is the equivalent of MID$(var$,byteno,1)=CHR$(value) but executes much faster.
See also the BYTE function.

=== CALL usersubname$ [,usersubparameters,..]
--- keep
This is an efficient way of programmatically calling user defined subroutines (see also the CALL() function). In many cases it can allow you to get rid of complex SELECT and IF THEN ELSEIF ENDIF clauses and is processed in a much more efficient way. 
The “usersubname$” can be any string or variable or function that resolves to the name of a normal user subroutine (not an in-built command).  The “usersubparameters” are the same parameters that would be used to call the subroutine directly.  A typical use could be writing any sort of emulator where one of a large number of subroutines should be called depending on some variable.  It also allows a way of passing a subroutine name to another subroutine or function as a variable.

=== CAN OPEN index, speed, mode
or
CAN OPEN index, 0, mode, prescaler, seg1, seg2, sjw
or
CAN OPEN index, 0, mode, prescaler, seg1, seg2, sjw, brs, dsize, dprescaler, dseg1, dseg2, dsjw
---
More detail is in Appendix J (CAN Support).  A CAN transceiver is needed between the pins and the CAN bus (see the chapter *Special Device Support*).
{}
Opens the CAN interface ‘index’ and allocates its pins: interface 1 uses pin 5 (CAN Rx) and pin 3 (CAN Tx), shared with the first I^^2^^C channel, and interface 2 uses pin 19 (CAN Rx) and pin 40 (CAN Tx), shared with SPI MOSI and SPI2 CLOCK.  Only one interface can be open at a time.
‘speed’ is the bit rate: 125000, 250000, 500000 or 1000000 bits per second, with the sample point at 80% and the Classical CAN frame type.
With a ‘speed’ of 0 the bit timing is given instead, from the 40MHz clock of the CAN controller: ‘prescaler’, ‘seg1’, ‘seg2’ and ‘sjw’ (the synchronisation jump width) alone for the Classical CAN frame type, or with the further six values for the CAN FD frame type: ‘brs’ is 1 for bit rate switching or 0 for none, ‘dsize’ the size of the data field (8, 12, 16, 20, 24, 32, 48 or 64 bytes) and ‘dprescaler’, ‘dseg1’, ‘dseg2’ and ‘dsjw’ the timing of the data phase.  Appendix J gives the values for the common speeds.
‘mode’ is 0 for normal operation, 1 for the internal loop back (nothing is sent to or received from the bus and the transceiver is not needed), 2 for the external loop back (as 1, but the messages are also sent to the bus) or 3 for monitoring the bus (messages are received but nothing is sent).
CAN OPEN sets the global filter to accept every message into FIFO 1 (as CAN FILTER GLOBAL 1, 1, 1, 1).  Other filters are set after CAN OPEN, then CAN START starts the interface.

=+= CAN FILTER index, eid, type, config, id1, id2
---
Sets the filter ‘index’ (0 to 31) for 11-bit identifiers (‘eid’ 0) or for 29-bit identifiers (‘eid’ 1).  The filters are tested in order of ‘index’; a message that matches none is dealt with by the global filter (below).
‘type’ is 0 for a range (the identifiers from ‘id1’ to ‘id2’), 1 for two identifiers (‘id1’ or ‘id2’), 2 for a classic filter (‘id1’ is the identifier and ‘id2’ the mask) or 3 for a range without the extended ID mask.
‘config’ is 0 to disable the filter, 1 to put a matching message in FIFO 0, 2 to put it in FIFO 1 or 3 to reject it.
‘id1’ and ‘id2’ are 0 to &H7FF for 11-bit identifiers and 0 to &H1FFFFFFF for 29-bit identifiers.
A filter can be set or changed while the interface is running.

=+= CAN FILTER GLOBAL id, eid, idr, eidr
---
Sets what happens to the messages that match no filter.  ‘id’ is for those with 11-bit identifiers and ‘eid’ for those with 29-bit identifiers: 0 accepts them into FIFO 0, 1 into FIFO 1 and 2 rejects them.  ‘idr’ and ‘eidr’ are the same for remote frames: 0 passes them to the filters, 1 rejects them.
The global filter can only be set while the interface is stopped: after CAN OPEN and before CAN START, or after CAN STOP.  CAN OPEN sets it to 1, 1, 1, 1.

=+= CAN START
or
CAN STOP
--- keep
CAN START starts the interface receiving messages and sending the messages queued by CAN SEND.  It must be given after CAN OPEN (and any filters).
CAN STOP stops it, for example to pause the reception of messages or to change the global filter.  CAN START starts it again.

=+= CAN SEND id, eid, rtr, dlc, msg, ret
or
CAN SEND id, eid, rtr, dlc, msg(), ret
---
Places a message in the next free transmit buffer and it is sent in order (there are 32 buffers).
‘id’ is the message’s identifier: 0 to &H7FF when ‘eid’ is 0 or 0 to &H1FFFFFFF (a 29-bit identifier) when ‘eid’ is 1.  ‘rtr’ is 1 for a remote frame (no data), otherwise 0.  ‘dlc’ is the number of data bytes: 0 to 8, or with CAN FD also 12, 16, 20, 24, 32, 48 or 64, and no more than the ‘dsize’ of CAN OPEN.
‘msg’ holds the data.  For Classical CAN it is an integer variable, sent from its most significant byte (with ‘dlc’ 2, &HAABB000000000000 sends &HAA then &HBB).  For CAN FD it is an integer array large enough for ‘dlc’ bytes (eg, `INTEGER msg(7)` for 64 bytes).
‘ret’ is an integer variable which is set to 0 if the message was queued or 1 if no transmit buffer was free.

=+= CAN READ fifo, id, eid, rtr, dlc, msg, fmi, ret
or
CAN READ fifo, id, eid, rtr, dlc, msg(), fmi, ret
---
Reads the next message from FIFO 0 or FIFO 1 (‘fifo’ is 0 or 1; each holds up to 32 messages).
The other arguments are integer variables (‘msg()’ an integer array with CAN FD) which are set from the message: ‘id’ its identifier, ‘eid’ 1 for a 29-bit identifier (otherwise 0), ‘rtr’ 1 for a remote frame, ‘dlc’ the number of data bytes, ‘msg’ the data (in the same order as CAN SEND, with the bytes beyond ‘dlc’ set to zero) and ‘fmi’ the number of the filter that accepted it, or 99 if it matched no filter and was accepted by the global filter.
‘ret’ is set to 0 if there was no message (the other variables are then not changed), otherwise to the number of messages that were waiting, including the one read.
Only one message is read each time and nothing interrupts the program when one arrives: the program reads them by calling CAN READ regularly (eg, in its main loop).

=+= CAN CLOSE
--- keep

=== CAT S$, N$
--- keep

=== CHAIN file$ [, cmdline$]
--- keep
Runs another program, keeping the global variables (and constants) with their values.  The program in ‘file$’ is loaded and run as by RUN, but the global variables of the program that used CHAIN stay, so a program too large for program memory can be split into parts that pass their data on.  ‘file$’ and ‘cmdline$’ are string expressions; ".BAS" is added to ‘file$’ if it has no extension.  ‘cmdline$’ is passed to the new program as MM.CMDLINE$.

=== CONTROLLER CLASSIC OPEN [channel] [, interrupt [, bitmask]]
or
CONTROLLER CLASSIC CLOSE [channel]
---
Opens a Wii Classic controller for communications.  These commands can also be written with WII in place of CONTROLLER (eg, `WII CLASSIC OPEN`).
‘channel’ is the I^^2^^C channel that the Classic is connected to: 1 or 2 on the rear I/O connector, or 3 (the default if it is not specified) for the Wii connector on the front panel.
‘interrupt’ is an optional MMBasic interrupt routine that will be triggered when a button is pressed.  ‘bitmask’ specifies which of the 15 buttons on the Wii Classic will trigger an interrupt.  The default is that they all will.  See the CLASSIC() function for which bits in the bitmask control which buttons.
The PicoMite's forms are accepted too: WII OPEN [interrupt [, bitmask]] and WII CLOSE (or DEVICE WII OPEN and DEVICE WII CLOSE, see DEVICE) open and close a Classic on the Wii connector, channel 3.
The firmware checks for the existence of a controller on open and will throw an error if not found.  Once open the Classic is polled continuously in the background every 20 ms.  The I^^2^^C transfers are under interrupt control and non-blocking for the rest of the firmware.  The I^^2^^C channel is opened at 100KHz: other I^^2^^C devices can share the channel with the Classic, in which case I2C OPEN should not be used (I2C WRITE, READ and CHECK work on the channel without it).  A Nunchuk and a Classic cannot be open on the same channel.
CONTROLLER CLASSIC CLOSE will close the Classic on ‘channel’ (3 if it is omitted).
Also see the CLASSIC() function for accessing the state of the device.

=+= CONTROLLER MOUSE OPEN [channel] [, LBinterrupt] [, RBinterrupt] [, sensitivity] [, LBUpinterrupt]
or
CONTROLLER MOUSE CLOSE [channel]
---
Opens a mouse connected through the Hobbytronic USB mouse interface (see the chapter *Special Device Support*) for communications.  The latest board, the G2 V2.0, does not support the Hobbytronic interface, and Hobbytronics no longer appears to be trading.
‘channel’ is the I^^2^^C channel that the interface is connected to: 1, 2 (the default: pins 27 and 28 on the rear I/O connector) or 3.
‘LBinterrupt’ and ‘RBinterrupt’ are optional MMBasic interrupt routines that will be triggered when the left or the right mouse button is pressed.  The interrupts trigger once on the button press and will not re-interrupt until it is released.  ‘LBUpinterrupt’ is an optional interrupt routine which is called when the left button is released.
The sensitivity of the Hobbytronic interface can be set by specifying a number between 0 and 10 for ‘sensitivity’.  0 (the default) sets it from the width of the screen; other values explicitly set the sensitivity as per the Hobbytronic documentation.
The interface is told the size of the screen (the current write page) when it is opened, so the mouse should be opened after the MODE command.  The firmware checks for the existence of the interface on open and will throw an error if not found.  This error can be trapped with the ON ERROR command.
Once open the interface is polled continuously in the background every 20 ms.  The I^^2^^C transfers are under interrupt control and non-blocking for the rest of the firmware.  The I^^2^^C channel is opened at 100KHz: other I^^2^^C devices (such as a Wii controller) can share it with the mouse, in which case I2C OPEN should not be used.
Only one mouse can be open at a time.  While a USB mouse is plugged in it is the mouse, on channel 2: CONTROLLER MOUSE OPEN 2 then only sets the interrupts, which work for the USB mouse too, and the other channels give an error.
CONTROLLER MOUSE CLOSE will close the mouse on ‘channel’ (2 if it is omitted).  Also see the MOUSE() function for accessing the state of the device.

=+= CONTROLLER MOUSE OPEN 0 [, LBinterrupt] [, RBinterrupt] [, sensitivity] [, LBUpinterrupt]
or
CONTROLLER MOUSE CLOSE 0
---
Opens a PS2 mouse for communications.
With OPTION MOUSE 0 the PS2 mouse is already running, as a USB mouse is: it is started when the computer starts, or when a mouse is first needed.  CONTROLLER MOUSE OPEN 0 then only sets the interrupts (the sensitivity is OPTION MOUSE's), and CONTROLLER MOUSE CLOSE 0 removes them, the mouse running on.
On the Generation 1 Colour Maximite 2 the mouse clock line is connected to pin 33 and the mouse data to pin 32 of the rear I/O connector.  Both lines MUST be pulled up to 5V with 4.7K resistors.  On the Generation 2 additional pins are allocated to the PS2 mouse and it is connected to the lower USB port: the pullup resistors are already fitted.  The recommended mouse is the Microsoft Basic Optical Mouse v2.0, used in PS2 mode.
‘LBinterrupt’, ‘RBinterrupt’ and ‘LBUpinterrupt’ are optional interrupt routines as for the mouse above.
The PS2 mouse sensitivity can be set between 0 and 8.  Values of 1-4 set the resolution of the mouse to 1, 2, 4 or 8 counts/mm.  Values 5-8 do the same but in addition enable mouse scaling which gives a non-linear relationship between speed and count.  See <<https://isdaman.com/alsos/hardware/mouse/ps2interface.htm>> for more details.  NB: not all PS2 mice seem to implement these commands.
The firmware checks for the existence of a mouse on open and will throw an error if not found.  This error can be trapped with the ON ERROR command.  Once open the mouse operates under interrupt control so it has no performance impact unless the mouse is moving.
The PS2 mouse shares a hardware interrupt with pin 15, so it cannot be opened while pin 15 is a frequency, period or counting input, and pin 15 cannot be made one while the mouse is open.
CONTROLLER MOUSE CLOSE 0 will close the PS2 mouse (with OPTION MOUSE 0, only remove its interrupts).  Also see the MOUSE() function for accessing the state of the device.

=+= CONTROLLER NUNCHUK OPEN [channel] [, Zinterrupt [, Cinterrupt]]
or
CONTROLLER NUNCHUK CLOSE [channel]
---
Opens a Wii Nunchuk for communications.
‘channel’ is the I^^2^^C channel that the Nunchuk is connected to: 1 or 2 on the rear I/O connector, or 3 (the default if it is not specified) for the Wii connector on the front panel.
‘Zinterrupt’ and ‘Cinterrupt’ are optional MMBasic interrupt routines that will be triggered when the Z or the C button is pressed.  The interrupts trigger once on the button press and will not re-interrupt until it is released.
The firmware checks for the existence of a controller on open and will throw an error if not found.  This error can be trapped with the ON ERROR command.  If a Classic controller is plugged in instead, an error will not be thrown: you can check the ID code with NUNCHUK(T, channel).
The PicoMite's forms are accepted too: WII NUNCHUCK OPEN [interrupt] and WII NUNCHUCK CLOSE (or DEVICE NUNCHUCK OPEN and CLOSE) open and close a Nunchuk on the Wii connector, channel 3, the interrupt being ‘Zinterrupt’.
Once open the Nunchuk is polled continuously in the background every 20 ms.  The I^^2^^C transfers are under interrupt control and non-blocking for the rest of the firmware.  The I^^2^^C channel is opened at 100KHz: other I^^2^^C devices can share the channel with the Nunchuk, in which case I2C OPEN should not be used (I2C WRITE, READ and CHECK work on the channel without it).
CONTROLLER NUNCHUK CLOSE will close the Nunchuk on ‘channel’ (3 if it is omitted).
Also see the NUNCHUK() function for accessing the state of the device.

=== CSUB name [type  [, type]  …]
  hex [[ hex[…] 
  hex [[ hex[…] 
END CSUB
---
Defines the binary code for an embedded machine code program module written in C or ARM assembler. The module will appear in MMBasic as the command 'name' and can be used in the same manner as a built-in command.
Multiple embedded routines can be used in a program with each defining a different module with a different 'name'.  
The first 'hex' word is a 32 bit word which is the offset in 32-bit words from the word after it (the start of the compiled code) to the entry point of the embedded routine (usually the function main()).  The following hex words are the compiled binary code for the module. These are automatically programmed into MMBasic when the program is loaded (by RUN). Each 'hex' must be exactly eight hex digits representing the bits in a 32-bit word and be separated by one or more spaces or new lines. The command must be terminated by a matching END CSUB.   Any errors in the data format will be reported when the program is run.  During execution MMBasic will skip over any CSUB commands so they can be placed anywhere in the program. 
The type of each parameter can be specified in the definition. For example:
{l=720}`CSUB MySub integer, integer, string` 
This specifies that there will be three parameters, the first two being integers and the third a string.  
Note:
{kl=1 n=3 v=0 t=l1980 b=0 a=45}Up to sixteen arguments can be specified ('arg1', 'arg2', etc).
{kl=1 n=3 v=0 t=l1980 b=0 a=45}If a variable or array is specified as an argument the C routine will receive a pointer to the memory allocated to the variable or array and the C routine can change this memory to return a value to the caller. In the case of arrays, they should be passed with empty brackets eg, arg().  In the CSUB the argument will be supplied as a pointer to the first element of the array. 
{kl=1 n=3 v=0 t=l1980 b=0 a=45}Constants and expressions will be passed to the embedded C routine as pointers to a temporary memory space holding the value. 
A CSUB built for the PicoMite can also be used if it uses only MMBasic's call table and none of the PicoMite's hardware (see the chapter *Porting Programs*).

=== DAC n, voltage
--- keep
Sets the DAC channel ‘n’ (1 or 2) to ‘voltage’, from 0 to just below OPTION VCC (normally 3.3V).  The DACs drive the audio output: DAC 1 is the left channel and DAC 2 the right.
Do not use this command while sound is playing or DAC START is running: they would overwrite the value.  The function PIN("DAC1") or PIN("DAC2") returns the voltage on a DAC.

=+= DAC START freq, array1%() [, array2%()] [, interrupt]
---
Sets up the DACs to create an arbitrary waveform.  ‘array1%()’ (for DAC 1) and the optional ‘array2%()’ (for DAC 2) are integer arrays which should contain numbers in the range 0-4095 to suit the 12-bit DACs.  They must be global (or STATIC), not LOCAL.  The output occurs in the background and control returns to MMBasic immediately.
‘freq’ is the rate at which the DACs change value, up to 500KHz.  The software automatically and separately uses the number of items in each of the arrays to drive the DACs.  As an example if there are 180 items in the array c%() which are output at a frequency of 100,000 Hz this will give a waveform frequency of 100,000/180 = 555Hz.  If there are 90 items in the array d%() at the same frequency of 100,000 Hz this will at the same time produce a waveform frequency of 100,000/90 = 1111Hz.
The output runs continuously unless the optional interrupt is specified.  In this case the contents of ‘array1%()’ is output once (the second array repeats or is cut short with it) and the interrupt is triggered on completion.  If there is no second array the interrupt is the third argument:  `DAC START 100000, c%(), , Done`
DAC START cannot be used while sound is playing ("DAC in use").  A new DAC START replaces the output of the last.

=+= DAC STOP
--- keep
Stops the DAC output and returns the DACs to normal use (and to the resting level of the audio output).

=== {b=40 a=40}DATE$ = "DD-MM-YY[YY]"

{b=40 a=40}DATE$ = "DD/MM/YY[YY]"

Set the date of the internal clock/calendar.

=== DEVICE device [arguments]
--- keep
The PicoMite's prefix for its device commands, so that its programs run unchanged.  ‘device’ is one of:

{l=720}NUNCHUCK: a Wii Nunchuk on the Wii connector (DEVICE NUNCHUCK OPEN [interrupt], DEVICE NUNCHUCK CLOSE: see CONTROLLER NUNCHUK)

=+= DEVICE SERIALTX pin, baudrate, string$
--- keep
Sends ‘string$’ as serial data on ‘pin’, which can be any I/O pin: 8 data bits, no parity and one stop bit, the line high when it is idle (the PicoMite's command).  ‘baudrate’ can be 110 to 230400.  A pin that has been set up must be a digital output; one that has not is made one.

=+= DEVICE SERIALRX pin, baudrate, string$, timeout, status [, nbr] [, terminators$]
--- keep
Receives serial data on ‘pin’, which can be any I/O pin, into the string variable ‘string$’: 8 data bits, no parity and one stop bit (the PicoMite's command).  ‘baudrate’ can be 110 to 230400 and ‘timeout’ is in milliseconds, 1 to 100000.  ‘status’ is a numeric variable.
The command returns when ‘nbr’ characters have been received (‘status’ is set to 2), when one of the characters of ‘terminators$’ has been received (it is kept in ‘string$’, and ‘status’ is 3), or after ‘timeout’ (‘status’ is -1, and ‘string$’ holds what had been received).  ‘nbr’ is at most what ‘string$’ can hold (255 characters, or its LENGTH), and that if it is left out.
A pin that has been set up must be a digital input; one that has not is made one, with its pullup. Interrupts are disabled while the command waits, so everything else (sound, the USB devices, the timers) waits too.

DIM a = 1234, b = 345
DIM STRING strn = "text"
DIM x%(3) = (11, 22, 33, 44)
{}
---
Declares one or more variables (i.e. makes the variable name and its characteristics known to the interpreter).  
When OPTION EXPLICIT is used (as recommended) the DIM, LOCAL or STATIC commands are the only way that a variable can be created.  If this option is not used then using the DIM command is optional and if not used the variable will be created automatically when first referenced.
The type of the variable (i.e. string, float or integer) can be specified in one of three ways:
By using a type suffix (i.e. !, % or $ for float, integer or string).   For example:
{kn=1 b=0 a=0 l=720}`DIM nbr%, amount!, name$`
By using one of the keywords FLOAT, INTEGER or STRING immediately after the command DIM and before the variable(s) are listed.  The specified type then applies to all variables listed (i.e. it does not have to be repeated).  For example:
{kn=1 b=0 a=0 l=720}`DIM STRING first_name, last_name, city`
By using the Microsoft convention of using the keyword "AS" and the type keyword (i.e. FLOAT, INTEGER or STRING) after each variable.  If you use this method the type must be specified for each variable and can be changed from variable to variable.  
For example:
{kn=1 b=0 a=0 l=720}`DIM amount AS FLOAT, name AS STRING`
Floating point or integer variables will be set to zero when created and strings will be set to an empty string (i.e. "").  You can initialise the value of the variable by using an equals symbol (=) and an expression following the variable definition.  For example:\n`     DIM STRING city = "Perth", house = "Brick"`
The initialising value can be an expression (including other variables) and will be evaluated when the DIM command is executed.  See the chapter *Variables and Expressions* for more examples of the syntax.
As well as declaring simple variables the DIM command will also declare arrayed variables (i.e. an indexed variable with a number of dimensions).  Following the variable's name the dimensions are specified by a list of numbers separated by commas and enclosed in brackets.  For example:
{kn=1 b=0 a=0 l=720}`DIM array(10, 20)`
Each number specifies the index range in each dimension.  Normally the indexing of each dimension starts at 0 but the OPTION BASE command can be used to change this to 1.
The above example specifies a two dimensional array with 11 elements (0 to 10) in the first dimension and 21 (0 to 20) in the second dimension.  The total number of elements is 231 and because each floating point number requires 8 bytes a total of 1848 bytes of memory will be allocated.
A dimension can hold a single element.  With the default OPTION BASE 0 this is written as DIM a(0) and with OPTION BASE 1 as DIM a(1).  This matters when the size of an array is calculated while the program is running and the calculation can produce one element, and it allows the MATH matrix commands to produce a single row, a single column, or a 1x1 result.
Strings will default to allocating 255 bytes (i.e. characters) of memory for each element and this can quickly use up memory when defining arrays of strings.  In that case the LENGTH keyword can be used to specify the amount of memory to be allocated to each element and therefore the maximum length of the string that can be stored.  This allocation ('n') can be from 1 to 255 characters.
For example:  `DIM STRING s(5, 10)`  will declare a string array with 66 elements consuming 16,896 bytes of memory while:
{kn=1 b=0 a=0 l=720}`DIM STRING s(5, 10) LENGTH 20`
Will only consume 1,386 bytes of memory.  Note that the amount of memory allocated for each element is n + 1 as the extra byte is used to track the actual length of the string stored in each element.
If a string longer than 'n' is assigned to an element of the array an error will be produced.  Other than this, string arrays created with the LENGTH keyword act exactly the same as other string arrays.  This keyword can also be used with non-array string variables (see below).
In the above example you can also use the Microsoft syntax of specifying the type __after__ the length qualifier.  For example:
{kn=1 b=0 a=0 l=720}`DIM s(5, 10) LENGTH 20 AS STRING`
{kn=1 b=0 a=0}With a simple (non arrayed) string the LENGTH keyword also sets the maximum length of the string, and if the length is 15 or less the string is held in the variable's own record, saving the 256 bytes of memory that a string variable otherwise takes.  This is useful for short strings.  A string constant (CONST) of up to 15 characters is held in the same way.
Arrays can also be initialised when they are declared by adding an equals symbol (=) followed by a bracketed list of values at the end of the declaration.  For example:
{kn=1 b=0 a=0 l=720}`DIM INTEGER nbr(4) = (22, 44, 55, 66, 88)`
{b=0}or          `DIM s$(3) = ("foo", "boo", "doo", "zoo")`
Note that the number of initialising values must match the number of elements in the array including the base value set by OPTION BASE.  If a multi dimensioned array is initialised then the first dimension will be initialised first followed by the second, etc.
Also note that the initialising values must be after the LENGTH qualifier (if used) and after the type declaration (if used).

=== DO UNTIL expression \n   <statements> \nLOOP

=== DO\n   <statements> \nLOOP UNTIL expression

=== DO\n   <statements> \nLOOP WHILE expression

Loops until the expression following WHILE is false.  Because the test is made at the end of the loop the statements inside the loop will be executed at least once, even if the expression is false.

=== DRAW3D SHOW n, x, y, z [,nocull] [,usefurthest]
or
DRAW3D WRITE n, x, y, z [,nocull] [,usefurthest]
---
The 3D engine draws objects made of flat faces as a camera sees them, with the hidden faces removed.  It has the sub-commands CREATE, CAMERA, LIGHT, ROTATE, SHOW, WRITE, HIDE, HIDE ALL, RESTORE, RESET, SET FLAGS, DIAGNOSE, CLOSE and CLOSE ALL, which are described with the DRAW3D() function in the document *The 3D engine.pdf* in the Colour Maximite 2 firmware download (see Appendix O).  Up to 128 objects and 6 cameras can be used.
DRAW3D LIGHT n, x, y, z, ambient sets the position of the light source for object ‘n’ and its ambient light level, 0 to 100 (percent).  DRAW3D SET FLAGS n, flag, face, count [, face, count ...] sets the flags (0 to 255) of ‘count’ faces of object ‘n’, from face number ‘face’.  DRAW3D DIAGNOSE n, x, y, z [, sort] prints each face of object ‘n’ as it would be drawn at ‘x’, ‘y’, ‘z’: its distance, its dot product and whether it is hidden or showing (sorted by distance unless ‘sort’ is 0).  DRAW3D RESET n [, n ...] makes the current orientation of each object its starting point: later ROTATE commands turn it from there.
DRAW3D SHOW draws the 3D object ‘n’ at the position ‘x’, ‘y’, ‘z’, first erasing (to colour 0) the area where it was last drawn; DRAW3D WRITE draws it without erasing anything.
Rendering of the 3D object works by the painter's algorithm: the faces are sorted and those further away are drawn first.  In addition MMBasic supports back face culling: faces that point away from the camera are not drawn.  Set ‘nocull’ to 1 to draw them as well (0, the default, culls them).
To sort the faces MMBasic uses the position of each face's centroid.  This works in many situations but in some 3D models it is better to use the furthest vertex of each face: set ‘usefurthest’ to 1 for that (0, the default, uses the centroid).

=== FLASH SAVE n
or
FLASH OVERWRITE n
--- keep
Saves the program in program memory (the one RUN last loaded) into flash slot ‘n’ (1 to 3), as the PicoMite does, for FLASH RUN, FLASH CHAIN and FLASH LOAD.  FLASH SAVE gives the error "Already programmed" if the slot holds anything; FLASH OVERWRITE replaces what it holds.  They can only be used at the command prompt.
The Colour Maximite 2 keeps its flash slots on the SD card, as the files slot1 to slot3 in the hidden directory A:/.flash, and reads a slot into RAM when it is first used after a RUN or NEW.  No flash memory is written, and the slots are kept when the power is off, as the PicoMite's are.  A slot holds the program as it was tokenised, not its source text, so a version of the firmware that tokenises programs differently will not run it: FLASH LIST then says that the slot was saved by another firmware version, and the program must be loaded from its file and saved again.

=+= FLASH RUN n
--- keep
Runs the program in flash slot ‘n’, as RUN runs a program.  The program runs where it is, in the slot's copy in RAM: it is not loaded into program memory or tokenised again.  A slot of 0 runs the program in program memory.  MM.INFO(FLASH) returns the slot whose program is running, or 0.
In a slot's program, RUN with no file name runs that program again.  When the program ends, or stops with an error or Ctrl-C, the program in program memory is the current program again (for LIST, RUN and EDIT), and CONTINUE cannot resume the slot's program.

=+= FLASH CHAIN n
--- keep
Runs the program in flash slot ‘n’ as FLASH RUN does, but the global variables are kept, as with CHAIN.  A slot of 0 runs the program in program memory.  It can only be used in a program.

=+= FLASH LOAD n
--- keep
Loads the program in flash slot ‘n’ into program memory, replacing the program there.  RUN then runs it as it is (not its file, which RUN otherwise loads afresh) until another program is loaded, NEW is used or the Colour Maximite 2 restarts.  It can only be used at the command prompt.

=+= FLASH LIST [n [, ALL]]
--- keep
FLASH LIST reports what each flash slot holds: "available", the file name of a program, or the size of an image.  FLASH LIST n lists the program in slot ‘n’ as it is held (as LIST FLASH lists program memory), pausing at each screenful unless ALL is given.

=+= FLASH ERASE n
or
FLASH ERASE ALL
--- keep
Empties flash slot ‘n’, or all three.  FLASH ERASE ALL can only be used at the command prompt.

=+= FLASH LOAD IMAGE n, file$ [, O]
or
FLASH LOAD IMAGE n, file$ [, OVERWRITE]
--- keep
Loads the BMP file ‘file$’ (".BMP" is added if it has no extension) into slot ‘n’ in the PicoMite's format, for the PicoMite's commands that use image slots (BLIT FLASH and TILEMAP).  The slot holds an 8 byte header, the image's width and height as two 32-bit words, followed by the pixels in the RGB121 format, two to a byte with the left pixel in the low four bits; MM.INFO(FLASH ADDRESS n) gives its address.
‘n’ is 1 to 8.  Slots 1 to 3 are the flash slots, kept on the SD card (see FLASH SAVE).  Slots 4 to 8 are the PicoMite's RAM slots 1 to 5, held in RAM until RAM ERASE, an overwrite or a restart (see RAM SAVE), so a program that loads its images every time it starts gives O.
A slot that already holds something gives the error "Already programmed" unless O (or OVERWRITE) is given.  At the command prompt the command reports the size of the image.

=+= FLASH DISK LOAD n, file$ [, O]

Loads the bytes of the file ‘file$’, as they are, into slot ‘n’ (1 to 8), for a program to read with PEEK or MEMORY COPY at MM.INFO(FLASH ADDRESS n) (eg, a PicoMite program's sprite data).  A slot that already holds something gives the error "Already programmed" unless O (or OVERWRITE) is given.

=== FRAMEBUFFER
--- keep
This command allows you to create, use and remove a variable size framebuffer which should make many applications which have a working area bigger than the screen easier to program.  The framebuffer is held in the variable memory.
These are the Colour Maximite 2's own FRAMEBUFFER commands, for all colour depths except 4 and 1 bits.  In the 4 and 1-bit colour depths FRAMEBUFFER is the PicoMite's (see below) and these forms are not available.
While a framebuffer exists, a MODE command that changes the colour depth gives the error "Colour mismatch with framebuffer": use FRAMEBUFFER CLOSE first.  The framebuffer and its backup are deleted when the program ends (for any reason, including Ctrl-C) and by running a program.
FRAMEBUFFER can be given as the page number to PAGE WRITE (which is the same as FRAMEBUFFER WRITE) and to the commands that read from a page, such as BLIT, SPRITE READ and the IMAGE commands.

=+= FRAMEBUFFER CREATE [width] [, height]
--- keep
Creates a framebuffer with the width and height specified in pixels.  Each must be at least the size of the write page (normally MM.HRES and MM.VRES, which are also the defaults) and can be at most 1600 by 1200 on the Generation 1 and 4096 by 2048 on the Generation 2.  There must be enough free variable memory for it ("Not enough memory for framebuffer").
FRAMEBUFFER CREATE with a framebuffer already there replaces it with the new size and deletes its backup.  This is refused while the framebuffer is the write page ("Framebuffer is set for write").

=+= FRAMEBUFFER WRITE [F | N]
--- keep
Sets all drawing commands to write to the framebuffer and inherit its width and height (MM.HRES and MM.VRES report them).  PAGE WRITE n returns the drawing to a page.
The PicoMite's letters are accepted too, as a letter or a string: FRAMEBUFFER WRITE F is the same as FRAMEBUFFER WRITE, and FRAMEBUFFER WRITE N draws on the display again, as PAGE WRITE 0 does.  The other letters are for the 4 and 1-bit colour depths only (see below).

=+= FRAMEBUFFER BACKUP
--- keep
Creates a backup copy of the framebuffer.  If a backup already exists it is overwritten.  This allows the programmer to save the background before he/she starts writing non-static data to it.  The backup is also held in the variable memory, so it may not be possible to use this command if a very large framebuffer is specified in the 12, 16 or 32-bit colour depth.  An error is given in this case.

=+= FRAMEBUFFER RESTORE [x, y, w, h]
--- keep
Restores all or part of the framebuffer from the backup.  This allows the programmer to "clean" all or part of the framebuffer before adding new non-static items.
‘x’ and ‘y’ are the top left corner and ‘w’ and ‘h’ the width and height of the area to restore, which must lie within the framebuffer.  Give all four or none: without them the whole framebuffer is restored.

=+= FRAMEBUFFER WINDOW x, y, page [, I or B]
--- keep
Copies an area of the framebuffer with its top left corner at ‘x’, ‘y’ to the page specified.  The area is the size of the page (normally MM.HRES by MM.VRES) and must lie within the framebuffer.  The optional parameter specifies if the copy is done immediately (I, the default) or during the next frame blanking (B).
Without a framebuffer the error is "World not created".

=+= FRAMEBUFFER CLOSE
--- keep
Releases the memory used by the framebuffer and its backup, allowing a new framebuffer to be created with a different size.  The framebuffer cannot be closed while it is the write page ("Framebuffer is set for write"): use PAGE WRITE first.

=== FRAMEBUFFER CREATE
--- keep
__IN THE 4 AND 1-BIT COLOUR DEPTHS ONLY__ In the 4-bit colour depth (MODE r, 4) and the 1-bit colour depth (MODE r, 1) the FRAMEBUFFER command is the PicoMite's, so that programs written for the PicoMite's VGA and HDMI versions work as they do there (see the chapter Video Modes and Pages).  In the 1-bit depth a buffer holds a bit a pixel, as the display does, and a pixel drawn in any colour but black is set.  Its framebuffers are pages 0 to 4: N (the display, page 0), L (the layer, page 1), F (the framebuffer, page 2), 2 (the second framebuffer, page 3) and T (the top layer, page 4).  They are held in the video memory, not in the variable memory, and MODE closes them.  Creating a buffer that exists already is an error.  BLIT FRAMEBUFFER, BLIT FLASH and TILEMAP use the same letters.
A colour given as a number from 0 to 15 is one of the 16 colours: 0 black, 1 blue, 2 myrtle, 3 cobalt, 4 midgreen, 5 cerulean, 6 green, 7 cyan, 8 red, 9 magenta, 10 rust, 11 fuchsia, 12 brown, 13 lilac, 14 yellow and 15 white (unless changed by MAP).
FRAMEBUFFER CREATE creates the framebuffer F, cleared to black, with the resolution of the current mode.  It takes no size (the Colour Maximite 2's FRAMEBUFFER CREATE w, h gives the error "Unexpected text" in this depth).

=+= FRAMEBUFFER CREATE 2
--- keep
Creates the second framebuffer "2", cleared to black, with the resolution of the current mode.  It is intended for use with FRAMEBUFFER MERGE as the alternative to a live layer.

=+= FRAMEBUFFER LAYER [colour]
--- keep
Creates the layer buffer L with the resolution of the current mode.  The layer is shown over the display N automatically: at the end of each frame the firmware puts the two onto the screen, the pixels of the layer that are of the transparent colour ‘colour’ (0 to 15, default 0) letting N show through.  The layer is cleared to that colour, as CLS without a colour does while the layer is the write target.
In the 1-bit colour depth the layer has no transparent colour (‘colour’ is not used): it is ORed with N, a pixel set in either showing its tile's foreground colour, as on the PicoMite.

=+= FRAMEBUFFER LAYER TOP [colour]
--- keep
Creates the top layer T with the resolution of the current mode.  It is shown over the layer L (where that has been created) and N in the same way, its pixels of the transparent colour ‘colour’ (0 to 15, default 0) letting what is under them show through.  It is cleared to that colour.
In the 1-bit colour depth T can be created and drawn on but, as on the PicoMite, it is not shown.

=+= FRAMEBUFFER WRITE where
or
FRAMEBUFFER WRITE where$
--- keep
Specifies the target for subsequent graphics commands.  ‘where’ can be N, F, 2, T or L, where N is the display, or a string expression giving one of them.  The buffer must have been created ("Frame buffer not created", "Layer not created" and the like).  MM.HRES and MM.VRES report its size.
PAGE WRITE selects any 4-bit page, including the pages after page 4.

=+= FRAMEBUFFER CLOSE [which]
--- keep
Closes a framebuffer.  The optional parameter ‘which’ can be F, L, T or 2.  If it is omitted all four are closed and the drawing returns to N.  A buffer that was the write target when it was closed is replaced by N.

=+= FRAMEBUFFER COPY from, to [, B]
--- keep
Does a highly optimised full screen copy of one framebuffer to another.  ‘from’ and ‘to’ can be N, F, 2, T or L.  A buffer that has not been created stands for N, as on the PicoMite; the two must differ ("Buffer not created").
If the optional parameter B is specified the copy waits until the next frame blanking starts.

=+= FRAMEBUFFER WAIT
--- keep
Pauses processing until the next frame blanking starts.

=+= FRAMEBUFFER MERGE [colour] [, B]
--- keep
Copies framebuffer "2" over framebuffer F into the display N in a single pass.  Pixels in "2" that are of the transparent colour ‘colour’ (0 to 15, default 0) show the F pixel instead.  Both must have been created.  The layers L and T are not involved and continue to be applied over the result.  In the 1-bit colour depth N is F ORed with "2" (‘colour’ is not used).
If the optional parameter B is specified the merge waits until the next frame blanking starts before it begins, so that tearing is avoided.  This is the alternative to a live layer for programs that draw sprites over a background: the display only changes when MERGE is commanded.

=== FUNCTION xxx (arg1 [,arg2, …]) [AS <type>]\n   <statements>\n   <statements>\n   xxx = <return value>\nEND FUNCTION
---
Defines a callable function.  This is the same as adding a new function to MMBasic while it is running your program.
'xxx' is the function name and it must meet the specifications for naming a variable.    The type of the function can be specified by using a type suffix (i.e. xxx$) or by specifying the type using AS <type> at the end of the functions definition.  For example:
{kn=1 b=0 a=0 l=720}`FUNCTION xxx (arg1, arg2) AS STRING`
'arg1', 'arg2', etc are the arguments or parameters to the function (the brackets are always required, even if there are no arguments).  An array is specified by using empty brackets.  i.e.  arg3().    The type of the argument can be specified by using a type suffix (i.e. arg1$) or by specifying the type using `AS <type> (i.e. arg1 AS STRING).`
The argument can also be another defined function or the same function if recursion is to be used (the recursion stack is limited).
To set the return value of the function you assign the value to the function's name.  For example:
{kn=1 b=0 a=0 l=720}`FUNCTION SQUARE(a)`
{b=0 a=0 l=720}`  SQUARE = a \* a`
{b=0 a=0 l=720}`END FUNCTION`
Every definition must have one END FUNCTION statement.  When this is reached the function will return its value to the expression from which it was called.  The command EXIT FUNCTION can be used for an early exit.
You use the function by using its name and arguments in a program just as you would a normal MMBasic function.  For example:
{b=0 a=0 l=720}`PRINT SQUARE(56.8)`
When the function is called each argument in the caller is matched to the argument in the function definition.  These arguments are available only inside the function.  
Functions can be called with a variable number of arguments.  Any omitted arguments in the function's list will be set to zero or a null string.  
Arguments in the caller's list that are a variable and have the correct type will be passed by reference to the function.  This means that any changes to the corresponding argument in the function will also be copied to the caller's variable and therefore may be accessed after the function has ended.  The argument can be prefixed with BYVAL which will prevent this mechanism and cause only the value to be used.  Alternatively, the prefix BYREF instructs MMBasic that a reference is required and an error will be generated if that cannot be done.
Arrays are passed by specifying the array name with empty brackets (eg, arg()) and are always passed by reference and must be the correct type.
You must not jump into or out of a function using commands like GOTO.  Doing so will have undefined side effects including ruining your day.
A function can also return a whole array by declaring the array dimensions with the type at the end of the definition (INTEGER and FLOAT arrays only).  For example:
{kn=1 b=0 a=0 l=720}`FUNCTION fred (arg1, arg2) AS INTEGER(6)`
Inside the function the result is set by assigning to elements of the function's name (eg, fred(i) = 44).  Note that reading an element of the function's name inside the function will call the function recursively - if intermediate values must be read back, build the result in a LOCAL array and copy it with fred() = tmp%().
Such a function can only be used as the source of a whole-array assignment and the destination array must have the same type and total number of elements.  For example:
{kn=1 b=0 a=0 l=720}`DIM b%(6) : b%() = fred(1, 2)`
It cannot be used anywhere else in an expression, so something like PRINT fred(1, 2) will generate an error.
The dimensions can be expressions and are evaluated each time the function is called, after its arguments have been set up, so they can depend on the arguments.  The result array can also be filled by passing it to any command that takes an array (eg, the MATH commands) rather than by assigning to its elements.  For example, this returns the inverse of whatever size matrix it is given:
{kn=1 b=0 a=0 l=720}`FUNCTION Invr(N()) AS FLOAT(BOUND(N(),1), BOUND(N(),2))`
{kn=1 b=0 a=0 l=720}`  MATH M_INVERSE N(), Invr()`
{kn=1 b=0 a=0 l=720}`END FUNCTION`
{kn=1 b=0 a=0 l=720}`DIM a(3,3), b(3,3) : b() = Invr(a())`

=== GUI
---
The GUI commands create the GUI controls and manage them: GUI BUTTON, SWITCH, CHECKBOX, RADIO, LED, FRAME, NUMBERBOX, TEXTBOX, FORMATBOX, SPINBOX, DISPLAYBOX, CAPTION, GAUGE, BARGAUGE, AREA, LISTBOX and SLIDER create a control and GUI PAGE, SETUP, DELETE, DISABLE, ENABLE, HIDE, SHOW, RESTORE, REDRAW, FCOLOUR, BCOLOUR and INTERRUPT manage them.  GUI CLICK clicks them from a program or a pin.  See the chapter *GUI Controls*; the commands are described in full in the document GUI Controls and Programming.pdf (see Appendix O), and GUI LISTBOX, SLIDER and CLICK below.
The controls need memory reserved for them with OPTION MAXCTRLS (otherwise the error is "No memory allocated for GUI controls").  They are touched on a USB touch screen, where a finger acts where it touches, or clicked with the left button of a USB mouse, which is used as soon as it is plugged in, or of a PS2 or I^^2^^C mouse set with OPTION MOUSE.  The first GUI command opens that mouse and displays the GUI's pointer at it, linked to it as GUI CURSOR ON : GUI CURSOR LINK MOUSE would, so the GUI CURSOR commands work on it; a USB mouse plugged in after that is used at once, and the pointer is then displayed.  The pointer goes at the end of the program.
The controls are those of the Micromite Plus: its TOUCH() function reads a USB touch screen here, as on the PicoMite, and CLICK() reads the mouse and GUI CLICK.  GUI BEEP is not provided (use PLAY TONE in the interrupt routine if a click is wanted).  GUI TEST checks a touch screen and the display.

=== GUI BITMAP  x,  y,  bits  [, width]  [, height]  [, scale]  [, c]  [, bc]
---
Displays the bits in a bitmap on the screen starting at 'x' and 'y'.
'height' and 'width' are the dimensions of the bitmap as displayed on the screen and default to 8x8.  
{t=l2592}'scale' is optional and can be 1 to 15 (the default is 1).  
{t=l2592}'c' is the drawing colour and 'bc' is the background colour.  They are optional and default to the current foreground and background colours.  'bc' can be -1 and then the background is not drawn (the pixels of the zero bits are left as they are).
The bitmap can be an integer or a string variable or constant and is drawn using the first byte as the first bits of the top line (bit 7 first, then bit 6, etc) followed by the next byte, etc.  When the top line has been filled the next line of the displayed bitmap will start with the next bit in the integer or string.  An integer holds 64 bits (its least significant byte is the first) and a string up to 255 bytes: 'width' x 'height' must not be more bits than it holds ("Not enough data").
See the chapter *Graphics Functions* for a definition of the colours and graphics coordinates.

=== GUI CLICK [x, y]
or
GUI CLICK DOWN
or
GUI CLICK UP
or
GUI CLICK PIN pin [, INV]
or
GUI CLICK PIN OFF
---
Clicks the GUI controls without a mouse, as on the PicoMite: from a program (a joystick read by it, say, or a test), or with a button on a pin.  The clicks act as the left mouse button, for the controls and for CLICK(DOWN), CLICK(X) and the others.
GUI CLICK presses and releases the button at the cursor's active point (see GUI CURSOR), whether the cursor is shown or not, and moves the mouse there, as the PicoMite does: GUI CURSOR x, y sets that point without a click, and a cursor linked to the mouse (the GUI's pointer is) has it where the mouse is.  With ‘x’ and ‘y’ it moves the point (and the mouse) there first.  It returns when the controls have taken the press and the release (in 130 mS to one second), and a GUI interrupt routine that the click calls has run by then.
GUI CLICK DOWN presses the button at the cursor's active point and holds it until GUI CLICK UP: a slider then follows the pointer (moved by the mouse, or by MOUSE SET), and a spin box repeats.
GUI CLICK PIN makes a button on ‘pin’ click at the cursor's active point: pressed when the pin is low, the pin set as a digital input with a pull-up, or with INV pressed when it is high, with a pull-down.  The pin must not be in use.  GUI CLICK PIN OFF releases it.
GUI CLICK, DOWN and UP cannot be used in an interrupt routine, and GUI CLICK PIN's pin is released at RUN.
A press belongs to what made it, a finger on a USB touch screen or the mouse's button (or GUI CLICK), until that is released: while a finger is down a click is not taken, and the other way round.  A message box (MSGBOX()) cannot be opened by a click made with GUI CLICK or GUI CLICK PIN.

=== GUI CURSOR ON [n [,x, y [,colour]]]
--- keep tight
Displays and manipulates a cursor (eg, a mouse pointer) on the screen, as the PicoMite's GUI CURSOR does.  The cursor sits above all other graphics and nothing can overwrite it.  It is drawn on page 0 (page 1 in the 12-bit colour depth); in the 4 and 1-bit colour depths it is drawn over the display, and a loaded cursor (2) cannot be used there ("Invalid for this screen mode").
GUI CURSOR ON enables and displays the cursor.  ‘n’ is the cursor number: 0 is a mouse type pointer, 1 is a cross hair and 2 is a user defined cursor previously loaded with GUI CURSOR LOAD; without ‘n’ it is the one last chosen.  ‘x’ and ‘y’ specify the position of the cursor's active point: without them it is the centre of the screen, and the mouse is moved there too.  ‘colour’ sets the colour of cursors 0 and 1, as GUI CURSOR COLOUR does.  If the cursor is already on, the command applies its arguments again: a new shape, position or colour.
The cursor's shape, active point and colour are kept by GUI CURSOR OFF; RUN sets them back to cursor 0, the top left corner and white.

=+= GUI CURSOR x, y
--- keep tight
GUI CURSOR x, y moves the cursor's active point to ‘x’, ‘y’.  If the cursor is hidden or off it is not displayed, just its stored location is updated: GUI CLICK presses there.  A cursor linked to the mouse moves the mouse there too.

=+= GUI CURSOR OFF
--- keep tight
GUI CURSOR OFF turns off the cursor and breaks its link to the mouse.

=+= GUI CURSOR HIDE
{}
GUI CURSOR SHOW
--- keep tight
GUI CURSOR HIDE hides the cursor but maintains its position and GUI CURSOR SHOW will show a hidden cursor again at its stored position.  Neither does anything while the cursor is off.

=+= GUI CURSOR COLOUR colour
--- keep tight
GUI CURSOR COLOUR changes the colour of cursor numbers 0 and 1, and is kept while the cursor is off.  It does not affect a loaded cursor which has its colours specified by the cursor designer.

=+= GUI CURSOR LOAD fname$
--- keep tight
GUI CURSOR LOAD loads cursor number 2 from the file ‘fname$’ (".CUR" is added if it has no extension) and makes it the cursor: displayed at once in the same place if the cursor is on, or by the next GUI CURSOR ON.  The file uses the same layout and colour coding as a sprite file (see SPRITE LOAD) except that the header line is: width, height, xoffset, yoffset.  The two offsets define the position of the cursor’s active point within the image - the mouse pointer (cursor 0) has offsets 0,0 (the tip of the arrow) and the cross hair (cursor 1) has 7,7 (its centre).  The cursor is held in the pixel format of the colour depth in use when it is loaded, so it should be loaded after the MODE command.

=+= GUI CURSOR LINK MOUSE
GUI CURSOR UNLINK MOUSE
--- keep tight
GUI CURSOR LINK MOUSE links the cursor to the mouse so that it automatically tracks the mouse movement (MOUSE SET too), moving the mouse to the cursor first so that the cursor does not jump.  GUI CURSOR UNLINK MOUSE breaks the link.  A USB mouse must be connected, a PS2 mouse set with OPTION MOUSE 0, or a PS2 or I^^2^^C mouse opened with CONTROLLER MOUSE OPEN, before the cursor can be linked (otherwise the error is "No mouse connected").  The cursor's active point (see GUI CURSOR LOAD) follows the mouse, and GUI CURSOR OFF also breaks the link.  The GUI's pointer (see GUI) is a cursor linked in this way.

=== GUI LISTBOX [#]ref, array$(), x, y, w, h [,fc] [,bc] [,maxrows]
or
GUI LISTBOX CANCEL
---
Creates a list box, as on the PicoMite: a box ‘w’ by ‘h’ pixels with its top left at ‘x’, ‘y’, showing the selected item of the string array ‘array$()’ and a marker pointing down.  ‘fc’ and ‘bc’ are its foreground and background colours (by default the last ones used).
Clicking it opens a list of the items below it (or above it, if there is more room there), each row as high as the box; while the list is open the other controls are greyed and do not respond.  Clicking an item selects it and closes the list, and clicking outside the list closes it with the selection unchanged.  If there are more items than fit on the screen, or than ‘maxrows’ (1 to 100), arrows above and below the rows scroll the list, and repeat while they are held.  GUI LISTBOX CANCEL closes an open list, with the selection unchanged.
CTRLVAL(#ref) returns the index of the item selected, 0 for the array's first element (so with OPTION BASE 1 the item is array$(CTRLVAL(#ref) + 1)); it is 0 when the control is created.  CTRLVAL(#ref) = n selects item ‘n’ (kept within the items).  The GUI up interrupt is called when an item is selected.
The control reads the array's items each time it is drawn, so an item changed and the control drawn again (by CTRLVAL, or GUI REDRAW) shows the change.  The array must therefore last as long as the control: it must be global or STATIC ("Must be a global variable" for a LOCAL one) and one-dimensional, and the number of items is its size when the control is created.

=== GUI SLIDER [#]ref, x, y, w, h [,fc] [,bc] [,min] [,max] [,inc]
---
Creates a slider, as on the PicoMite: a thumb on a track, ‘w’ by ‘h’ pixels with its top left at ‘x’, ‘y’, for a value from ‘min’ to ‘max’ (by default 0 to 100).  It is horizontal if it is wider than it is tall, with ‘min’ at the left, and vertical otherwise, with ‘min’ at the bottom.  ‘fc’ is the colour of the thumb and of the track up to it, and ‘bc’ is the background colour (by default the last ones used).
Clicking the track moves the thumb there, and while the button is held the thumb follows the mouse, past the ends of the track too.  If ‘inc’ is more than 0 (the default is 0) the value is a whole number of steps of ‘inc’ from ‘min’.
CTRLVAL(#ref) returns the value, ‘min’ when the control is created, and CTRLVAL(#ref) = v sets it (kept within ‘min’ and ‘max’).  The GUI down interrupt is called every 50 mS while the thumb is being dragged, and the up interrupt when the button is released.

=== GUI TEST LCDPANEL

=== HELP [searchtext]
---
Shows the syntax of a command or function.  It can only be used at the command prompt (in the editor F11 shows the help for the keyword at the cursor).  ‘searchtext’ need not be quoted.
If the SD card has the file help.txt in its root directory (A:/help.txt) HELP looks up ‘searchtext’ in that file.  This can be a user written or community developed file and must be in a particular format.
For each help entry the first line must be a search string prefixed with a ~ character. This is used for the help functionality to find an entry and is not displayed. The ‘searchtext’ can contain ? for single character substitution or \* for multiple character (or none) substitution.
Following, the search string the next line would typically give the syntax of a particular command of function. Any subsequent lines would be further explanation.
{kn=1}e.g.
*~COLOR\nCOLOR fore [, back]\nSets the default color for commands (PRINT, etc)\nthat display on the screen.\n'fore' is the foreground colour, 'back' is the background colour.\nThe background is optional and if not specified will default to black.*
The command will return all entries that match the ‘searchtext’ and these will be paged to match the console device. Various versions of help.txt are available on <<https://www.thebackshed.com/forum/ViewTopic.php?FID=16&TID=17865>>
Without A:/help.txt the help built into MMBasic is used.  HELP then shows up to three lines of it that start with the text typed so far (‘searchtext’ and any characters typed after it, which can be deleted with backspace), and the up and down arrow keys move through the matches.  Esc or F12 ends the command.

=== HUMID pin, tvar, hvar [,DHT11]
or
DHT22 pin, tvar, hvar [,DHT11]
---
Returns the temperature and humidity using the DHT22 sensor.  Alternative versions of the DHT22 are the AM2302 or the RHT03 (all are compatible).
‘pin’ is the I/O pin connected to the sensor.  Any I/O pin may be used but it must not be configured: the command sets it up and returns it to the not configured state afterwards.
‘tvar’ is the variable that will hold the measured temperature and ‘hvar’ is the same for humidity.  Both must be present and both must be floating point variables.
For example:     `HUMID 3, TEMP!, HUMIDITY!`
Temperature is measured in ºC and the humidity is percent relative humidity.  Both will be measured with a resolution of 0.1.  If an error occurs (sensor not connected or corrupt signal) both values will be 1000.0.
Normally the signal pin of the DHT22 should be pulled up by a 1K to 10K resistor (4.7K recommended) to the supply voltage.  If the sensor is powered from 5V the pin must be 5V tolerant (see the pin table in the chapter *Hardware Features*).
The optional DHT11 parameter modifies the timings to work with the DHT11.  Set to 1 for DHT11 and 0 or omit for DHT22.  The DHT11 readings have a resolution of 1 degree and 1%.
DHT22 and BITBANG DHT22 are the older names of this command and are still accepted.  See the chapter *Special Device Support*.

=== I2C OPEN speed, timeout
--- keep

{}
Enables the first I^^2^^C channel (on the rear I/O connector) in master mode.  ‘speed’ is the clock speed (in KHz) to use and must be one of 100, 400 or 1000.
‘timeout’ is a value in milliseconds after which the master send and receive commands will be interrupted if they have not completed. The minimum value is 100. A value of zero will disable the timeout (though this is not recommended).

=+= I2C WRITE addr, option, sendlen, senddata [,senddata ..]
---
Send data to the I^^2^^C slave device. ‘addr’ is the slave’s I^^2^^C address.
‘option’ can be 0 for normal operation or 1 to keep control of the bus after the command: a stop condition will not be sent at the completion of the command, and the next command on the channel begins with a repeated start.
‘sendlen’ is the number of bytes to send (1 to 256).  ‘senddata’ is the data to be sent (all values sent will be between 0 and 255).  It may be supplied in any one of three forms:
{n=39 v=0}**A list of individual items**, one for each byte: constants, variables or expressions.  The number of items must equal ‘sendlen’ and array elements such as a(3) are allowed.\nExample:  `I2C WRITE &H6F, 0, 3, &H23, &H43, &H25`
{n=39 v=0}**A one dimensional array** of numbers specified with empty brackets.  ‘sendlen’ elements of the array will be sent starting with the first.\nExample:  `I2C WRITE &H6F, 0, 3, ARRAY()`
{n=39 v=0}**A string variable** (not a constant).  Its first ‘sendlen’ characters are sent; it must be at least that long.\nExample:  `I2C WRITE &H6F, 0, 3, STRING$`

=+= I2C READ addr, option, rcvlen, rcvbuf [,rcvbuf ..]
---
Get data from the I^^2^^C slave device. ‘addr’ is the slave’s I^^2^^C address.
‘option’ can be 0 for normal operation or 1 to keep control of the bus after the command (a stop condition will not be sent at the completion of the command).
‘rcvlen’ is the number of bytes to receive.
‘rcvbuf’ is the destination for the received data.  It may be supplied in any one of three forms:
{n=39 v=0}**A list of individual numeric variables**, one for each byte received.  The number of variables must equal ‘rcvlen’ and array elements such as a(3) are allowed.  A single variable is a list of one: ‘rcvlen’ must then be 1.
{n=39 v=0}**A one dimensional array** of numbers specified with empty brackets.  Received bytes will be stored in sequential elements of the array starting with the first.\nExample:  `I2C READ &H6F, 0, 3, ARRAY()`
{n=39 v=0}**A string variable.**  Received bytes will be stored as sequential characters and the string will be set to ‘rcvlen’ characters (so ‘rcvlen’ can be no more than 255, or than a LENGTH given to the string).

=+= I2C CLOSE

=== IF expr THEN stmt [: stmt]
or
IF expr THEN stmt ELSE stmt
--- keep
Evaluates the expression ‘expr' and performs the statement following the THEN keyword if it is true or skips to the next line if false.  If there are more statements on the line (separated by colons (:) they will also be executed if true or skipped if false.  The ELSE keyword is optional and if present the statement(s) following it will be executed if 'expr' resolved to be false.  
The ‘THEN statement’ construct can be also replaced with:\nGOTO linenumber | label’.
This type of IF statement is all on one line.

=== IF expression THEN \n   <statements>\n[ELSEIF expression THEN\n   <statements>]\n[ELSE\n   <statements>]\nENDIF
--- keep
Multiline IF statement with optional ELSE and ELSEIF cases and ending with ENDIF.   Each component is on a separate line.
Evaluates 'expression' and performs the statement(s) following THEN if the expression is true or optionally the statement(s) following the ELSE statement if false.  The ELSEIF statement (if present) is executed if the previous condition is false and it starts a new IF chain with further ELSE and/or ELSEIF statements as required.  One ENDIF is used to terminate the multiline IF. 

=== IMAGE
--- keep
The IMAGE commands resize, rotate and warp a rectangular part of the image on a page.  The image is read from the write page, or from the page given by ‘page’, and written to the write page as specified by the PAGE WRITE command.  ‘page’ can also be FRAMEBUFFER to read from the framebuffer (see the FRAMEBUFFER command).
The area read must lie within the page it is read from and the top left corner of the area written must lie on the write page.  If ‘flag’ is set to 1 then black pixels are not written.
The IMAGE commands are not available in the 4 and 1-bit colour depths ("Invalid for this screen mode").

=+= IMAGE RESIZE x, y, width, height, new_x, new_y, new_width, new_height [, page] [, flag]
or
IMAGE RESIZE_FAST x, y, width, height, new_x, new_y, new_width, new_height [, page] [, flag]
--- keep
Takes the part of the image with its top left corner at ‘x’, ‘y’ and of the specified ‘width’ and ‘height’ and resizes it, writing it to the area specified by ‘new_x’, ‘new_y’, ‘new_width’ and ‘new_height’, which must lie on the write page.  The command will both increase and decrease the size of the part of the image chosen.
IMAGE RESIZE uses bi-linear interpolation to generate the new pixels.  IMAGE RESIZE_FAST uses a nearest neighbour technique and is much faster but the resulting image quality will not be as good.

=+= IMAGE ROTATE x, y, width, height, new_x, new_y, angle! [, page] [, flag]
or
IMAGE ROTATE_FAST x, y, width, height, new_x, new_y, angle! [, page] [, flag]
--- keep
Takes the part of the image with its top left corner at ‘x’, ‘y’ and of the specified ‘width’ and ‘height’ and rotates it about its centre in a clockwise direction by ‘angle’ (in degrees).  Areas of the image that after rotation are outside of the area specified are cropped.  The image is then drawn with its top left corner at ‘new_x’, ‘new_y’.
IMAGE ROTATE uses bi-linear interpolation to rotate the image.  IMAGE ROTATE_FAST uses a nearest neighbour technique and is much faster but the resulting image quality will not be as good.

=+= IMAGE WARP_H x, y, w, h, x1, y1, h1, x2, y2, h2 [, page] [, flag]
or
IMAGE WARP_V x, y, w, h, x1, y1, w1, x2, y2, w2 [, page] [, flag]
---
These commands allow you to modify an image by translating and/or stretching or compressing one of the axes: the rectangle read is drawn as a trapezoid.
‘x’, ‘y’, ‘w’ and ‘h’ define the top left corner and the width and height of the area to read.  In both cases ‘x1’ and ‘y1’ define the top left corner of the area to write.
IMAGE WARP_H warps horizontally: the area written runs from ‘x1’ across to ‘x2’ (which must be to the right of ‘x1’), ‘h1’ and ‘h2’ are its heights at its left and right edges, and ‘x2’, ‘y2’ is the top of its right edge (its top right corner).
IMAGE WARP_V warps vertically: the area written runs from ‘y1’ down to ‘y2’ (which must be below ‘y1’), ‘w1’ and ‘w2’ are its widths at its top and bottom edges, and ‘x2’, ‘y2’ is the left end of its bottom edge (its bottom left corner).

=== INC var [,increment]
--- keep
Increments the variable “var” by either 1 or, if specified, the value in increment. “increment” can be negative which will decrement. 
This is functionally the same as `var = var + increment `but is processed much faster
If “var” is a string variable “increment” must be given and must be a string, which is appended to “var” (as CAT does).  The error is "String too long" if the result is longer than the variable can hold.

=== INPUT ["prompt$";] var1 [,var2 [, var3 [, etc]]]
--- keep
Will take a list of values separated by commas (,) entered at the console and will assign them to a sequential list of variables.
For example, if the command is:  INPUT a, b, c
And the following is typed on the keyboard:  23, 87, 66
Then a = 23 and b = 87 and c = 66
The list of variables can be a mix of float, integer or string variables.  The values entered at the console must correspond to the type of variable.
If a single value is entered a comma is not required (however that value cannot contain a comma).
‘prompt$’ is a string constant (not a variable or expression) and if specified it will be printed first.  Normally the prompt is terminated with a semicolon (;) and in that case a question mark will be printed following the prompt.  If the prompt is terminated with a comma (,) rather than the semicolon (;) the question mark will be suppressed.

=== INPUT #nbr,\nlist of variables
--- keep
Same as above except that the input is read from a serial port or file previously opened for INPUT as ‘nbr’.  See the OPEN command.

=== INTERRUPT [myint]
--- keep
This command triggers a software interrupt. The interrupt is set up using INTERRUPT ‘myint’ where ‘myint’ is the name of a subroutine that will be executed when the interrupt is triggered. 
Use INTERRUPT 0 to disable the interrupt
Use INTERRUPT without parameters to trigger the interrupt.
Note: the interrupt can also be triggered from within a CSUB

=== IR dev, key, int
or
IR CLOSE
---
Decodes NEC or Sony infrared remote control signals.
An IR Receiver Module is required to sense the IR light and demodulate the signal.  It is soldered to the pads for it on the motherboard (see IR Receiver in the chapter *Hardware Features*), which are connected to pin 41, and this command sets that pin up.
The IR signal decode is done in the background and the program will continue after this command without interruption.  ‘dev’ and ‘key’ should be numeric variables and their values will be updated whenever a new signal is received (‘dev’ is the device code transmitted by the remote and ‘key’ is the key pressed).  They must be global (or STATIC), not LOCAL, as they are set in the background.
‘int’ is a user defined subroutine that will be called when a new key press is received or when the existing key is held down for auto repeat.  In the interrupt subroutine the program can examine the variables ‘dev’ and ‘key’ and take appropriate action.
The IR CLOSE command will terminate the IR decoder.
Note that for the NEC protocol the bits in ‘dev’ and ‘key’ are reversed.  For example, in ‘key’ bit 0 should be bit 7, bit 1 should be bit 6, etc.  This does not affect normal use but if you are looking for a specific numerical code provided by a manufacturer you should reverse the bits.  This describes how to do it: <<http://www.thebackshed.com/forum/forum_posts.asp?TID=8367>>
See the chapter *Special Device Support* for more details.

=== IR SEND pin, dev, key
--- keep
Generate a 12-bit Sony Remote Control protocol infrared signal.
'pin' is the I/O pin to use.  This can be any I/O pin which will be automatically configured as an output and should be connected to an infrared LED.  Idle is low with high levels indicating when the LED should be turned on. 
'dev' is the device being controlled and is a number from 0 to 31, 'key' is the simulated key press and is a number from 0 to 127.
The IR signal is modulated at about 38KHz and sending the signal takes about 25mS during which program execution is paused.

=== IRETURN
--- keep
Returns from an interrupt routine.  An interrupt routine is normally a defined subroutine which is terminated with END SUB, however an interrupt can also be specified as a line number or a label and in that case the interrupt code must be terminated with IRETURN.

=== KEYBOARD ON
or
KEYBOARD OFF
---
Shows or hides the on-screen keyboard (see OPTION SCREEN KEYBOARD and the chapter Keyboard, Mouse and Gamepad), as on the PicoMite.  The keyboard is shown at the command prompt and in the editor and the file manager, and taken away while a program runs.  In a program KEYBOARD ON shows it, so that a USB touch screen types into INKEY$, INPUT and the like, and KEYBOARD OFF takes it away again; when the program ends the keyboard is as it was at RUN.  At the command prompt KEYBOARD OFF keeps it away until KEYBOARD ON or a restart.
OPTION SCREEN KEYBOARD must have been set first ("Set OPTION SCREEN KEYBOARD first"), and the keyboard is not available in MODE n,1 ("Invalid for this screen mode").  Under OPTION PICOMITE, MM.INFO(KEYBOARD) returns "On" while a program has it on.

=== KILL file$ [, ALL]
--- keep
Deletes the file (or empty directory) specified by ‘file$’ on the SD card or USB flash drive. Any extension must be specified.  
Bulk erase is triggered if ‘file$’ contains a '\*' or a '?' character: every file that matches is deleted (directories, hidden and system files are left alone), and this can only be done at the command prompt.  If ALL is added you will be prompted for a single confirmation.  If ALL is not specified you will be prompted on each file.

=== LET variable = expression
--- keep
Assigns the value of 'expression' to the variable.  LET is automatically assumed if a statement does not start with a command.  For example:
{b=0 l=720}`Var = 56`
A whole array can be copied into another array by using the array names with empty brackets.  For example:
{b=0 l=720}`b%() = a%()`
Both arrays must be the same type (for strings, also the same maximum length) and must hold the same total number of elements; the dimensions may differ (eg, a 2 x 3 array can be copied into a six element array).  The source can also be a user defined function that returns an array (see the FUNCTION command).

=== LIBRARY
--- tight
The library is a second program whose subroutines, functions, embedded C routines (CSUBs), fonts, labels and DATA statements are available to every program, as if they were part of MMBasic: they do not show when the program is listed or edited and are not deleted when a new program is loaded or by NEW.  Any code in the library that is not in a subroutine or function is run before each program, which can be used to set constants, options, etc.  See The Library in the chapter Using MMBasic.
The library is kept in the last 128KB of the program flash memory (flash slot 6, see OPTION FLASH), which cannot then be used for a program, and it can be up to 128KB long.  A program can also load a library of its own into RAM (LIBRARY LOAD with RAM).

=+= LIBRARY SAVE
--- tight
Adds the program in program memory (the program last run, or loaded from the editor or AUTOSAVE with F1) to the library, compressed: its comments, blank lines and unnecessary spaces are removed and the hex codes of its CSUBs and fonts are kept as binary.  Program memory is then cleared, as by NEW.  LIBRARY SAVE can be used again to add more routines to the library.  It can only be used at the command prompt.

=+= LIBRARY DELETE
--- tight
Deletes the library and returns its flash memory for normal use (OPTION RESET does not delete it).  It can only be used at the command prompt.

=+= LIBRARY LIST
or
LIBRARY LIST ALL
--- tight
Lists the library (the RAM library while there is one), with a pause at every screen full.  ALL lists without pauses.  It can only be used at the command prompt.

=+= LIBRARY DISK SAVE file$
or
LIBRARY DISK LOAD file$
--- tight
LIBRARY DISK SAVE saves the library (the RAM library while there is one) to the file ‘file$’ as a binary image, and LIBRARY DISK LOAD loads such a file into the library in the flash memory, replacing the library there.  ".LIB" is added to ‘file$’ if it has no extension.  Together these allow a library to be kept with the programs that use it, and to be distributed.  They can only be used at the command prompt.

=+= LIBRARY LOAD file$ [, file$ ...] [, O] [, RAM]
--- tight
Reads one or more BASIC source files (up to eight, joined in the order given; ".BAS" is added to a name without an extension), compresses them and installs them as the library, replacing whatever was there.  Unlike LIBRARY SAVE it can be used in a program, so that a program can bring its own library rather than requiring the user to install it first.  It must then be the first statement in the program: once the library is installed the program is restarted, so that the library's own initialisation code runs before the program proper.  A hash of the source files is remembered, so if the library already holds those exact files the command does nothing and no flash is written: a program can therefore use it on every run at no cost.
If a different library is already in the flash memory MMBasic asks for confirmation before replacing it; the option O (or OVERWRITE) suppresses the question.  A bare O, OVERWRITE or RAM in the list is the option of that name rather than a file name: a file name is always a string expression, so a quoted "O" is a file name.  Nothing is written until every file has been read, so a mistyped name leaves the existing library untouched.
With RAM the library goes into RAM instead of the flash memory, which is left exactly as it was: the RAM library takes the place of the flash library until the program ends (END, or running off its last line) or the next RUN, NEW, CHAIN or program load, so a program loads it every time it starts.  No question is asked and O is not needed.

=== LINE  x1, y1, x2, y2 [,[-] LW [, C]]
--- keep
Draws a line on the display starting at the coordinates ‘x1’ and ‘y1’ and ending at ‘x2’ and ‘y2’.\n‘LW’ is the line’s width. It defaults to 1 if not specified. For lines that have a defined width and the x1 and y1 coordinate define the top-left pixel of the thick line. i.e. the line is to the right of the specified position or below it on the screen.\nIf width is given as a -ve value then width will apply to lines in all directions and they are centred on the given origin and destination coordinates.\n‘C’ is an integer representing the colour and defaults to the current foreground colour.\nAll parameters can be expressed as arrays and the software will plot the number of lines as determined by the dimensions of the smallest array. 'x1', 'y1', 'x2', and 'y2' must all be arrays or all be single variables /constants otherwise an error will be generated.  'lw' and 'c' can be either arrays or single variables/constants.

Draws a line with anti-aliasing . The parameters are as per the LINE command above. However this version will use variable intensity values of the specified colour to reduce the “staggered” quality of diagonal lines. In addition this version can draw diagonal lines of any width.  Note that it does not accept arrays as parameters.

=== LINE PLOT ydata() [,nbr] [,xstart] [,xinc] [,ystart] [,yinc] [,colour]

Plots a line graph from an array of y-axis data points.
‘ydata()’ is an array of floats or integers to be plotted

=== LOAD BMP file$ [,x] [,y] [,mode] [,ximage] [,yimage]
or
LOAD IMAGE file$ [,x] [,y] [,mode] [,ximage] [,yimage]
---
Loads a BMP image from ‘file$’ and draws it on the current write page with its top left corner at ‘x’, ‘y’ (0, 0 if they are not specified).  If an extension is not specified “.BMP” will be added to the file name.
All the usual types of the BMP format are supported including black and white and true colour 24-bit images: 1, 4, 8, 16 and 24 bits a pixel, uncompressed or RLE encoded.  The image can be up to 3840 x 2160 pixels and positioned anywhere: pixels that end up off the screen are ignored.
‘ximage’ and ‘yimage’ specify the pixel of the image that is drawn at ‘x’, ‘y’ (0, 0 if they are not specified), so that a part of a large image can be shown.
‘mode’ (-1 to 7) is accepted so that the PicoMite's programs run: there it chooses a dither, here the image is drawn in the colour depth of the screen and ‘mode’ is not used.  LOAD IMAGE is the PicoMite's name for LOAD BMP.

If an extension is not specified “.FNT” will be added to the file name.  A program can load many fonts this way during the course of its execution but each new font replaces the one loaded before.

GIFs can be a single image or animated.  If it is animated it will start playing in the background (ie, program execution will continue while it is playing) and repeat until it is stopped.  If an animated GIF is already running it will be replaced by the new one.  If LOAD GIF is used without any parameters it will stop the currently playing animated GIF.

=== LOAD JPG file$ [,x] [,y] [,mode] [,ximage] [,yimage] [,scale]
---
Loads a JPG image from ‘file$’ and draws it on the current write page with its top left corner at ‘x’, ‘y’ (0, 0 if they are not specified), which must be on the screen; the image is cropped at the right and bottom edges of the screen.  If an extension is not specified “.JPG” will be added to the file name.  Progressive JPG images are not supported.
‘ximage’ and ‘yimage’ specify the pixel of the image that is drawn at ‘x’, ‘y’ (0, 0 if they are not specified), so that a part of a large image can be shown.  They must be within the image.
‘scale’ reduces the displayed size of the image by pixel averaging: use 2 for 50% (each output pixel is the average of a 2x2 block of source pixels), 4 for 25% (a 4x4 block) or 8 for 12.5%.  The default is 1 which displays the image at full size.
The optional ‘mode’ parameter dithers the image to fewer colours, which can give a better picture in the 4 and 8-bit colour depths.  Bits 0 and 1 specify the colours and bit 2 the type of dithering:
{l=720}-1 = no dithering (the default)
{l=720}0 = Floyd-Steinberg to RGB121 (the colours of the 4-bit colour depth)
{l=720}1 = Floyd-Steinberg to RGB222
{l=720}2 = Floyd-Steinberg to RGB332 (the colours of the 8-bit colour depth)
{l=720}4 = Atkinson to RGB121
{l=720}5 = Atkinson to RGB222
{l=720}6 = Atkinson to RGB332

=== LOAD PNG file$ [,x] [,y] [,t] [,cutoff] [,ximage] [,yimage]
---
Loads a PNG image from ‘file$’ and draws it on the current write page with its top left corner at ‘x’, ‘y’ (0, 0 if they are not specified).  If an extension is not specified “.PNG” will be added to the file name.  The image can be of any size and positioned anywhere: pixels off the screen are ignored, and as the image is decoded a line at a time a large image needs little memory.
The file can be an 8-bit RGB, RGBA (ARGB8888), grey or grey with alpha PNG, or an indexed (palette) one; interlaced files are not supported.
‘ximage’ and ‘yimage’ specify the pixel of the image that is drawn at ‘x’, ‘y’ (0, 0 if they are not specified), so that a part of a large image can be shown.  They must be within the image.
If ‘t’ is omitted or zero every pixel is drawn as a solid colour, as with any other image load.  If ‘t’ (1 to 15) is specified the transparency of the file decides which pixels are drawn: MMBasic compares the 4 most significant bits of each pixel's alpha value with ‘t’, a pixel below it is not drawn (so that what is under it shows through) and the others are drawn as solid colours.  This allows RGB(0,0,0) to be a valid solid colour.  ‘cutoff’ (1 to 254) sets the alpha value below which a pixel is not drawn directly, rounded down to a multiple of 16, in place of ‘t’.  A file without transparency (RGB or grey) is drawn with every pixel solid.
With OPTION PICOMITE ‘t’ and ‘cutoff’ are the PicoMite's: a pixel whose alpha is ‘cutoff’ or less (20 if it is not given) is drawn in colour ‘t’, one of the 16 colours of the 4-bit modes (0 to 15, 0 if it is not given), or is not drawn when ‘t’ is -1, and the other pixels are drawn as solid colours.

=== LONGSTRING
---
The LONGSTRING commands allow for the manipulation of strings longer than the normal MMBasic limit of 255 characters (see the chapter Long Strings).
Variables for holding long strings must be defined as single dimensioned integer arrays with the number of elements set to the number of characters required for the maximum string length divided by eight.  The reason for dividing by eight is that each integer in an MMBasic array occupies eight bytes.  The first element holds the length of the string.  The commands give an error ("Destination array too small", "Integer array too small" or a number out of bounds) rather than make a string longer than its array can hold.

=+= LONGSTRING AES128 ENCRYPT CBC/ECB/CTR key$/key(), in%(), out%() [, iv$/iv()]
or
LONGSTRING AES128 DECRYPT CBC/ECB/CTR key$/key(), in%(), out%()
---
Encrypts or decrypts the long string in ‘in%()’ with the AES-128 cipher, putting the result in ‘out%()’.  The length of ‘in%()’ must be a multiple of 16 bytes.  ‘key$’ is the key as a string of 16 characters, or ‘key()’ as an integer or floating point array of 16 elements holding values from 0 to 255.
For CBC and CTR modes the encryption will generate a random initialisation vector (IV) and prepend ‘out%()’ with the IV, so the result is 16 bytes longer.  If an explicit IV is specified (16 characters or elements, as for the key) this will be used instead of the random vector and this will be prepended to ‘out%()’.  ECB mode does not use an IV.
For CBC and CTR decryption the firmware assumes that the first 16 bytes of ‘in%()’ are the initialisation vector (an IV is not a parameter of DECRYPT).
In the case where you want to transmit a message without IV you can use LONGSTRING RIGHT to remove the IV before sending the message.  In this case the recipient must know the IV as well as the key and create a complete long string before using DECRYPT.  This can be done by using LONGSTRING CONCAT to add the incoming message to a long string containing the IV.

=+= LONGSTRING APPEND array%(), string$
--- keep
Append a normal MMBasic string to a long string variable.  ‘array%()’ is a long string variable while ‘string$’ is a normal MMBasic string expression.

=+= LONGSTRING BASE64 ENCODE in%(), out%()
or
LONGSTRING BASE64 DECODE in%(), out%()
--- keep
Encodes or decodes the long string in ‘in%()’ with BASE64, placing the result in ‘out%()’.  The array used for the output must be big enough for the result: encoding increases the length by 4/3 and decoding decreases it by 3/4.

=+= LONGSTRING CLEAR array%()
--- keep
Will clear the long string variable ‘array%()’, ie, it will be set to an empty string.

=+= LONGSTRING COPY dest%(), src%()
--- keep
Copy one long string to another.  ‘dest%()’ is the destination variable and ‘src%()’ is the source variable.  Whatever was in ‘dest%()’ will be overwritten.

=+= LONGSTRING CONCAT dest%(), src%()
--- keep
Concatenate one long string to another.  ‘dest%()’ is the destination variable and ‘src%()’ is the source variable.  ‘src%()’ will be added to the end of ‘dest%()’ (the destination will **not** be overwritten).

=+= LONGSTRING LCASE array%()
--- keep
Will convert any uppercase characters in ‘array%()’ to lowercase.  ‘array%()’ must be a long string variable.

=+= LONGSTRING LEFT dest%(), src%(), nbr
--- keep
Will copy the left hand ‘nbr’ characters from ‘src%()’ to ‘dest%()’ overwriting whatever was in ‘dest%()’, ie, copy from the beginning of ‘src%()’ (all of it if it is shorter).  ‘src%()’ and ‘dest%()’ must be long string variables.

=+= LONGSTRING LOAD array%(), nbr, string$
--- keep
Will copy the first ‘nbr’ characters of ‘string$’ (all of them if it is shorter) to the long string variable ‘array%()’, overwriting whatever was in ‘array%()’.

=+= LONGSTRING MID dest%(), src%(), start [, nbr]
--- keep
Will copy ‘nbr’ characters from ‘src%()’ to ‘dest%()’ starting at character position ‘start’, overwriting whatever was in ‘dest%()’, ie, copy from the middle of ‘src%()’.  ‘nbr’ is optional and if omitted the characters from ‘start’ to the end of the string will be copied.  ‘src%()’ and ‘dest%()’ must be long string variables.

=== MAP

The MAP commands set the colours used in the 8-bit and 4-bit colour depths.  Each value in the palette (0 to 255 in the 8-bit depth, 0 to 15 in the 4-bit depth) can be set to any 24-bit colour.  They are refused in the other colour depths (in the 1-bit depth the colours are the tiles': see TILE).

=+= MAP SET
--- keep
Updates the colour map (set with MAP( n ) = rgb%) during the next frame blanking interval.  The command waits for it.

=+= MAP RESET
--- keep
Resets the colour map to the default colours.

=+= MAP GREYSCALE
or
MAP GRAYSCALE
--- keep
Sets a colour map of shades and applies it at the next frame blanking interval.  In the 8-bit depth it makes eight ramps of 32 levels: grey (values 0 to 31), blue (32 to 63), green, cyan, red, magenta, yellow, and grey again (224 to 255).  In the 4-bit depth it makes 16 levels of grey.

In the 8-bit depth, sets the colour map to the colours of the original Colour Maximite (palette values 0 to 7 and 48 to 55) and applies it at the next frame blanking interval.

=== MATH SENSORFUSION type ax, ay, az, gx, gy, gz, [mx], [my], [mz], pitch, roll, yaw [,p1] [,p2]
---
Type can be MAHONY or MADGWICK
Ax, ay, and az are the accelerations in the three directions and should be specified in units of standard gravitational acceleration.  
Gx, gy, and gz are the instantaneous values of  rotational speed which should be specified in radians per second, or in degrees per second under OPTION ANGLE DEGREES.
Mx, my, and mz are the magnetic fields in the three directions and should be specified in nano-Tesla (nT). They can be omitted, keeping their commas (eg, gz, , , , pitch), in which case the fusion uses only the accelerometer and gyroscope and the yaw may slowly drift, but this allows sensors like the MPU-6050 to be used.  The magnetometer is used when mx is given.
Care must be taken to ensure that the x, y and z components are consistent between the three inputs. So , for example, using the MPU-9250 the correct input will be ax, ay,az, gx, gy, gz, my, mx, -mz based on the reading from the sensor.
Pitch, roll and yaw should be floating point variables and will contain the outputs from the sensor fusion, in radians, or in degrees under OPTION ANGLE DEGREES.
The SENSORFUSION routine will automatically measure the time between consecutive calls (in milliseconds, and at most one second) and will use this in its internal calculations.
The Madgwick algorithm takes an optional parameter p1. This is used as beta in the calculation. It defaults to 0.5 if not specified
The Mahony algorithm takes two optional parameters p1, and p2. These are used as Kp and Ki in the calculation. If not specified these default to 10.0 and 0.0 respectively.
A fully worked example of using the code is given on the BackShed forum at: <<https://www.thebackshed.com/forum/ViewTopic.php?TID=13459&PID=166962%23166962|https://www.thebackshed.com/forum/ViewTopic.php?TID=13459&PID=166962#166962>>

=== MATH AES128 ENCRYPT/DECRYPT CBC/ECB/CTR key$/key(), in$/in(), out$/out() [,iv$/iv()]
---
This command encrypts or decrypts the data in 'in' and puts the answer in 'out' using the AES128 encryption method specified
The parameters can each be either a string, integer array, or float array with any mix possible
The key must be 16 elements long (16\*8=128bits), in and out must be a multiple of 16 elements long.  In the case of out being specified as a string (e.g. out$), the string variable must exist and should be set to empty (DIM out$="")
The maximum number of elements in 'in' and 'out' is limited by memory when defined as arrays. Strings for encrypting are limited to 240bytes (ECB) and 224bytes (CTR and CBC).
For CBC and CTR encryption you can optionally specify an initialisation vector 'iv'. 'iv' must be 16 elements long (16\*8=128bits). If an initialisation vector is not specified encryption will generate a random initialisation vector.
In both cases the output is prepended with the IV.
For CBC and CTR, decryption requires that the first 16 elements of the input are the initialisation vector.
In the case where you want to transmit a message without IV you should remove the IV before sending the message using standard MMBasic manipulations. In this case the recipient must know the IV as well as the key and create a complete message before using DECRYPT by prepending the IV to the incoming message.

=== MEMORY PACK source%()/sourceaddress%, dest%()/destaddress%, number, size
{}

---
Memory pack and unpack allow integer values from one array to be compressed into another or uncompressed from one to the other.
The two arrays are always normal integer arrays but the packed array can have 2, 4, 8, 16 or 64 values “packed into them. Thus a single integer array element could store 2 off 32-bit words, 4 off 16 bit values, 8 bytes, 16 nibbles, or 64 booleans (bits). 
“number specifies the number of values to be packed or unpacked and “size” specifies the number of bits (1,4,8,16,or 32)
Alternatively,  memory address(es) can be used in which case no checking can take place and user errors could result in a crash of the firmware.

=== MID$( str$, start [, num]) = str2$
--- keep roomy

=== MMDEBUG [expression [[,; ]expression] …]
or
MMDEBUG BREAK
--- keep
A command for debugging a program that costs nothing when it is not wanted.  When a program is loaded (by RUN, or by F1 or F2 in the editor or AUTOSAVE), a line that starts with MMDEBUG is dropped, as a comment is, unless the directive #MMDEBUG ON has come before it in the program; #MMDEBUG OFF drops the lines that follow it again.  So MMDEBUG commands can be left throughout a program while it is developed and turned on or off with one line.  An #INCLUDE file starts with the setting in force at its #INCLUDE.
MMDEBUG on its own or with a list of expressions acts exactly like PRINT.
MMDEBUG BREAK stops the program and shows the prompt DEBUG>.  Any command can then be entered as at the command prompt, to print or change variables, call subroutines and so on: commands that make sense at the command prompt (not GOTO, for example).  The command CONTINUE leaves this mode and the program carries on after the MMDEBUG BREAK.

=== MODE r [, bits [, bg [, int]]]
---
Sets the resolution and the colour depth of the VGA video output.
‘r’ is the screen resolution.  It is a number from 1 to 18 as follows:
{b=0 a=0 l=720}1 = 800 x 600 pixels (the default)
{b=0 a=0 l=720}2 = 640 x 400 pixels
{b=0 a=0 l=720}3 = 320 x 200 pixels
{b=0 a=0 l=720}4 = 480 x 432 pixels
{b=0 a=0 l=720}5 = 240 x 216 pixels
{b=0 a=0 l=720}6 = 256 x 240 pixels
{b=0 a=0 l=720}7 = 320 x 240 pixels
{b=0 a=0 l=720}8 = 640 x 480 pixels
{b=0 a=0 l=720}9 = 1024 x 768 pixels
{b=0 a=0 l=720}10 = 848 x 480 pixels (widescreen format)
{b=0 a=0 l=720}11 = 1280 x 720 pixels (widescreen format)
{b=0 a=0 l=720}12 = 960 x 540 pixels (widescreen format, lines duplicated)
{b=0 a=0 l=720}13 = 400 x 300 pixels
{b=0 a=0 l=720}14 = 960 x 540 pixels (widescreen format, lines not duplicated: not supported by all monitors)
{b=0 a=0 l=720}15 = 1280 x 1024 pixels
{b=0 a=0 l=720}16 = 1920 x 1080 pixels (widescreen format, Generation 2 with the Rev V processor only)
{b=0 a=0 l=720}17 = 384 x 240 pixels
{b=0 a=0 l=720}18 = 1024 x 600 pixels
All resolutions except 10, 11, 12, 14 and 16 work perfectly with monitors that have an aspect ratio of 4:3 or widescreen monitors that can switch to that ratio (most widescreen monitors will do this automatically).
‘bits’ is the colour depth.  It can be 1, 4, 8, 12, 16 or 32 and is 8 if it is left out:
{b=0 a=0 l=720}1 = a bit a pixel, eight pixels to a byte, each in its tile's colours: the PicoMite's MODE 1 (see below)
{b=0 a=0 l=720}4 = RGB121, 16 colours, two pixels to a byte: the PicoMite's 16 colour display (see below)
{b=0 a=0 l=720}8 = RGB332, 256 colours, each of which can be changed with the MAP command
{b=0 a=0 l=720}12 = ARGB4444, 4096 colours with 16 levels of transparency, in two layers over a background colour
{b=0 a=0 l=720}16 = RGB565, 65,536 colours
{b=0 a=0 l=720}32 = ARGB8888, 16,777,216 colours (Generation 2 only)
Not every combination is available: modes 9, 11 and 12 have no 12 or 32-bit depth, modes 15 and 16 have the 8 and 1-bit depths only, and the 4-bit depth is not available in modes 9, 11, 12, 15, 16 and 18.  The 1-bit depth is available in every mode.  With OPTION LEGACY ON only the 8-bit depth can be used.
‘bg’ is the background colour and can be used in the 12-bit depth.  If the pixels in page 0 (the lower layer) are not set to solid (transparency = 15) then the background will show through as determined by the transparency value of the pixel.  This parameter is ignored in the other depths.
‘int’ is a subroutine that will be called at the start of each frame blanking (useful for updating the screen without tearing).  A MODE command without it cancels the interrupt.  To give ‘int’ without a background colour leave ‘bg’ out (MODE r, bits, , int) or give 0.
MODE sets the colours to white on black and the default font for the resolution: font 7 in modes 3, 5, 6, 7, 13 and 17, font 4 in modes 9, 11, 15 and 18, font 3 in mode 16 and font 1 in the others.  When it changes the resolution or the colour depth it also clears the screen and makes page 0 the write page.  A change of colour depth also closes the sprites and deletes a cursor loaded by GUI CURSOR LOAD, as they are held in the pixel format of the old depth.
A program is started (RUN) in the default mode, MODE 1 or the mode set by OPTION DEFAULT MODE with the 8-bit depth, and the display returns to it when the program ends.
The display always shows the contents of page 0 (pages 0 and 1 in the 12-bit depth, page 1 being the upper layer) unless overridden with the PAGE DISPLAY command.  Use PAGE WRITE and PAGE COPY to avoid the artefacts of flashing and tearing.  The pages available in each mode and colour depth, and how to PEEK and POKE them, are listed in the chapter Video Modes and Pages.  MM.INFO(MAX PAGES) returns the highest page number in the current mode.
The 4-bit depth gives the display of the PicoMite's VGA and HDMI versions in their 16 colour modes: MODE 7,4 (320 x 240) is the PicoMite's MODE 2 and MODE 8,4 (640 x 480) is its MODE 3.  Its 16 colours can be changed with MAP and its FRAMEBUFFER command is the PicoMite's (see FRAMEBUFFER).  PAGE DISPLAY and the IMAGE commands are not available in it.
With OPTION PICOMITE VGA or HDMI, MODE with no colour depth is the PicoMite's MODE (1 to 3 for VGA, 1 to 5 for HDMI), and always clears the screen: see Running PicoMite Programs in the chapter Video Modes and Pages.  MODE with a colour depth is the Colour Maximite 2's.
The 1-bit depth gives the PicoMite's MODE 1: MODE 8,1 (640 x 480) is the PicoMite's MODE 1 on its VGA version and at 640 x 480 on its HDMI version.  A pixel is set or clear, and the screen is divided into tiles 8 pixels wide and TILE HEIGHT tall, each with a foreground colour for its set pixels and a background colour for the others (see TILE).  Its FRAMEBUFFER command is the PicoMite's.  MAP, PAGE DISPLAY, the IMAGE commands, GUI CURSOR and RAY are not available in it.  MODE r,1 clears the screen and resets the tiles even when that mode is already set, as the PicoMite's MODE does.

=== MOUSE INTERRUPT ENABLE channel, int
or
MOUSE INTERRUPT DISABLE channel
or
MOUSE SET channel, x, y [, wheel]
---
These commands act on the mouse in use, which a program reads as channel 2 (see the chapter *Keyboard, Mouse and Gamepad* and the DEVICE(MOUSE ...) function).  ‘channel’ can be 1 to 4 for MOUSE INTERRUPT, where it is not used, and must be 2 for MOUSE SET.
MOUSE INTERRUPT ENABLE sets ‘int’, a user defined subroutine that will be called whenever a button of a USB mouse is pressed or released, and when the left button is double clicked.  MOUSE INTERRUPT DISABLE disables it.  For a PS2 or I^^2^^C mouse see CONTROLLER MOUSE OPEN.
MOUSE SET sets the position that the mouse will report: ‘x’ (0 to MM.HRES-1), ‘y’ (0 to MM.VRES-1) and optionally the wheel count (-1000000 to 1000000).  The error is "No mouse" if no mouse is connected or open.

=== ON ERROR ABORT
or
ON ERROR IGNORE
or
ON ERROR SKIP [nn]
or
ON ERROR CLEAR
or
ON ERROR RESTART
---
This controls the action taken if an error occurs while running a program and applies to all errors discovered by MMBasic including syntax errors, wrong data, missing hardware, etc.
ON ERROR ABORT will cause MMBasic to display an error message, abort the program and return to the command prompt.  This is the normal behaviour and is the default when a program starts running.
ON ERROR RESTART will cause MMBasic to restart the Colour Maximite 2 when an error occurs and, of course, if you have OPTION AUTORUN set the program will then restart cleanly
ON ERROR IGNORE will cause any error to be ignored.
ON ERROR SKIP will ignore an error in a number of commands (specified by the number 'nn') executed following this command.  'nn' is optional (1 to 10000), the default if not specified is one.  After the number of commands has completed (with an error or not) the behaviour of MMBasic will revert to ON ERROR ABORT.
If an error occurs and is ignored/skipped the read only variable MM.ERRNO will be set to non zero, MM.ERRMSG$ will be set to the error message that would normally be generated and MM.ERRLINE to the number of the line.  These are reset to zero and an empty string by ON ERROR CLEAR.  They are also cleared when the program is run and when ON ERROR IGNORE, SKIP and RESTART are used.
ON ERROR IGNORE can make it very difficult to debug a program so it is strongly recommended that only ON ERROR SKIP be used.

=== ON KEY target 
or 
ON KEY ASCIIcode, target
---
The first version of the command sets an interrupt which will call 'target' user defined subroutine whenever there is one or more characters waiting in the console input buffer (typed on the USB keyboard or received from the serial console). 
Note that all characters waiting in the input buffer should be read in the interrupt subroutine otherwise another interrupt will be automatically generated as soon as the program returns from the interrupt.   
The second version allows you to associate an interrupt routine with a specific key press (‘ASCIIcode’ is 1 to 255). This operates at a low level for both the USB keyboard and the serial console and if activated the key does not get put into the input buffer but merely triggers the interrupt. It uses a separate interrupt from the simple ON KEY command so can be used at the same time if required. 
In both variants, to disable the interrupt use numeric zero for the target, i.e.:  
ON KEY 0. or ON KEY ASCIIcode, 0

=== ON nbr GOTO | GOSUB target [, target, target…]
--- keep
ON either branches (GOTO) or calls a subroutine (GOSUB) depending on the rounded value of 'nbr': if it is 1 the first target is used, if it is 2 the second target, and so on.  Each target can be a line number or a label.
If 'nbr' is zero or greater than the number of targets the program carries on with the next command.  'nbr' must be between 0 and 255.
ON ... GOSUB nests as GOSUB does and the subroutine must be terminated with RETURN.  This is a legacy command; SELECT CASE and defined subroutines are recommended for new programs.

=== ONEWIRE RESET pin
or
ONEWIRE WRITE pin, flag, length, data [, data…]
or
ONEWIRE READ pin, flag, length, data [, data…]
---
Commands for communicating with 1-Wire devices.
ONEWIRE RESET will reset the 1-Wire bus
ONEWIRE WRITE will send a number of bytes
ONEWIRE READ will read a number of bytes
'pin' is the I/O pin (located in the rear connector) to use.  It can be any pin capable of digital I/O.
'flag' is a combination of the following options:
{b=0 a=0}1 - Send reset before command
{b=0 a=0}2 - Send reset after command
{b=0 a=0}4 - Only send/recv a bit instead of a byte of data
{b=0 a=0}8 - Invoke a strong pullup after the command (the pin will be set high and open drain disabled)
'length' is the length of data to send or receive
'data' is the data to send or variable to receive.  The data to send (WRITE) or the destination for received data (READ) may be supplied in any one of three forms:
{n=39 v=0}**A list of individual items.** The number of items must equal the length parameter. For WRITE each item is a constant, variable or expression; for READ each item is a numeric variable to receive one value. Array elements such as a(3) are allowed.
{n=39 v=0}**An array**, specified with empty brackets, e.g. array(). It may be a floating-point or integer array and must be large enough to supply (WRITE) or hold (READ) the specified number of elements, which are taken from / stored into consecutive elements starting at the first.
{n=39 v=0}**A string variable.** For WRITE the first length characters are sent (the string must be at least that long); for READ the received bytes are stored as sequential characters and the string is set to that length.
See also *Appendix C*.

=== OPEN fname$ FOR mode AS [#]fnbr
---
Opens a file for reading or writing.
‘fname’ is the filename with an optional extension separated by a dot (.).  Long file names with upper and lower case characters are supported.  The file systems on both the SD Card and the flash drives are NOT case sensitive.
A directory path can be specified with the backslash as directory separators.  The parent of the current directory can be specified by using a directory name of “..” (two dots) and the current directory with “.” (a single dot).
For example: OPEN ".\\dir1\\dir2\\filename.txt" FOR INPUT AS #1
‘mode’ is INPUT, OUTPUT, APPEND or RANDOM.
INPUT will open the file for reading and throw an error if the file does not exist.  OUTPUT will open the file for writing and will automatically overwrite any existing file with the same name.  
APPEND will also open the file for writing but it will not overwrite an existing file; instead any writes will be appended to the end of the file.  If there is no existing file the APPEND mode will act the same as the OUTPUT mode (i.e. the file is created then opened for writing).
RANDOM will open the file for both read and write and will allow random access using the SEEK command.  When opened the read/write pointer is positioned at the end of the file.  If the file does not exist , it will be created.
‘fnbr’ is the file number (1 to 10).  The # is optional.  Up to 10 files can be open simultaneously and can be on either or both the A: and B: drives.  The INPUT, LINE INPUT, PRINT, WRITE and CLOSE commands as well as the EOF() and INPUT$() functions all use ‘fnbr’ to identify the file being operated on.
See also ON ERROR and MM.ERRNO for error handling.

=== OPEN comspec$ AS [#]fnbr
--- keep
{t=l2592}Will open a serial communications port for reading and writing.  COM1: and COM2: are on the rear I/O connector.  COM3: is the port of the serial console (on the USB connector used for power) and can be opened when the serial console is disabled with OPTION CONSOLE SCREEN.  COM4: to COM7: are USB serial devices plugged into the USB connector (see the chapter *Keyboard, Mouse and Gamepad*).
‘comspec$’ is the communication specification, a string of the form "COMn: baud, buf, int, int-trigger, tx-int" followed by any of the options DEP or DEN, 7BIT, ODD or EVEN, INV, OC and S2.  The default is 9600 baud (the minimum is 1200), a receive buffer of 1024 bytes, 8 data bits, no parity and one stop bit.  DEP and DEN (RS485 mode, using the COM1 DE pin, pin 37) are available on COM1: only, and INV, OC, DEP and DEN do not apply to COM4: to COM7:.  For a full description with examples see *Appendix A*.
‘fnbr’ is the file number (1 to 10).  Using ‘fnbr’ the port can be written to and read from using any command or function that uses a file number, and it is closed with CLOSE.

=== OPEN comspec$ AS GPS [, timezone_offset] [, monitor]
---
{t=l2592}Will open a serial communications port (COM1: to COM7:) for reading from a GPS receiver.  ‘comspec$’ is as for the OPEN command above.  The data can then be retrieved using the GPS() function.  The sentences interpreted are GPRMC, GNRMC, GPGGA and GNGGA (those with a correct checksum).
The ‘timezone_offset’ parameter is used to convert UTC as received from the GPS to the local timezone.  If omitted the timezone will default to UTC.  The ‘timezone_offset’ is in hours and can be any number between -12 and 14 allowing the time to be set correctly even for the Chatham Islands in New Zealand (UTC +12:45, an offset of 12.75).
If the ‘monitor’ parameter is set to 1 then all GPS input is also directed to the console.  This can be stopped by closing the GPS channel.
The port takes the first free file number.  It is closed with CLOSE GPS, and PRINT #GPS sends a sentence to the receiver.

=== PAGE
--- keep
The PAGE commands manage the video pages.  Building an image on a page that is not displayed and then copying it to the display page avoids flashing and tearing.  The pages available in each mode and colour depth are listed in the chapter Video Modes and Pages, and MM.INFO(MAX PAGES) returns the highest page number in the current mode.
In the 4 and 1-bit colour depths only PAGE WRITE, PAGE COPY and PAGE SCROLL are available (the others give the error "Invalid for this screen mode").  There pages 0 to 4 are the PicoMite's framebuffers N, L, F, 2 and T (see the FRAMEBUFFER command).

=+= PAGE WRITE n
or
PAGE WRITE FRAMEBUFFER
--- keep
Instructs MMBasic to make all graphics commands write to page ‘n’.  If not used page 0 is the default.  MM.HRES and MM.VRES report the size of the write page.
Set the page to FRAMEBUFFER to write to the framebuffer: see the FRAMEBUFFER command.

=+= PAGE DISPLAY n [, layer]
or
PAGE DISPLAY -1
---
Selects the page that is displayed on the screen (this does not change the write page).  For example:
{l=720}`PAGE DISPLAY 3`
will display the current contents of page 3.  In the 12-bit depth ‘layer’ can be 1 to select the page that is to be displayed as the top layer, for example:
{l=720}`PAGE DISPLAY 4, 1`
‘layer’ 0, the default, is the lower layer.  The command executes in the next frame blanking period.  When a program ends for any reason page 0 is displayed again.
In modes 3, 5, 6, 7, 12, 13 and 17 only pages 0 and 1 (pages 0, 1 and 2 in the 12-bit depth) can be displayed, as only they hold each line twice.  A page must also lie in the first 3 MB of the video memory (MM.INFO(PAGE ADDRESS n) plus the size of the page no higher than &HD0300000), so on the Generation 2 the higher pages cannot be displayed (the error "Display page address > &HD0300000 - use a lower page number").
PAGE DISPLAY -1 turns off the display (the monitor no longer receives the synchronisation signals).  It is only valid in a program.  To turn the display back on select a valid display page; the display is also turned back on when the program ends.

=+= PAGE COPY n TO m [, when] [, T]
---
Copies the contents of one video page to another.  ‘n’ is the source and ‘m’ is the destination (a comma can be used instead of TO).  The two pages must be the same size ("Page size mismatch - use BLIT").
‘when’ can be one of the letters I, B or D.  If omitted it will default to I.
{l=720}I means do the copy immediately.  It is the most efficient but risks causing screen artefacts.
{l=720}B means wait until the next frame blanking and then do the copy.  It is the least efficient but is absolutely determinate in its effect and no screen artefacts will ever be seen.
{l=720}D means carry on processing the next command and do the copy in the background when the next frame blanking occurs.  This is efficient but must be used with care as subsequent drawing commands may or may not be included in the copy depending on the timing of the next frame blanking.  Only one such copy is held: another D copy before the frame blanking replaces it.
If T (or 1) is added then only the non-black pixels are copied, for example `PAGE COPY 1 TO 0, B, T`.

=+= PAGE SCROLL pageno, x, y [, fillcolour]
--- keep
Will scroll the image on the page specified by ‘pageno’ by the amount defined by ‘x’ pixels to the right and ‘y’ pixels up (negative values scroll it left and down).  ‘x’ can be from -w/2-1 to w/2 and ‘y’ from -h/2-1 to h/2, where ‘w’ and ‘h’ are the width and height of the page (MM.HRES and MM.VRES unless it has been resized).  By default the area scrolled off the page appears on the other side.
If ‘fillcolour’ is specified it will replace the area left behind by the scroll with the colour specified.  If ‘fillcolour’ is set to -1 then the area left behind by the scroll is left untouched.  This is the most efficient version and is suitable if there is a black background.

=+= PAGE RESIZE pageno, w, h
--- keep
Changes the width and height of a given page in memory (its contents are not rescaled).  ‘w’ can be set between 1 and the normal width for the current display mode and ‘h’ between 1 and its normal height.  Page 0 (pages 0 and 1 in the 12-bit depth) cannot be resized.
When PAGE WRITE is set to a resized page all graphics commands will respect the new values of width and height, including print output scrolling, and MM.HRES and MM.VRES will report the revised size.  The next MODE command, and the end of the program, restore the normal size.

=+= PAGE STITCH frompage1, frompage2, topage, offset
--- keep
Will take the last MM.HRES minus ‘offset’ columns from ‘frompage1’ and the first ‘offset’ columns from ‘frompage2’ and copies them, side by side, to ‘topage’.  Stepping ‘offset’ from 0 to MM.HRES moves the view smoothly from the first page to the second.
The three pages must be the same size, and ‘frompage1’ and ‘frompage2’ cannot be page 0 (pages 0 and 1 in the 12-bit depth).

=+= PAGE MERGE frompage1, frompage2, topage [, colour]
--- keep
Copies ‘frompage1’ to ‘topage’ with the image on ‘frompage2’ over it: the pixels of ‘frompage2’ that are of the transparent colour ‘colour’ (default 0, black) let ‘frompage1’ show through.
The three pages must be the same size, and ‘frompage1’ and ‘frompage2’ cannot be page 0 (pages 0 and 1 in the 12-bit depth).

=+= PAGE AND_PIXELS sourcepage1, sourcepage2, destinationpage
or
PAGE OR_PIXELS sourcepage1, sourcepage2, destinationpage
or
PAGE XOR_PIXELS sourcepage1, sourcepage2, destinationpage
--- keep
These commands combine the pixels on ‘sourcepage1’ and ‘sourcepage2’ by ANDing, ORing or XORing them and write the result to ‘destinationpage’, which can be the same as either of the source pages if required.  The three pages must be the same size.

=== PAUSE delay

Note that interrupts will be recognised and processed during a pause.

=== PIN( pin ) = value

=== PIXEL x, y [,c]
---
Set a pixel on the screen to a colour.
‘x’ is the horizontal coordinate and ‘y’ is the vertical coordinate of the pixel.  ‘c’ is a 24 bit number specifying the colour.  ‘c’ is optional and if omitted the current foreground colour will be used.
All parameters can be expressed as arrays and the software will plot the number of pixels as determined by the dimensions of the smallest array.  ‘x’ and ‘y’ must both be arrays or both be single variables/constants otherwise an error will be generated.  ‘c’ can be either an array or a single variable or constant.

See the chapter *Graphics Functions* for a definition of the colours and graphics coordinates.

=+= PIXEL FAST x, y [,c]
--- keep
A quicker PIXEL for a single point: ‘x’ and ‘y’ are single values (not arrays) and ‘c’ is the colour (the current foreground colour if it is omitted).  PIXEL FAST is another name for CLS with two or three arguments, which draws a pixel in the same way, and a program lists it as CLS.

=+= PIXEL FILL x, y, c
--- keep
Implements a flood fill by reading the colour of the pixel at coordinates ‘x’, ‘y’ on the screen and replacing it and the entire area of connected pixels having the same colour with the new colour ‘c’.  See also FILL.

=== PLAY
--- keep
The PLAY commands generate sound on the audio output: the stereo audio socket on the front panel, driven by the processor's DAC (see the chapter Sound Output).  The sound plays in the background, so the program continues while it plays.
Only one kind of sound can play at a time.  A command that would start another kind while a sound is playing (or paused) gives the error "Sound output in use", so use PLAY STOP first.  A PLAY TONE, PLAY SOUND, PLAY ARRAY, PLAY SAMPLE or PLAY BBC SOUND while a sound of its own kind plays changes that sound, and PLAY EFFECT and PLAY MODSAMPLE play over a MOD file.  The sound is stopped when a program ends, and RUN sets the volume to the maximum.

=+= PLAY TONE left, right [, dur] [, interrupt]
---
Generates two separate sine waves on the left and right channels of the audio output.  ‘left’ and ‘right’ are the frequencies in Hz, from 0 (silence) to 20000.  The frequencies are very accurate (they are based on a crystal oscillator).
‘dur’ specifies the number of milliseconds that the tone will sound for.  MMBasic rounds the time to the next complete cycle of the left frequency (when it is 10Hz or more) so that the tone always finishes with the output at its middle level, without a click.  If ‘dur’ is not specified the tone will continue until explicitly stopped or the program terminates.  ‘interrupt’ is an optional subroutine which will be called when the tone has finished.
The frequencies can be changed at any time by issuing a new PLAY TONE command.  A paused tone takes the new frequencies and stays paused.

=+= PLAY WAV file$ [, interrupt]
or
PLAY FLAC file$ [, interrupt]
or
PLAY MP3 file$ [, interrupt]
---
Plays an audio file on the audio output.  ‘file$’ is the file to play, on the SD card or USB flash drive; the appropriate extension (.WAV, .FLAC or .MP3) is added if it has none.  ‘interrupt’ is optional and is the name of a subroutine which will be called when the file has finished playing.
For WAV and FLAC files MMBasic adjusts to the file's sample rate, number of bits and number of channels: they can be mono or stereo, with sample rates up to 96kHz (eg, 44.1kHz 16-bit CD quality or 96kHz 24-bit).  MP3 files can have the MP3 format's sample rates (up to 48kHz).
If ‘file$’ is a directory MMBasic finds the files of the type in it and plays them one after another (up to 20 of them); an empty string ("") is the current directory.  The files found are listed when the command is used at the command prompt but not in a program.  The file names are kept with their full path, so CHDIR can be used while they play.  The interrupt is called when the last file has played.  PLAY NEXT and PLAY PREVIOUS skip between the files and MM.INFO$(TRACK) returns the name of the file that is playing.

=+= PLAY MODFILE file$ [, samplerate] [, interrupt]
---
Plays a MOD file (music made with a tracker) on the audio output.  ‘file$’ is the MOD file (.MOD is added if it has no extension); it is read into memory and played in the background.  The MOD player supports up to 32 channels and 32 samples, with 16-bit resolution.
Without ‘interrupt’ the MOD file plays continuously, in a loop, until PLAY STOP.  With ‘interrupt’ it plays once through the sequence and then the subroutine is called (in a program only).  PLAY MODFILE file$, interrupt (with no sample rate) is accepted, as on the PicoMite.
‘samplerate’ is the number of samples a second that the MOD player generates: 8000, 16000, 22050, 44100 (the default) or 48000.  A lower rate reduces the processor's work.  A WAV file played with PLAY EFFECT while the MOD file plays must have the same sample rate.

=+= PLAY MODSAMPLE sampleno, channel [, volume] [, samplerate]
---
Plays one of the samples of the MOD file that is playing, at the same time as the MOD file, so that the MOD file's samples can be used as sound effects.  ‘sampleno’ is the sample's number, 1 to 32.  Up to four samples can play at once on independent channels: ‘channel’ is 1 to 4, and a sample started on a channel that is playing replaces the sample there (MM.INFO(SAMPLE PLAYING n) says whether channel n is playing).
‘volume’ is 0 to 64 (the default).  ‘samplerate’ is the rate at which the sample is played, 150 to 500000 (default 16000): changing it changes the pitch and the duration, and it should be the sample's own rate to play it as it was recorded.
A MOD file must be playing (otherwise the error is "Samples play over MOD file").

=+= PLAY EFFECT file$ [, interrupt]
---
Plays the WAV file ‘file$’ (.WAV is added if it has no extension) at the same time as the MOD file that is playing, for sound effects over the music.  If a previous effect is still playing it is stopped and the new one starts.  The file can be mono or stereo but must have the same sample rate as the MOD file's output (see PLAY MODFILE): 44100Hz unless another rate was given.  ‘interrupt’ is optional and is the name of a subroutine which will be called when the file has finished playing.
A MOD file must be playing (otherwise the error is "Effects play over MOD file").

=+= PLAY TTS text$ [, speed] [, pitch] [, mouth] [, throat] [, interrupt]
or
PLAY TTS PHONETIC text$ [, speed] [, pitch] [, mouth] [, throat] [, interrupt]
---
Speaks the English text ‘text$’ on the audio output with the voice of SAM (the Software Automatic Mouth).  With PHONETIC ‘text$’ is SAM's phonemes instead of English: see <<http://www.retrobits.net/atari/sam.shtml>> for them and for the voice's parameters.
‘speed’, ‘pitch’, ‘mouth’ and ‘throat’ set the voice: each is 1 to 255 and they default to 72, 64, 128 and 128.  The speech plays in the background and ‘interrupt’ is optional: a subroutine which will be called when it has finished.  The speech cannot be paused.

=+= PLAY SOUND soundno, channelno, type [, frequency] [, volume]
---
Plays up to four sounds at once on each channel of the audio output, made from simple waveforms.
‘soundno’ is the sound's number, 1 to 4.  ‘channelno’ is the output channel: L (left speaker), R (right speaker) or B (both speakers).
‘type’ is the waveform: S (sine wave), Q (square wave), T (triangle wave), W (sawtooth), P (periodic noise), N (white noise), U (the wave loaded by PLAY LOAD SOUND) or O (off).  ‘channelno’ and ‘type’ can also be string expressions (eg, "L"; "M" is the same as "B").
‘frequency’ is from 1 to 20000 (Hz) and can have decimals; it must be specified except when ‘type’ is O.  For type N it is the number of periods of 1/44100 second that the output stays at each random value.  For type U the 4096 values of the wave are played ‘frequency’ times a second.
‘volume’ is optional and must be between 0 and 25.  It defaults to 25.
Calling PLAY SOUND on a sound that is playing will immediately replace it; individual sounds are turned off using type O.  Output can be stopped temporarily using PLAY PAUSE and PLAY RESUME, and PLAY STOP stops all the sounds.

=+= PLAY LOAD SOUND array%()
---
Loads the wave that PLAY SOUND plays for type U.  ‘array%()’ is an integer array of 1024 elements holding 4096 16-bit values between 0 and 4095, four to an element: MEMORY PACK can make it from a normal 4096 element integer array.  The array must be global (or STATIC), not LOCAL, as it is read while sounds play.
The wave is forgotten by PLAY STOP and when the program ends.  While it is loaded another cannot be loaded (the error is "Already loaded").

=+= PLAY ARRAY left%(), right%(), freq [, start] [, end] [, interrupt]
---
Plays sound held in two integer arrays.  ‘left%()’ and ‘right%()’ (which can be the same array) hold the samples for the left and right channels as 16-bit values (-32768 to 32767), four to an element (see MEMORY PACK); they must have the same number of elements.  ‘freq’ is the rate at which the samples are played: 10 to 48000 a second.
If ‘start’ is specified the arrays are played from that sample (0 is the first) and if ‘end’ is specified until that sample is reached.  ‘interrupt’ (in a program only) is the name of a subroutine which will be called once the last sample has been played.
It is important to understand the ‘freq’ parameter: it is the rate at which each sample is output.  So, for example, if the arrays held 10 cycles of a sine wave in 18000 samples then a ‘freq’ of 1800 would output a 1Hz sine wave for 10 seconds, and a ‘freq’ of 18000 a 10Hz sine wave for 1 second.
The arrays must be global (or STATIC), not LOCAL, as they are read while the sound plays.

=+= PLAY SAMPLE left%(), right%(), freq, attack, decay, sustain, release [, freqR, attackR, decayR, sustainR, releaseR] [, interrupt]
or
PLAY RELEASE
---
Plays a looped single cycle waveform under an ADSR envelope, as a synthesiser plays a note.  ‘left%()’ and ‘right%()’ hold one cycle of the wave for the left and right channels, one 16-bit value (-32768 to 32767) in each element; they must have the same number of elements.  The cycle is repeated ‘freq’ times a second (10 to 48000).
‘attack’, ‘decay’ and ‘release’ are times in milliseconds (0 to 30000) and ‘sustain’ is a level, 0 to 100 percent of the full volume.  The sound rises to the full volume over the attack time, falls to the sustain level over the decay time and stays there until PLAY RELEASE, after which it falls to silence over the release time and ends.
The optional second set of parameters gives the right channel its own frequency and envelope (otherwise both use the first).  ‘interrupt’ (in a program only) is the name of a subroutine which will be called when the sound has ended.
PLAY RELEASE starts the release of the envelopes.
The arrays must be global (or STATIC), not LOCAL, as they are read while the sound plays.

=== PLAY BBC SOUND channel, amplitude, pitch, duration
--- keep
The BBC Micro's SOUND statement.  Queues a note on one of four channels: channels 1 to 3 are square-wave tones and channel 0 is a noise source.  The notes queued on a channel play in order, each for its duration, so a tune can be written as a run of PLAY BBC SOUND commands and the program carries on while it plays.
'channel' is the BBC channel word &HSFC.  C (bits 0 and 1) is the channel, 0 to 3.  Adding &H10 flushes the channel's queue and stops its current note so that the new note is heard at once.  Adding &H100, &H200 or &H300 holds the note until that many other channels are waiting with the same value at the head of their queues, and then they all start together, so a three note chord uses &H2xx on all three channels.
'amplitude' is -15 (loudest) to 0 (silent, a rest), or 1 to 16 to use an envelope defined with PLAY BBC ENVELOPE.  'pitch' is 0 to 255 in quarter semitones, 89 being A4 (440Hz) and 53 middle C; on channel 0 only its low three bits are used and they select one of eight noises: 0 to 2 are periodic (a buzzy, pitched tone) at high, medium and low rates, 4 to 6 are white noise at the same three rates, and 3 and 7 are periodic and white clocked by channel 1's tone rather than at a fixed rate, so a note on channel 1 tunes the noise and a pitch envelope on channel 1 bends it (channel 1 need not be audible; an amplitude of 0 still sets its pitch).  'duration' is 0 to 255 in twentieths of a second and 255 means until the channel is flushed or PLAY STOP is used.
Each channel queues up to 16 notes.  MM.INFO(BBC BUFFER) returns the number of free slots, so a program can keep ahead of the music without ever waiting.  When a channel's queue is full the command waits for a slot, as the BBC did, so a loop of PLAY BBC SOUND commands paces itself to the music (Ctrl-C works while it waits but MMBasic interrupts are held off until it returns).  The audio output is released automatically when every channel is silent and every queue is empty, as it is when a PLAY TONE ends, and the next PLAY BBC SOUND starts it again.  The output is mono and PLAY VOLUME applies.  The engine's state (608 bytes) is taken from the MMBasic heap by the first PLAY BBC command and freed when the program's variables are cleared.  See the Sound Output chapter for the pitch table and examples.

=== PLAY BBC ENVELOPE n, T, PI1, PI2, PI3, PN1, PN2, PN3, AA, AD, AS, AR, ALA, ALD
--- keep
The BBC Micro's ENVELOPE statement.  Defines envelope 'n' (1 to 16) for use as the amplitude of a PLAY BBC SOUND.  It shapes the volume of the note (attack, decay, sustain and release) and can bend its pitch while it plays.  Definitions survive PLAY STOP and are cleared with the program's variables by RUN, NEW and loading a program, so a program defines its envelopes at the start.
'T' is the length of each step in hundredths of a second (bits 0 to 6, 0 is treated as 1); add 128 to stop the pitch envelope repeating.  'PI1', 'PI2' and 'PI3' (-128 to 127) are the pitch change per step, in quarter semitones, in each of three pitch sections and 'PN1', 'PN2' and 'PN3' (0 to 255) are the number of steps in each section.  When the three sections are done the pitch returns to the note's own and the sections repeat, unless 128 was added to T.
'AA', 'AD', 'AS' and 'AR' (-127 to 127) are the volume change per step during the attack, decay, sustain and release phases and 'ALA' and 'ALD' (0 to 126) are the levels the attack rises to and the decay falls to (126 is as loud as amplitude -15).  The attack runs from 0 to ALA, the decay from there to ALD, the sustain lasts until the note's duration ends and the release then runs until the level reaches 0, at which point the note ends.  A release of 0 never ends the note, so it will sound until the channel is flushed.

=== PLAY PAUSE
PLAY RESUME
PLAY STOP
PLAY CLOSE
--- keep
PLAY PAUSE will temporarily halt the sound that is playing (a file, a tone or any of the others but TTS speech) and PLAY RESUME will resume it.  PLAY STOP will terminate the sound; PLAY CLOSE (the PicoMite's name) does the same.  When the program terminates for whatever reason the sound output will also be automatically stopped.  Pausing, resuming and stopping are smoothed over a few milliseconds so that they do not click.

=+= PLAY VOLUME left [, right]
--- keep
Will adjust the volume of the audio output.  ‘left’ and ‘right’ are the levels to use for the left and right channels and can be between 0 and 100, with 100 being the maximum volume.  Either can be omitted to leave that channel as it is: PLAY VOLUME ,50 changes the right channel only, and PLAY VOLUME 50 the left only.  A change is smoothed over a few milliseconds so that it does not click.  The volume is set to the maximum when a program is run.

=+= PLAY NEXT
PLAY PREVIOUS
--- keep
When a directory of files is playing (PLAY WAV, FLAC or MP3 with a directory) these stop the file that is playing and start the next one or the previous one.  At the command prompt a message says when the last (or the first) file is already playing.

=== PRINT expression \n[[,; ]expression] … etc
---
Outputs text to the console (the screen and the serial console, as set by OPTION CONSOLE) followed by a carriage return/newline pair. Multiple expressions can be used and must be separated by either a:
{n=1 v=0 t=x1152,n432 b=0 l=430 h=181}Comma (,) which will output the tab character
{n=1 v=0 t=x1152,n432 b=0 l=430 h=181}Semicolon (;) which will not output anything (it is just used to separate expressions).

=== PRINT #GPS, string$
--- keep

=== PRINT @(x [, y]) expression
or

--- keep
Same as the standard PRINT command except that the cursor is positioned at the coordinates x, y expressed in pixels. If y is omitted the cursor will be positioned at “x” on the current line. === PULSE pin, width
--- keep
{t=n360}Will generate a pulse on 'pin' with duration of 'width' ms.  'width' can be a fraction.  For example, 0.01 is equal to 10µs and this enables the generation of very narrow pulses. 
The generated pulse is of the opposite polarity to the state of the I/O pin when the command is executed.  For example, if the output is set high the PULSE command will generate a negative going pulse.  
Notes:	
{n=1 v=0 t=x1152,n360 b=0 l=360 h=181}'pin' must be configured as an output.
{n=1 v=0 t=x1152,n360 b=0 l=360 h=181}For a pulse of less than 3 ms the accuracy is ± 1 µs.
{n=1 v=0 t=x1152,n360 b=0 l=360 h=181}For a pulse of 3 ms or more the accuracy is ± 0.5 ms.
{n=1 v=0 t=x1152,n360 b=0 l=360 h=181}A pulse of 3 ms or more will run in the background. === PWM 1, freq, 1A [, 1B] [, 1C] [, centre]
or
PWM 2, freq, 2A [, 2B] [, , centre]
or
PWM channel, STOP (or OFF)
---
Generate a pulse width modulated (PWM) output for driving analog circuits, sound output, etc.
There are a total of five outputs designated as PWM in the table of the external I/O connector in the chapter *Hardware Features* (they are also used for the SERVO command).  Controller 1 can have one, two or three outputs (1A on pin 12, 1B on pin 22 and 1C on pin 29) while controller 2 can have one or two outputs (2A on pin 36 and 2B on pin 31).  Both controllers are independent and can be turned on and off and have different frequencies.
‘1’ or ‘2’ is the controller number and ‘freq’ is the output frequency in Hz (1 to 20000000).  1A, 1B and 1C are the duty cycles for each of the controller 1 outputs while 2A and 2B are the duty cycles for the controller 2 outputs.  1B and 1C can be left out, and any of them can be left empty (eg, PWM 1, 1000, , 50): an output that is not given is left as it is.  The specified I/O pins will be automatically configured as outputs while any others will be unaffected and can be used for other duties.
The duty cycle for each output is independent of the others and is specified as a percentage.  If it is close to zero the output will be a narrow positive pulse, if 50 a square wave will be generated and if close to 100 it will be a very wide positive pulse.  A negative duty cycle (down to -100) inverts the output, giving negative going pulses.
‘centre’ is 1 for centre aligned outputs: the pulses of the outputs are centred in the period, so that a shorter pulse starts and ends equal times from a longer one.  0 (or omitted) starts all the pulses at the beginning of the period.
The frequency is derived from a 240MHz clock (200MHz on a 400MHz processor), so it can be any value of 240,000,000/n and the duty cycle and frequency accuracy will depend on the frequency (eg, at 1MHz the duty cycle has 240 steps).  The output will run continuously in the background while the program is running and can be stopped using the STOP command.  The frequency and duty cycle can be changed at any time (without stopping the output) by issuing a new PWM command.
The PWM function will take control of any specified outputs and when stopped the pins will be returned to a high impedance "not configured" state.
With OPTION PICOMITE the arguments are the PicoMite's: PWM channel, freq, [A] [, B] [, phase] [, defer].  ‘phase’ is 1 for centre aligned outputs, as ‘centre’ is above, and there is no output C.  ‘defer’, on the PicoMite a start left to PWM SYNC, can only be 0.  The channels are 1 and 2, whose outputs are GP2 to GP5 (see PicoMite Pin Names in the chapter Using the I/O Pins).

=== RUN [file$] [, cmdline]
--- keep

=== {b=0 a=0 ln=288 lr=auto}SELECT CASE value
{b=0 a=0 ln=288 lr=auto}  CASE testexp [[, testexp] …]
{b=0 a=0 ln=288 lr=auto}        <statements>\n        <statements>\n  CASE test-n [[, test-n] …]
{b=0 a=0 ln=288 lr=auto}        <statements>\n        <statements>\n  CASE ELSE
{b=0 a=0 ln=288 lr=auto}        <statements>\n        <statements>\nEND SELECT
---
Executes one of several groups of statements, depending on the value of an expression.  'value' is the expression to be tested.  It can be a number or string variable or a complex expression.  
'testexp' (or test-n) is the value that is to be compared against.  It can be:
{n=8 v=0 t=x720,n432 l=432 h=290}A single expression (i.e. 34, "string" or PIN(4)\*5) to which it may equal
{n=8 v=0 t=x720,n432 l=432 h=290}A range of values in the form of two single expressions separated by the keyword "TO" (i.e. 5 TO 9 or "aa" TO "cc")
{n=8 v=0 t=x720,n432 l=432 h=290}A comparison starting with the keyword "IS" (which is optional).  For example:  IS > 5, IS <= 10.
When a number of test expressions (separated by commas) are used the CASE statement will be true if any one of these tests evaluates to true.
If 'value' cannot be matched with a 'testexp' it will be automatically matched to the CASE ELSE.  If CASE ELSE is not present the program will not execute any <statements> and continue with the code following the END SELECT.  When a match is made the <statements> following the CASE statement will be executed until END SELECT or another CASE is encountered when the program will then continue with the code following the END SELECT.
An unlimited number of CASE statements can be used but there must be only one CASE ELSE and that should be the last before the END SELECT.
Example:
{b=0 a=0 l=720}`SELECT CASE nbr%`
{b=0 a=0 l=720}`  CASE 4, 9, 22, 33 TO 88`
{b=0 a=0 l=720}`       statements`
{b=0 a=0 l=720}`  CASE IS < 4, IS > 88, 5 TO 8`
{b=0 a=0 l=720}`       statements`
{b=0 a=0 l=720}`  CASE ELSE`
{b=0 a=0 l=720}`       statements`
{b=0 a=0 l=720}`END SELECT `
Each SELECT CASE must have one and one only matching END SELECT statement.  Any number of SELECT…CASE statements can be nested inside the CASE statements of other SELECT…CASE statements.

=== SERVO 1 [, freq], 1A [, 1B [, 1C]]
or
SERVO 2 [, freq], 2A [, 2B]
or
SERVO channel, STOP (or OFF)
---
Generate a constant stream of positive going pulses for driving a servo.
The Colour Maximite 2 has two servo controllers with the first being able to control up to three servos and the second two servos.  Both controllers are independent and can be turned on and off and have different frequencies.  This command uses the I/O pins that are designated as PWM in the table of the external I/O connector (the two commands are very similar): 1A is pin 12, 1B pin 22, 1C pin 29, 2A pin 36 and 2B pin 31.
‘1’ or ‘2’ is the controller number.  ‘freq’ is the output frequency (between 20Hz and 1000Hz) and is optional.  If not specified it will default to 50Hz.  (A first value of 20 or more is taken as the frequency.)
1A, 1B and 1C are the pulse widths for each of the controller 1 outputs while 2A and 2B are the pulse widths for the controller 2 outputs.  Any of them can be left empty (eg, SERVO 1, , 1.5): an output that is not given is left as it is.  The specified I/O pins will be automatically configured as outputs while any others will be unaffected and can be used for other duties.
The pulse width for each output is independent of the others and is specified in milliseconds, which can be a fractional number (i.e. 1.536).  For accurate positioning the output resolution is about 0.005 ms.  The minimum value is 0.01ms while the maximum is 18.9ms (and less than the period).  Most servos will accept a range of 0.8ms to 2.2ms.  The output will run continuously in the background while the program is running and can be stopped using the STOP command.  The pulse widths of the outputs can be changed at any time (without stopping the output) by issuing a new SERVO command.
The SERVO function will take control of any specified outputs and when stopped the pins will be returned to a high impedance "not configured" state.
With OPTION PICOMITE the arguments are the PicoMite's: SERVO channel, [A] [, B], at 50Hz, where A and B are positions from -20 to 120.  A position of 0 is a pulse of 1 ms and 100 one of 2 ms (1 ms and a hundredth of a millisecond for each unit), so -20 to 120 is 0.8 ms to 2.2 ms.  There is no frequency and no output C.

=== SETPIN pin, cfg [, option]
---
{t=l2592}Will configure an external I/O pin.  Refer to the chapter *Using the I/O Pins* for a general description of the Colour Maximite 2's input/output capabilities, and to the table of the external I/O connector in the chapter *Hardware Features* for the capabilities of each pin.
{t=l2592}‘pin’ is the I/O pin to configure (its number in that table), ‘cfg’ is the mode that the pin is to be set to and ‘option’ is an optional parameter.  ‘cfg’ is a keyword and can be any one of the following:
{t=l1260 b=0 l=1258 h=1009}OFF	Not configured or inactive (0 can also be used).
{t=l1260 b=0 l=1258 h=1009}AIN	Analog input (i.e. measure the voltage on the input). {t=l1260 b=0 l=1258 h=1009}DOUT	Digital output.\n‘option’ can be OC in which case the output will be open collector (or more correctly open drain).

{t=l2592}The functions PIN() and PORT() can also be used to return the value on one or more output pins.  See the function PIN() for reading inputs and the statement PIN()= for setting an output.  See the command below if an interrupt is configured.
{t=l2592}‘pin’ can also be a PicoMite GP name (eg, SETPIN GP2, DOUT), and the PicoMite's SETPIN commands that give COM ports, I2C, SPI, PWM and IR their pins are accepted (see PicoMite Pin Names in the chapter Using the I/O Pins).

=== SETTICK period, target [, nbr] 
--- keep
This will setup a periodic interrupt (or "tick").  
Four tick timers are available ('nbr' is 1, 2, 3 or 4).  'nbr' is optional and if not specified timer number 1 will be used.

=+= SETTICK PAUSE, target [, nbr]

=== SORT array() [,indexarray()] [,flags] [,startposition] [,elementstosort]
---
This command takes an array of any type (integer, float or string) and sorts it into ascending order in place. 
It has an optional parameter ‘indexarray%()’. If used this must be an integer array of the same size as the array to be sorted. After the sort this array will contain the original index position of each element in the array being sorted before it was sorted.  Any data in the array will be overwritten. This allows connected arrays to be sorted.  
The ‘flag’ parameter is optional and valid flag values are:
{l=201}bit0:  0 (default if omitted) normal sort - 1 reverse sort\nbit1:  0 (default) case dependent - 1 sort is case independent (strings only).\nbit2:  0 (default) normal sort - 1 empty strings go to the end of the array
The optional ‘startposition’ defines which element in the array to start the sort. Default is 0 (OPTION BASE 0) or 1 (OPTION BASE 1)
The optional ‘elementstosort’ defines how many elements in the array should be sorted. The default is all elements after the ‘startposition’.
Any of the optional parameters may be omitted so, for example, to sort just the first 50 elements of an array you could use:
	`SORT array(), , , ,50`
Example:
The array city$() might contain the names of world cities and can be easily sorted into increasing alphabetical order with the command: SORT city$() 
The SORT command will work with strings, floats and integers however the array to be sorted must be single dimensioned. 
Often data is held in multiple arrays, for example, the name of each city might be held in the array city$(), the population held in the array pop%() and the size of the city held in area!(). The same index would refer to the name, population and the area of the city.  
Sorting and accessing this data is a little more complex but it can be done relatively easily using an optional parameter to the sort command as follows: 
{l=484}SORT array(), indexarray%()
indexarray%() must be a single dimension integer array of the same size as the array being sorted.  Following the sort indexarray%() will contain the corresponding index to the original data before it was sorted. (anything previously in indexarray%() will be overwritten). 
To access the sorted data you would first copy the array holding the main key to a temporary array and sort that while specifying indexarray%(). After the sort indexarray%() can be used to index the original arrays. 
For example: 
{kn=1 b=0 a=0 l=201}`DIM city$(100),pop%(100),area!(100),sindex%(100),t$(100) `
{kn=1 b=0 a=0 l=201}`FOR i = 0 to 100 `
{kn=1 b=0 a=0 l=201}`  t$(i) = city$(i)       ‘ temporary copy of the keys`
{kn=1 b=0 a=0 l=201}`NEXT i `
{kn=1 b=0 a=0 l=201}`SORT t$(), sindex%()     ‘ sort the temporary array,`
{kn=1 b=0 a=0 l=201}`FOR i = 0 to 100 `
{kn=1 b=0 a=0 l=201}`  k = sindex%(i)         ‘ index to the original array `
{kn=1 b=0 a=0 l=201}`  PRINT city$(k),pop%(k),area!(k)‘ print in sorted order `
{kn=1 b=0 a=0 l=201}`NEXT i`

=== SPI OPEN speed, mode [, bits]
or
SPI READ nbr, data [, data…]
or
SPI WRITE nbr, data [, data…]
or
SPI CLOSE
---
Communications via the first SPI channel, on the rear I/O connector.  See Appendix D for the details.
‘speed’ is the clock speed in Hz, ‘mode’ the transmission format (0 to 3) and ‘bits’ the number of bits in each item (4 to 32, 8 if it is left out).
‘nbr’ is the number of data items to send or receive.
The data to send (WRITE) or the destination for the received data (READ) may be supplied in any one of three forms:
{n=39 v=0}**A list of individual items.**  The number of items must equal ‘nbr’.  For WRITE each item is a constant, variable or expression; for READ each item is a numeric variable to receive one value.  Array elements such as a(3) are allowed.
{n=39 v=0}**An array** specified with empty brackets, eg, array().  It may be a floating point or integer array and must be large enough to supply (WRITE) or hold (READ) ‘nbr’ elements, which are taken from / stored into consecutive elements starting at the first.
{n=39 v=0}**A string variable.**  For WRITE the first ‘nbr’ characters are sent (the string must be at least that long); for READ the received bytes are stored as sequential characters and the string is set to that length.
SPI WRITE discards any data returned by the slave and SPI READ sends zeros while reading the data from the slave.  SPI CLOSE returns the I/O pins to a "not configured" state.

=== SPRITE
---
The SPRITE commands are used to manipulate small graphic images on the screen.  These are useful when writing games.  See Appendix F for how sprites, their layers and their collisions work, and the SPRITE() functions for interrogating them.
SPRITE and BLIT are one command: every SPRITE command can also be written as BLIT and every BLIT command as SPRITE.  The sprites are the buffers #1 to #64 that BLIT READ also uses, and the # before a sprite number is optional.  WRITE and LOAD differ with the name used, as on the PicoMite (see BLIT).
A sprite can be up to the size of the screen.  Its image is held in full colour whatever the colour depth, so a sprite can be loaded before the MODE command and it is kept through a change of mode.  A MODE command clears the screen, and with it the sprites that were showing: they are no longer displayed and can be shown again.
A sprite's transparent pixels are not drawn, so that the background shows through them.  A pixel is transparent when the colour depth shows it as the transparent colour, which is black unless SPRITE SET TRANSPARENT has set another.  So in every colour depth but the 32-bit one the colours too dark to be told from black are transparent too: in the 8-bit depth, say, any colour with red and green below 32 and blue below 64.

=+= SPRITE CLOSE [#]n
--- keep
Closes sprite ‘n’ and releases its memory resources allowing the sprite number to be re-used.  If the sprite is displayed it is first removed and the stored background replaced.  The command will give an error if other sprites are copied from this one unless they are closed first.

=+= SPRITE CLOSE ALL
---
Closes all sprites and releases all sprite memory, removes the static objects (see SPRITE STATIC) and makes black the transparent colour again.  The screen is not changed.  RUN does the same.

=+= SPRITE COPY [#]n, [#]m, nbr
--- keep
Makes a copy of sprite ‘n’ to ‘nbr’ of new sprites starting at number ‘m’.  Copied sprites share the same loaded image as the original to save memory.  The new sprite numbers must not be in use, and a copy cannot itself be copied.  While copies exist the original cannot be closed or read into.

=+= SPRITE HIDE [#]n
--- keep
Removes sprite ‘n’ from the display and replaces the stored background.  To restore a screen to a previous state sprites should be hidden in the opposite order to which they were written ("LIFO").

=+= SPRITE HIDE ALL
--- keep
Hides all the sprites allowing the background to be manipulated.  SPRITE RESTORE shows them again.
While the sprites are hidden SPRITE SHOW, SHOW SAFE, HIDE, HIDE SAFE, HIDE ALL, SWAP, MOVE, SCROLL, SCROLLR and CLOSE must not be used (they give the error "Sprites are hidden").

=+= SPRITE HIDE SAFE [#]n
--- keep
Removes sprite ‘n’ from the display and replaces the stored background.  Automatically hides all more recent sprites as well as the requested one and then replaces them afterwards.  This ensures that sprites that are covered by other sprites can be removed without the user tracking the write order.  Of course this version is less performant than the simple version and should only be used if there is a risk of the sprite being partially covered.

=+= SPRITE INTERRUPT sub
--- keep
Specifies the name of the subroutine that will be called when a sprite collision occurs.  See Appendix F for how to use the SPRITE() functions to interrogate details of what has collided.

=+= SPRITE LOAD fname$ [,start_sprite_number] [,palette]
---
Loads the file ‘fname$’ which must be formatted as an original Colour Maximite sprite file.  If an extension is not specified “.SPR” will be added to the file name.
The first line of the file holds the width of the sprites and their number, and optionally their height (the width if it is omitted), separated by commas: eg, `16, 8` or `16, 8, 24`.  Each sprite follows as ‘height’ lines of ‘width’ characters, a character for each pixel:
{l=720}space = transparent
{l=720}0 = black, 1 = blue, 2 = green, 3 = cyan, 4 = red, 5 = magenta, 6 = yellow, 7 = white
{l=720}8 = light grey, 9 = grey, A = orange, B = pink, C = gold, D = salmon, E = beige, F = brown
Black is the transparent colour (unless SPRITE SET TRANSPARENT has set another), so a 0 is not drawn when the sprite is shown, as on the PicoMite.
With ‘palette’ 1 the characters 0 to F are the PicoMite's 16 colours in order instead (its palette 1):
{l=720}0 = black, 1 = blue, 2 = myrtle, 3 = cobalt, 4 = midgreen, 5 = cerulean, 6 = green, 7 = cyan
{l=720}8 = red, 9 = magenta, A = rust, B = fuchsia, C = brown, D = lilac, E = yellow, F = white
‘palette’ 0, the list above it, is the default.
Any other character is also transparent, a short line is filled out with spaces, and lines starting with an apostrophe (') are comments.
The sprites are loaded as the sprite numbers from ‘start_sprite_number’ (1 if it is omitted) on.  Multiple sprite files can be loaded by specifying a different ‘start_sprite_number’ for each file.  The programmer is responsible for making sure that the sprite numbers used by the files do not overlap.
A sprite number already in use is loaded again, as SPRITE READ reads into one: a sprite that is showing takes the new image and stays where it is, if it is the same size ("Sprite n is showing, at another size" otherwise), and a copy, or a sprite that has copies, cannot be loaded into ("Sprite n is a copy", "Sprite n has copies").  The file's first line must give a width of 1 to 255 and at least one sprite ("Invalid sprite file").
Written as BLIT LOAD the command loads a BMP file instead (see BLIT).

=+= SPRITE LOADARRAY [#]n, w, h, array%()
--- keep
Creates the sprite ‘n’ with width ‘w’ and height ‘h’ by reading w × h RGB888 colour values from ‘array%()’ (an integer or floating point array).  The values must be stored in order of columns across and then rows down starting at the top left.  Black pixels are transparent.
This allows the programmer to create simple sprites in a program without needing to load them from disk or read them from the display.  The firmware will generate an error if ‘array%()’ is not big enough to hold the number of values required, or if sprite ‘n’ is already in use.

=+= SPRITE LOADBMP [#]n, fname$ [,x] [,y] [,w] [,h]
---
Loads the BMP image ‘fname$’ as sprite number ‘n’, which must not be in use.  If an extension is not specified “.BMP” will be added to the file name.  The file can be of any of the types that LOAD BMP reads.
‘x’, ‘y’, ‘w’ and ‘h’ load a part of the image: ‘w’ by ‘h’ pixels with its top left at ‘x’, ‘y’ in the image (0, 0 is the image's top left).  ‘x’ and ‘y’ default to 0, and ‘w’ and ‘h’ to the rest of the image.  The part must be within the image (the error "Coordinates") and no bigger than the screen ("Image too large").
Every pixel of the image is loaded as it is, so its black pixels are transparent when the sprite is shown (see SPRITE).  BLIT LOAD and BLIT LOADBMP are other names for this command.

=+= SPRITE LOADPNG [#]n, fname$ [,t] [,cutoff] [,x] [,y] [,w] [,h]
---
Loads the PNG image ‘fname$’ as sprite number ‘n’, which must not be in use.  If an extension is not specified “.PNG” will be added to the file name.  The file can be of any of the types that LOAD PNG reads, and it is decoded a line at a time.
A pixel whose alpha value (its opacity) is above ‘cutoff’ (1 to 254, default 30) is solid.  The others take the colour ‘t’, one of the PicoMite's 16 colours (0 to 15, default 0, black: the transparent colour, so that they are not drawn), as on the PicoMite.  The colours are numbered from 0:\nBlack, Blue, Myrtle, Cobalt, Midgreen, Cerulean, Green, Cyan, Red, Magenta, Rust, Fuchsia, Brown, Lilac, Yellow and White
A negative ‘t’ (-1 to -15) instead gives the colour -‘t’ to the solid pixels that the colour depth shows as black, which would be transparent, so that the image's black can be drawn; the others are then transparent.
A file without transparency (RGB or grey, or indexed with no transparency chunk) has every pixel solid.
‘x’, ‘y’, ‘w’ and ‘h’ load a part of the image, as with SPRITE LOADBMP.  The part must be within the image (the error "Coordinates") and no bigger than the screen ("Image too large").

=+= SPRITE MOVE
--- keep
Actions a single atomic transaction that re-locates all sprites which have previously had a location change set up using the SPRITE NEXT command.  Collisions are detected once all sprites are moved and reported in the same way as from a scroll.

=+= SPRITE NEXT [#]n, x, y
--- keep
Sets the X and Y coordinate of the sprite to be used when the screen is next scrolled or the SPRITE MOVE command is executed.  Using SPRITE NEXT rather than SPRITE SHOW allows multiple sprites to be moved as part of the same atomic transaction.

=+= SPRITE NOINTERRUPT
--- keep
Disables collision interrupts.

=+= SPRITE NOSTINTERRUPT
---
Disables the static object interrupt (see SPRITE STINTERRUPT).

=+= SPRITE READ [#]n, x, y, w, h [,page]
--- keep
Reads the display area specified by coordinates ‘x’ and ‘y’, width ‘w’ and height ‘h’ into buffer number ‘n’.  If the buffer is already in use and the width and height of the new area are the same as the original then the new command will overwrite the stored area.
The optional parameter ‘page’ specifies which page is to be read to create the sprite.  The default is the current write page.  Set ‘page’ to FRAMEBUFFER to read from the framebuffer (see the FRAMEBUFFER command).

=+= SPRITE RESTORE
--- keep
Restores all the sprites hidden by SPRITE HIDE ALL.  Any position changes previously requested using SPRITE NEXT for sprites on layers other than 0 will be actioned by the RESTORE and collision detection will be run.

=+= SPRITE SCROLL x, y [,colour]
---
Scrolls the background and any sprites on layer 0 ‘x’ pixels to the right and ‘y’ pixels up.  ‘x’ can be any number between -MM.HRES/2-1 and MM.HRES, ‘y’ any number between -MM.VRES/2-1 and MM.VRES.
Sprites on any layer other than zero will remain fixed in position on the screen (or move to the position set by SPRITE NEXT).  By default the scroll wraps the image round.  If ‘colour’ is specified the colour will replace the area behind the scrolled image.  If ‘colour’ is set to -1 the scrolled area will be left untouched.

=+= SPRITE SCROLLR x, y, w, h, delta_x, delta_y [,colour]
---
Scrolls the region of the screen defined by the top left coordinates ‘x’ and ‘y’ and width and height ‘w’ and ‘h’ by ‘delta_x’ pixels to the right and ‘delta_y’ pixels up (each less than the width or height of the region).
By default the scroll wraps the background round.  If ‘colour’ is specified the colour will replace the area behind the scrolled image (-1 wraps it as the default does).  Sprites on any layer other than zero will remain fixed in position on the screen (or move to the position set by SPRITE NEXT).  Sprites in layer zero where the centre of the sprite (x + w/2, y + h/2) falls within the scrolled region will move with the scroll and wrap round if the centre moves outside one of the boundaries of the scrolled region.

=+= SPRITE SET TRANSPARENT colour
---
Sets the transparent colour of the sprites to ‘colour’, one of the PicoMite's 16 colours (0 to 15, default 0, black).  They are numbered from 0:\nBlack, Blue, Myrtle, Cobalt, Midgreen, Cerulean, Green, Cyan, Red, Magenta, Rust, Fuchsia, Brown, Lilac, Yellow and White
A pixel of a sprite is then transparent when the colour depth shows it as that colour.  It applies to every sprite from its next draw on, and to SPRITE(B).  SPRITE CLOSE ALL, and RUN, make black the transparent colour again.

=+= SPRITE SHOW [#]n, x, y, layer [,orientation]
---
Displays sprite ‘n’ on the screen with the top left at coordinates ‘x’, ‘y’ (part of the sprite can be off the screen: ‘x’ can be from 1 - its width to MM.HRES-1 and ‘y’ from 1 - its height to MM.VRES-1).  ‘layer’ is a number from 0 to 10.  Sprites will only collide with other sprites on the same layer, layer zero, the static objects or the screen edge.  If a sprite is already displayed on the screen then the SPRITE SHOW command acts to move the sprite to the new location (and layer).  The display background is stored as part of the command and will be replaced when the sprite is hidden or moved further.
‘orientation’ is optional and can be:
{l=720}0 - normal display (default if omitted)
{l=720}1 - mirrored left to right
{l=720}2 - mirrored top to bottom
{l=720}3 - rotated 180 degrees (= 1+2)
{l=720}4 to 7 - the same with every pixel drawn, the transparent ones too, as on the PicoMite
The orientation stays with the sprite: SPRITE MOVE, SCROLL, SCROLLR and RESTORE draw it the same way.

=+= SPRITE SHOW SAFE [#]n, x, y, layer [,orientation] [,ontop]
---
Shows a sprite and automatically compensates for any other sprites that overlap it.
If the sprite is not already being displayed the command acts exactly the same as SPRITE SHOW.
If the sprite is already shown it is moved and remains in its position relative to other sprites based on the original order of writing.  ie, if sprite 1 was written before sprite 2 and it is moved to overlap sprite 2 it will display under sprite 2.
If the optional ‘ontop’ parameter is set to 1 then the sprite moved will become the newest sprite and will sit on top of any other sprite it overlaps.
Refer to SPRITE SHOW for details of the orientation parameter.

=+= SPRITE STATIC [#]n, x, y, w, h
or
SPRITE STATIC [#]n, OFF
---
Declares static object ‘n’ (1 to 64): an invisible rectangle ‘w’ by ‘h’ pixels with its top left at ‘x’, ‘y’, as on the PicoMite.  OFF removes it.  A static object has no pixels and is never drawn: it marks where the scenery that the program has drawn (a wall, a platform) is solid.
Each collision check tests the sprites displayed against the static objects as well as the other sprites.  A sprite that overlaps static object ‘n’ (touching is not overlapping) has &H80 + ‘n’ in its list of collisions (see SPRITE(C …)), and the collision interrupt is called.  Unlike a collision between sprites, which is reported once when it begins, a static object is reported at each check while the sprite overlaps it.
SPRITE SCROLL moves the static objects with the background, wrapping them round as it does, and SPRITE SCROLLR moves those whose centre is within its region.  See also SPRITE STINTERRUPT and SPRITE(ST …), and SPRITE(B) for a sprite's collision with the drawn background itself.

=+= SPRITE STATIC CLEAR
---
Removes every static object.  SPRITE CLOSE ALL does too.

=+= SPRITE STINTERRUPT sub
---
Specifies the name of the subroutine that will be called when a sprite overlaps a static object (see SPRITE STATIC).  SPRITE(ST, COLLISION) and SPRITE(ST, OBJECT) give the sprite and the static object of the last such collision.

=+= SPRITE SWAP [#]n1, [#]n2 [,orientation]
--- keep
Replaces the sprite ‘n1’ with the sprite ‘n2’.  The sprites must have the same width and height, ‘n1’ must be displayed and ‘n2’ must not be, or an error will be generated.  Refer to SPRITE SHOW for details of the orientation parameter.  The replacement sprite inherits the background from the original as well as its position in the list of order drawn.

=+= SPRITE TRANSPARENCY [#]n, transparency
--- keep
__IN THE 12-BIT COLOUR DEPTH ONLY__ Changes all pixels with a non-zero transparency in the stored sprite ‘n’ to the new level ‘transparency’, which can be between 1 and 15 (15 is solid).

=+= SPRITE WRITE [#]n, x, y [,orientation]
---
Overwrites the display with the contents of sprite buffer ‘n’ with the top left at coordinates ‘x’, ‘y’.
The background that is overwritten is not stored so SPRITE WRITE is inherently higher performing than SPRITE SHOW but with greater functional limitations.  The optional ‘orientation’ parameter (0 to 7) defaults to 4 and specifies how the stored image data is changed as it is written out.  It is the sum of the following values:
{l=720}&B001 = mirrored left to right
{l=720}&B010 = mirrored top to bottom
{l=720}&B100 = don't copy transparent pixels
Written as BLIT WRITE the default is 0, every pixel copied (see BLIT).  A sprite that is displayed can be written too: the copy is drawn, and the sprite shown, its orientation and its stored background are left as they were.

=== STATIC variable [, variables]

=== STEPPER
--- keep
This command controls up to three stepper motor axes (X, Y and Z) and a rotary A axis, with G-code execution, acceleration planning, arcs, homing and hardware limit switches.  It is the PicoMite's STEPPER command and is described in detail in the file *Stepper_Reference.pdf* included in the firmware download zip file.
On the Colour Maximite 2 the timer runs at 200 kHz (100 kHz on the PicoMite), so that a step pulse is 5 us long and the step rate can be up to 100 kHz (one step every two ticks of the timer).  A pin is given by its number on the rear connector or by its PicoMite GP name.  PEEK(STEPPER ...) and MM.CODE report on the motion and the G-code buffer.

=== STRUCT
---

=== SUB xxx (arg1 [,arg2, …])\n   <statements>\n   <statements>\nEND SUB
---
Defines a callable subroutine.  This is the same as adding a new command to MMBasic while it is running your program.
'xxx' is the subroutine name and it must meet the specifications for naming a variable.  
'arg1', 'arg2', etc are the arguments or parameters to the subroutine.  An array is specified by using empty brackets.  i.e.  arg3().  The type of the argument can be specified by using a type suffix (i.e. arg1$) or by specifying the type using `AS <type> (i.e. arg1 AS STRING).`
Arguments in the caller's list that are a variable and have the correct type will be passed by reference to the subroutine.  This means that any changes to the corresponding argument in the subroutine will also be copied to the caller's variable and therefore may be accessed after the subroutine has ended.  The argument can be prefixed with BYVAL which will prevent this mechanism and cause only the value to be used.  Alternatively, the prefix BYREF instructs MMBasic that a reference is required and an error will be generated if that cannot be done.
Arrays are passed by specifying the array name with empty brackets (eg, arg()) and are always passed by reference and must be the correct type.
Every definition must have one END SUB statement.  When this is reached the program will return to the next statement after the call to the subroutine.  The command EXIT SUB can be used for an early exit.
You use the subroutine by using its name and arguments in a program just as you would a normal command.  For example:   `MySub a1, a2`
When the subroutine is called each argument in the caller is matched to the argument in the subroutine definition.  These arguments are available only inside the subroutine.  Subroutines can be called with a variable number of arguments.  Any omitted arguments in the subroutine's list will be set to zero or a null string. 
Brackets around the argument list in both the caller and the definition are optional.

=== SYNC time% [,period]
or
SYNC
---
The SYNC command allows the user to implement very precisely timed repeated actions (1-2 microseconds accuracy). 
To enable this the command is first called with the parameter time%. This sets up a repeating clock for time% microseconds. The optional parameter ‘period’ modifies the time and can be  “U” for microseconds, “M” for milliseconds or “S” for seconds. 
Once the clock is set up the program is synchronised to it using the SYNC command without parameters. This waits for the clock period to expire. For periods below 2 ms this is non-interruptible. Above 2 ms the program will respond to Ctrl-C but not any MMBasic interrupts. 
SYNC 0 stops the clock.
Typical use is to set the clock outside of a loop and then at the top of the loop call the SYNC command without parameters. This means the contents of the loop will be executed exactly once for each clock period set.  For example, the following would drive a servo with the required precise 50Hz timing:  
{kn=1 b=0 a=0 l=720}`SETPIN 7, DOUT`
{kn=1 b=0 a=0 l=720}`SYNC 20, M`
{kn=1 b=0 a=0 l=720}`DO`
{kn=1 b=0 a=0 l=720}`  SYNC`
{kn=1 b=0 a=0 l=720}`  PULSE 7, n`
{kn=1 b=0 a=0 l=720}`LOOP` 

=== TEMPR START pin [, precision] [,timeout]
---
This command can be used to start a conversion running on a DS18B20 temperature sensor connected to 'pin'.  Normally the TEMPR() function alone is sufficient to make a temperature measurement so usage of this command is optional.  For more detail see the section *Measuring Temperature*.
This command will start the measurement on the temperature sensor.  The program can then attend to other duties while the measurement is running and later use the TEMPR() function to get the reading.  If the TEMPR() function is used before the conversion time has completed the function will wait for the remaining conversion time before returning the value.
Any number of these conversions (on different pins) can be started and be running simultaneously.
{kn=1 kl=1}'precision' is the resolution of the measurement and is optional.  It is a number between 0 and 3 meaning:
{kn=1 kl=1 l=432}0   =   0.5ºC resolution, 100 ms conversion time.
{l=432}1   =   0.25ºC resolution, 200 ms conversion time (this is the default).
{l=432}2   =   0.125ºC resolution, 400 ms conversion time.
{l=432}3   =   0.0625ºC resolution, 800 ms conversion time.
The optional timeout parameter (100 to 2000 ms) overrides the conversion times above to allow for slow devices.
'pin' can be any I/O pin, or pin 42 for a sensor fitted on the motherboard (see the chapter *Hardware Features*).

=== TEXT  x,  y,  string$  [,alignment$]  [, font]  [, scale]  [, c]  [, bc]
--- keep
{t=l2592}Displays a string on the screen starting at 'x' and 'y'. 
{t=l2592}‘string$’ is the string to be displayed.  Numeric data should be converted to a string and formatted using the Str$() function.
{t=l2592}' alignment$' is a string expression or string variable consisting of 0, 1 or 2 letters where the first letter is the horizontal alignment around 'x' and can be L, C or R for LEFT, CENTER, RIGHT and the second letter is the vertical alignment around 'y' and can be T, M or B for TOP, MIDDLE, BOTTOM.  The default alignment is left/top.
{t=l2592}For example. “CM” will centre the text vertically and horizontally.  
{t=l2592}The 'alignment$' string can be a constant (eg, “CM”) or it can be a string variable.  For backwards compatibility with earlier versions of MMBasic the string can also be unquoted (eg, CM).
A third letter can be used in the alignment string to indicate the rotation of the text.  This can be 'N' for normal orientation, 'V' for vertical text with each character under the previous running from top to bottom, 'I' the text will be inverted (i.e. upside down), 'U' the text will be rotated counter clockwise by 90º and 'D' the text will be rotated clockwise by 90º
{t=l2592}'font' and 'scale' are optional and default to that set by the FONT command.  
{t=l2592}'c' is the drawing colour and 'bc' is the background colour.  They are optional and default to the current foreground and background colours.  'bc' can be -1, and then the background of the characters is not drawn (see Transparent Text in the chapter *Graphics Functions*).
{t=l2592}See the chapter *Graphics Functions* for a definition of the colours and graphics coordinates.

=== TIME$ = "HH:MM:SS"
or
TIME$ = "HH:MM"
or
TIME$ = "HH"
or
TIME$ = sec
--- keep
Sets the time of the internal clock.  MM and SS are optional and will default to zero if not specified.  For example TIME$ = "14:30" will set the clock to 14:30 with zero seconds.
TIME$ = sec, where ‘sec’ is a number rather than a string, adds ‘sec’ seconds to the current time (or subtracts them when it is negative), which makes it easy to fine tune the clock; the date changes too if the adjustment crosses midnight.
The clock is the battery backed real time clock of the processor, or the DS3231 of a Generation 2 with OPTION DS3231 ON, so the time is kept while the power is off (see Backup Battery in the chapter *Hardware Features*).  The time is "00:00:00" when the clock is first powered.

=== TILE x, y [, foreground] [, background] [, w] [, h]
or
TILE RESET
or
TILE HEIGHT h
--- keep
The PicoMite's MODE 1 tiles, in the 1-bit colour depth (MODE r,1) only: elsewhere the error is "Invalid for this screen mode".  The screen is divided into tiles 8 pixels wide and TILE HEIGHT pixels tall, each with its own foreground colour, which its set pixels show, and background colour, which the others show.  A pixel drawn in any colour but black is set, so the colour it is seen in is its tile's foreground colour.
TILE x, y sets the colours of the tile ‘x’ across and ‘y’ down (counting from 0), or of ‘w’ tiles across and ‘h’ down from it.  A colour that is left out stays as it is.
Text drawn by PRINT or TEXT that lines up with the tiles (its left edge on a multiple of 8, its top on a multiple of the tile height, and its width and height whole tiles) also sets the tiles it covers to its foreground and background colours.  A transparent background (-1) leaves the tiles' background colours as they are.
TILE RESET gives every tile the default colours: white on black.
TILE HEIGHT h sets the height of the tiles to ‘h’ (8 to the height of the screen) and clears the screen.  MODE sets it to the height of the font.  MM.INFO(TILE HEIGHT) returns it.
The tiles' colours are held to 15 bits (RGB555), as on the PicoMite's HDMI version.  Up to 256 different colours can be on the screen at once: beyond that a new colour is shown as the nearest one in use.

=== TMC22xx pin, chip, address, current, holdpct, microsteps [, rsense] [, stealthchop]
or
TMC22xx SGTHRS address, value
or
TMC22xx TCOOLTHRS address, value
or
TMC22xx CLOSE
--- keep
Configures Trinamic TMC2208 and TMC2209 stepper motor driver chips through their single wire UART interface.  ‘pin’ is the I/O pin connected (through a 1k resistor) to the driver's PDN_UART pin, ‘chip’ is 2208 or 2209 and ‘address’ is the driver's address (0 for the TMC2208, 0 to 3 for the TMC2209).  ‘current’ is the motor's run current in mA (up to 2000), ‘holdpct’ is the hold current as a percentage of the run current and ‘microsteps’ is 1, 2, 4, 8, 16, 32, 64, 128 or 256.  ‘rsense’ is the value of the sense resistor in ohms (0.11 if it is not given) and ‘stealthchop’ selects the quiet StealthChop mode (1, the default) or SpreadCycle (0).
TMC22xx SGTHRS sets the TMC2209's StallGuard threshold (0 to 255) and TMC22xx TCOOLTHRS its CoolStep and StallGuard velocity threshold: both can be used at any time for tuning.  TMC22xx CLOSE releases the pin.
The settings are sent at 115200 baud.  It is normally used with the STEPPER command, and is described in more detail in the file *Stepper_Reference.pdf* included in the firmware download zip file.

=== VAR SAVE var [, var]… 
or
VAR RESTORE 
or
VAR CLEAR
---
VAR SAVE will save one or more variables to non-volatile memory where they can be restored later (normally after a power interruption).  
'var' can be any number of numeric or string variables and/or arrays.  Arrays are specified by using empty brackets.  For example: var()
The VAR SAVE command can be used repeatedly.  Variables that had been previously saved will be updated with their new value and any new variables (not previously saved) will be added to the saved list for later restoration.
VAR RESTORE will retrieve the previously saved variables and insert them (and their values) into the variable table.  
VAR CLEAR will erase all saved variables.   
This command is normally used to save calibration data, options, and other data which does not change often but needs to be retained across a power interruption.  Normally the VAR RESTORE command is placed at the start of the program so that previously saved variables are restored and immediately available to the program when it starts.  Notes:
{n=1 v=0 t=x1152,n360 b=0 l=360 h=181}The storage space available to this command is 4KB of RAM kept alive by the battery on the motherboard (see Saved Variables in the chapter *Using MMBasic*).  It can be written to an unlimited number of times.  The error is "Not enough memory" when it is full.
{n=1 v=0 t=x1152,n360 b=0 l=360 h=181}Using VAR RESTORE without a previous save will have no effect and will not generate an error.
{n=1 v=0 t=x1152,n360 b=0 l=360 h=181}If, when using RESTORE, a variable with the same name already exists its value will be overwritten.
{n=1 v=0 t=x1152,n360 b=0 l=360 h=181}Saved arrays must be declared (using DIM) before they can be restored.
{n=1 v=0 t=x1152,n360 b=0 l=360 h=181}Only global variables can be saved: not LOCAL or STATIC ones, constants or structures.
{n=1 v=0 t=x1152,n360 b=0 l=360 h=181}Be aware that string arrays can rapidly use up all the memory allocated to this command.  The LENGTH qualifier can be used when a string array is declared to reduce the size of the array (see the DIM command).  This is not needed for ordinary string variables.

=== WATCHDOG timeout
or
WATCHDOG OFF
---
Starts the watchdog timer, which restarts the Colour Maximite 2 when it times out.  This can be used to recover from some event that stopped the running program (such as an endless loop, or an error that returned to the command prompt), which can be important in an unattended control situation.
‘timeout’ is the time in milliseconds (1 or more) before a restart is forced.  This command should be placed in strategic locations in the running BASIC program to constantly reset the watchdog timer (to ‘timeout’) and therefore prevent it from counting down to zero.
If the timer count does reach zero (perhaps because the BASIC program has stopped running) the Colour Maximite 2 will be restarted, "Watchdog timeout" will be displayed and the automatic variable MM.WATCHDOG will be set to true (ie, 1) indicating that an error occurred.  This happens even when MMBasic is at the command prompt.  OPTION AUTORUN must be set for the program to run again.  On a normal startup MM.WATCHDOG will be set to false (ie, 0).
WATCHDOG OFF disables the watchdog timer (this is the default on a reset or power up).  The timer is also turned off when the break key (normally Ctrl-C) is used on the console to interrupt a running program.

=== WII
--- keep
WII is another name for CONTROLLER: for example WII NUNCHUK OPEN is the same as CONTROLLER NUNCHUK OPEN.  See CONTROLLER.
The PicoMite's spellings WII OPEN (for a Classic) and WII NUNCHUCK OPEN are not accepted: use WII CLASSIC OPEN and WII NUNCHUK OPEN, and the CLASSIC() and NUNCHUK() functions in place of the PicoMite's DEVICE(WII ...) and DEVICE(NUNCHUCK ...).

=== WS2812 type, pin, nbr, colours%()
or
WS2812 type, pin, 1, colour%
---
This command will drive one or more WS2812 LED chips connected to 'pin', which is made a digital output if it is not one already.
 'type' is a single character specifying the type of chip being driven:
{l=720}O = original WS2812
{l=720}B = WS2812B
{l=720}S = SK6812
{l=720}W = SK6812W (RGBW)
‘nbr’ is the number of LEDs in the chain (1 to 512).  The 'colours%()' array should be an integer array, specified with empty brackets, with at least as many elements as the number of LEDs to be driven.
For the first three variants each element in the array should contain the colour in the normal RGB888 format (i.e. 0 to &HFFFFFF).  For type W it holds the white level above the red: &HWWRRGGBB (0 to &HFFFFFFFF).
If only one LED is connected then a single integer value (‘colour%’) is used instead of the array, with the same range.
See the chapter Special Devices.  BITBANG WS2812, the older name, is still accepted.

=== XMODEM SEND file$ [, port]
or
XMODEM RECEIVE file$ [, port]
---
Transfers a file to or from a remote computer using the XModem protocol.  XMODEM SEND sends the file ‘file$’ on the SD card or USB flash drive to the remote computer and XMODEM RECEIVE accepts a file sent by the remote computer and saves it as ‘file$’, overwriting a file of that name.  Any file can be transferred, not only programs (a program received is run with RUN).  SEND and RECEIVE can be abbreviated to S and R.
The transfer is made over the serial console, which must be enabled (see OPTION CONSOLE), unless ‘port’ is given: 1, 2 or 3 for the serial port COM1, COM2 or COM3, which must have been opened (see OPEN) with a suitable baud rate.
The XModem protocol requires a cooperating software program running on the remote computer.  It has been tested on Tera Term running on Windows and it is recommended that this be used.  After running the XMODEM command in MMBasic select:\n       File -> Transfer -> XMODEM -> Receive/Send\nfrom the Tera Term menu to start the transfer.  Download Tera Term from <<http://ttssh2.sourceforge.jp/>>
If the remote computer does not respond within about 60 seconds the command returns to the MMBasic prompt with the error "Remote did not respond".  The break key is disabled while the transfer runs.  XModem sends the data in blocks of 128 bytes, so a file received is padded at its end to a multiple of 128 bytes (with the character &H1A).
The ZMODEM command does the same job faster, keeps a file's exact length and recovers from transmission errors.  The YModem protocol is not available.

=== ZMODEM SEND [file$]
or
ZMODEM RECEIVE [file$]
---
Transfers files to or from a remote computer over the serial console using the ZModem protocol.  It does the job of XMODEM but is much faster, and it recovers from transmission errors: every block of data is checked and if any is lost or damaged the receiver asks for it again from that point, so a poor connection slows a transfer down rather than stopping it.  SEND and RECEIVE can be abbreviated to S and R.  The serial console must be enabled (see OPTION CONSOLE).
ZMODEM SEND ‘file$’ sends the file ‘file$’ from the SD card or USB flash drive; the remote computer is given its name without the drive or directory.  ZMODEM SEND with no file name sends the file of the current program (see MM.INFO$(CURRENT)).
ZMODEM RECEIVE ‘file$’ saves the file sent by the remote computer as ‘file$’, overwriting any file of that name; the name sent by the remote computer is ignored.  If the remote computer sends several files only the first is received, unless ‘file$’ is "\*".
ZMODEM RECEIVE "\*", or ZMODEM RECEIVE with no file name, will accept any number of files and save each one in the current directory under the name given by the remote computer (without any directory), overwriting any file of that name.  A directory can be put in front of the \*, for example ZMODEM RECEIVE "C:/downloads/\*".  In Tera Term select all the files to be sent in the ZMODEM Send dialog; with lrzsz list them all, for example sz \*.bas.  When the transfer is complete the number of files and bytes received is reported.  If an error stops the transfer part way through, the files received before it are complete and the error message says how many there were.
ZMODEM SEND and RECEIVE with no file name can only be used at the command prompt; with a file name they can also be used in a program.  Programs are transferred as files: a program received is run with RUN.  The PicoMite's ZMODEM CRUNCH is not available.
The ZModem protocol requires a cooperating program on the remote computer.  On Windows Tera Term is recommended: after running the ZMODEM command select File -> Transfer -> ZMODEM -> Send or Receive from the Tera Term menu.  On Linux and macOS use sz (to send) and rz (to receive) from the lrzsz package, run with the serial port as their input and output, for example from a terminal program such as minicom.
If the remote computer does not start the transfer within 60 seconds the command returns to the MMBasic prompt with the error "Sender did not respond" (or "Receiver did not respond").  If the remote computer cancels the transfer the error is "Cancelled by remote" (or "Receiver cancelled").  The break key is disabled while the transfer runs.  The speed of the transfer is set by the console's baud rate (see OPTION BAUDRATE).
