# The I/O Pins

The services of version 7 give a program the pins of the rear I/O connector: digital inputs and outputs, the analog inputs, PWM, I2C, SPI and the COM ports. They name the pins by the PicoMite's GP numbers, as MMBasic does, so that code written for a PicoMite (MicroPython's machine module, for one) carries over with its wiring. The firmware's own drivers do the work, so the pins behave as they do for a BASIC program.

## The Pins

Each GP number is the pin of the connector that has that function:

{widths: 12,10,28,12,10,28}
| GP | Pin | Function | GP | Pin | Function |
|---|---|---|---|---|---|
| GP0 | 8 | COM1 TX | GP14 | 27 | I2C2 SDA |
| GP1 | 10 | COM1 RX | GP15 | 28 | I2C2 SCL |
| GP2 | 12 | PWM 1A | GP16 | 3 | I2C SDA |
| GP3 | 22 | PWM 1B | GP17 | 5 | I2C SCL |
| GP4 | 36 | PWM 2A | GP18 | 23 | SPI clock |
| GP5 | 31 | PWM 2B | GP19 | 19 | SPI MOSI |
| GP6 | 7 | General I/O | GP20 | 21 | SPI MISO |
| GP7 | 13 | General I/O | GP21 | 33 | General I/O |
| GP8 | 15 | General I/O | GP22 | 32 | General I/O |
| GP9 | 24 | General I/O | GP26 | 26 | Analog input |
| GP10 | 40 | SPI2 clock | GP27 | 29 | Analog input |
| GP11 | 38 | SPI2 MOSI | GP28 | 37 | Analog input |
| GP12 | 35 | SPI2 MISO | GP36 | 16 | COM2 TX |
| GP13 | 18 | General I/O | GP37 | 11 | COM2 RX |

Any of them can be a digital input or output when its other function is not in use. Pin 40 (GP10) is also the reset link: connected to ground (pin 39) at power up it resets every option and erases the program in program memory, so anything wired to it must not look like a short to ground at power up (see the user manual).

## Errors

Each I/O service returns 0 (or a value) or an error:

{widths: 12,88}
| Error | Meaning |
|---|---|
| -1 | No such GP number, bus or port. |
| -2 | The pin is in use by a COM port, SPI, I2C or another function. |
| -3 | Not possible: that mode on that pin, or a bus or port that is not open. |
| -4 | The firmware's driver reported an error: io_error() returns its message. |

```
const char *io_error(void);
```

## Digital and Analog Pins

```
int  pin_setup(int gp, int mode, int pull);
int  pin_read(int gp);
void pin_write(int gp, int v);
int  adc_read(int gp, uint32_t *uv);
```

pin_setup sets a pin's mode: CMM2_PIN_OFF (not configured), CMM2_PIN_IN, CMM2_PIN_OUT, CMM2_PIN_OD (an open drain output) or CMM2_PIN_ANALOG. For an input, pull is CMM2_PULL_NONE, CMM2_PULL_UP or CMM2_PULL_DOWN. pin_read returns its level, 0 or 1 (an output's too), and pin_write sets an output's level.

adc_read reads an analog input: it returns 0 to 65535 for 0V to the supply voltage, and puts the voltage in microvolts in uv (if uv is not NULL), from 3.3V or OPTION VCC's setting.

```
cmm2->pin_setup(21, CMM2_PIN_OUT, CMM2_PULL_NONE);      /* GP21: pin 33 */
cmm2->pin_setup(26, CMM2_PIN_ANALOG, CMM2_PULL_NONE);   /* GP26: pin 26 */
for(;;) {
    uint32_t uv;
    cmm2->adc_read(26, &uv);
    cmm2->pin_write(21, uv > 1650000);                 /* high above half of 3.3V */
    if(cmm2->poll()) break;
}
```

## PWM

```
int pwm_set(int gp, uint32_t freq, uint32_t duty);
int pwm_stop(int gp);
```

pwm_set starts or changes a PWM output, on GP2 to GP5: freq is its frequency in Hz (1 to 20,000,000) and duty its duty cycle, 0 to 65535 for 0% to 100%. GP2 and GP3 are the two outputs of PWM channel 1 and share its frequency, as GP4 and GP5 share channel 2's: setting one's frequency changes the other's, and the other keeps its duty cycle. pwm_stop stops an output.

## I2C

```
int i2c_open(int bus, int khz, int timeout_ms);
int i2c_close(int bus);
int i2c_xfer(int bus, int addr, const uint8_t *w, uint32_t wn,
             uint8_t *r, uint32_t rn, int stop);
```

Bus 0 is I2C (GP16 and GP17) and bus 1 is I2C2 (GP14 and GP15). i2c_open opens one at 100, 400 or 1000 kHz, with a timeout of 0 (none) or 100ms or more. i2c_xfer writes wn bytes from w to the device at the 7-bit address addr, then reads rn bytes into r, with a repeated start between them, and releases the bus at the end if stop is not zero (0 keeps it, for a repeated start in the next transfer). With wn and rn both 0 it sends the address alone, to see whether a device answers. It returns 0, 1 if the device did not acknowledge, 2 if it timed out (as MM.I2C does in BASIC), or an error.

```
uint8_t reg = 0, secs;
cmm2->i2c_open(0, 100, 100);
/* a DS3231's seconds register */
if(cmm2->i2c_xfer(0, 0x68, &reg, 1, &secs, 1, 1) == 0)
    printf("seconds: %02x\n", secs);
cmm2->i2c_close(0);
```

## SPI

```
int spi_open(int bus, uint32_t hz, int mode);
int spi_close(int bus);
int spi_xfer(int bus, const uint8_t *tx, uint8_t *rx, uint32_t n);
```

Bus 0 is SPI (GP18 to GP20) and bus 1 is SPI2 (GP10 to GP12). spi_open opens one at hz with the SPI mode 0 to 3, eight bits a transfer. spi_xfer sends n bytes from tx while receiving n into rx; tx NULL sends zeros and rx NULL throws away what comes in. A chip select is an ordinary output, set with pin_write around the transfer.

## The COM Ports

```
int com_open(int com, uint32_t baud, int bits, int parity, int stop, uint32_t rxbuf);
int com_close(int com);
int com_write(int com, const uint8_t *buf, uint32_t n);
int com_read(int com, uint8_t *buf, uint32_t n);
int com_avail(int com);
int com_connected(int com);
```

com is 1 (COM1: GP0 and GP1), 2 (COM2: GP36 and GP37) or, from version 14 of the services, 4 to 7 (COM4 to COM7: USB serial devices, such as a PicoMite plugged into a USB port). A USB device moves its data when poll is called, and com_write returns fewer bytes than it was given if the device is unplugged, or stops reading and Ctrl-C is pressed. com_open opens it as MMBasic's OPEN "COMn:" does: bits 7 or 8, parity 0 (none), 1 (even) or 2 (odd), stop 1 or 2, and a receive buffer of rxbuf bytes (0 for MMBasic's default). com_write queues bytes to send (it waits while the queue is full) and returns how many. com_read takes up to n of the bytes received and returns how many it took, 0 if there are none: it does not wait. com_avail returns the number of bytes waiting.

com_connected, from version 15 of the services, says whether a port's device is there, open or not: 1 if it is, 0 if a USB serial device is unplugged or restarting, as a PicoMite does after many OPTION commands, and -1 if com is not one of those above. COM1 and COM2 are always 1. An open port stays open while its device is away, and when it comes back the firmware sets the line up again as it was, so a program has nothing to do but tell its user.

## At the End

Whatever a program set up is undone when it ends: its pins are returned to not configured, its PWM outputs stopped, and its I2C and SPI buses and COM ports closed.
